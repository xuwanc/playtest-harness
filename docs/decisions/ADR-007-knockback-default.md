# ADR-007 · 默认配置反映真实手感，测试限制要显式打开

- 状态：已采纳（v9s.38）
- 影响范围：`config/game.json` → `core.hits.noDamageToPlayer`、调试面板、4 个旧用例

## 背景

`core.hits.noDamageToPlayer` 原本默认 `true`（玩家不会被击退）。它最初是为了「假人只做表现、不改玩家状态」这条契约加的开关，但后来变成了默认行为：任何新做的击退 / 受击手感，玩家自己永远感受不到，只有把开关翻过来才能验。

## 决策

- 默认值改为 `false`：**玩家受击会被击退**，与假人同一套公式（`knockback × decay`）。
- 开关保留，命名改成正向：调试面板里的「玩家受击击退」（`playerKnock` 代理），关掉才是旧行为。
- 旧用例如果守的是「无伤害 / 不击退」契约，在该用例内**显式写回** `noDamageToPlayer = true` 并注明原因，不靠默认值。

## 后果

- 默认体验 = 真实手感：玩家被三个陪练围住时会被推着走，混战强度可感。
- 4 个旧用例需要显式设置：`dummies.test`（无伤害契约）、`links.test`（对称机制）、`v9s25-skills-data.test`（弓箭原地连射会被推离）、`determinism`（快照）。后者的快照用 `-u` 更新后**再跑一次**确认不再漂移。
- `smoke` 新增一条：「玩家受击击退默认打开」——断言配置值为 `false`，防止有人手滑改回去。
- 命名教训：**否定式开关**（`noXxx`）在面板上会读成双重否定，新开关一律用正向命名 + 代理 getter/setter。
