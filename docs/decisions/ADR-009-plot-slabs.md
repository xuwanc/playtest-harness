# ADR-009 · 测试场地块化：模数 5m + 整数跨格拼底板

> 状态：**设计稿（未实现）** · 2026-11-09 · 决策人：用户（选定方案 A）· 执行：待排期
> 关联：[`../systems/plot-assembly.md`](../systems/plot-assembly.md)（现行拼合实现）、
> [`../systems/test-scene-policy.md`](../systems/test-scene-policy.md)（单一主场景）

## 1. 问题：一块 32×32 的底板，已经装不下第 10 块地

现状是**一整块地面** + 地面上的圆形/方形标识盘：

| 项 | 值 | 出处 |
|---|---|---|
| 底板 | 32 × 32，一格 box，`kind:'ground'` | `config/game.json` `scene.ground.size` |
| 可行走边界 | ±15.5 | `core.worldBounds` |
| 现有地块 | 9 块（7 块 pinned 老工位 + 2 块 auto） | `config/plots/*.json` |
| 占地 | 中心盘 r3.6、四角盘 r5.2、南侧盘 z=−10 | 同上 |

**已经出界了**：`sparring-demo` 是 auto 地块，落点 (0, 14)、半径 2 → 北边缘到 z=16，
超出可行走边界 0.5 m、正好压在地面边缘。再想加「可破坏物 / 新武器 / 新 AI」的独立场地，
只能挤在缝里，或者继续往北堆到地里去。

根因不是「32 太小」，而是**底板是单体、地块位置是手写绝对坐标**：
加一块地 = 改一块共享地板 + 手工找一个空位。这正是 `plot-assembly` 想消灭的冲突，只是当时只做了「标识盘」，没做「承重的地」。

## 2. 决策

**底板按地块拆开，每块地自带一块 5 m 模数的方形地板；进场景时按 id 排序整数格拼合。**

规格不是「全部一样大」，也不是「随便 10×10 / 20×10」，而是：
**统一模数 5 m × 整数跨格 `span: [cols, rows]`**。

| span | 实际尺寸 | 典型用途 |
|---|---|---|
| `[1,1]` | 5 × 5 | 小道具 / 单个装饰物 / 单个假人 |
| `[2,1]` | 10 × 5 | 一字排开的量具（刻度、标尺） |
| `[2,2]` | 10 × 10 | **默认**：圆盘工位、陪练场、可破坏物 |
| `[4,2]` | 20 × 10 | 冲刺跑道（现有 dash 需要 ≥10 m 直线） |

> 你说的 10×10 就是 `[2,2]`，20×10 就是 `[4,2]` —— 两者本来就是同一套模数的两个倍数。
> 所以「统一规格」和「按需尺寸」不冲突：**统一的是模数和缝，不统一的是跨几格**。

### 为什么不选另外两个

| 方案 | 为什么不选 |
|---|---|
| 全部同尺寸（如 12×12） | 圆盘工位 r3.2 只需要 6.4 m，12×12 里一半是空板；冲刺跑道 12 m 又刚好卡住 spawn + 5 m 标记。浪费与不够同时发生。 |
| 每块自由写 10×10 / 20×10 / 13×7 | 回到浮点矩形重叠检测：缝对不齐、加地可能挪旧地、拼合结果依赖加载顺序。等于把已经解决的冲突重新引进来。 |

## 3. 拼合规则（确定性，可单测）

```
cells = Map<"c,r", plotId>            // 整数占用表，容量上限 = columns × rows
先放 pinned：hub 占 (0,0)-(1,1)       // 只允许 hub 一个 pinned，其余全部 auto
按 id 字典序（与提交先后无关）：
  for 每个未放置的 def:
    从光标 (c=0,r=0) 起逐格扫描（行优先，列数 columns）：
      若 span 覆盖的 cells 全空且在边界内 → 占位，记录 origin 格
      否则游标 +1
    扫到末尾仍未放下 → diagnostics.unplaced，继续（不抛错）
最后整体平移：包围盒中心 → 世界 (0,0)
```

- **不重叠是构造性的**，不需要浮点圆/矩形相交判断 —— 现在 `overlaps()` + `gap` 那套整段删掉。
- **加地不挪旧地**：新地块 id 若排在后面，只会在末尾找空格；`pinned` 只有 hub，位置永远不变。
  （若 id 排序在前，后面的地块会顺延 —— 所以 `id` 一旦发布就不要再改名。）
- **边界**：`columns` 给 6，行数按需增长；`worldBounds` / `gridMeta` 从拼合结果的包围盒 + 1.5 m 余量推导，
  不再手写 ±15.5。

## 4. 数据结构（契约变更）

```ts
// types.ts
export type PlotDef = {
  span?: [number, number];   // 新增：占几格，默认 [2,2]
  anchor?: { x: number; z: number };  // 仅 hub 使用（钉在原点），其余忽略
  // radius 保留：只是「标识盘画多大」，与占地无关
};

export type SlabSpec = {     // 新增：拼合产物里的一块承重地板
  plotId: string;
  minX: number; maxX: number; minZ: number; maxZ: number;
  top: number;               // 顶面 y，统一 0
  thickness: number;
};

export type PlotAssembly = {
  // ...原有字段
  slabs: SlabSpec[];         // 每块地一块
  bounds: Bounds;            // 拼合后世界范围
};
```

`buildBoxes(scene)` 增加一条分支：有 `slabs` 就逐块生成 `kind:'ground'` 的 box（厚度 0.4），
没有则回落旧的单块 `ground.size`（兼容老配置 / 单测夹具）。

## 5. 视觉与行走

- **齐边、不留缝**：相邻地块顶面同高（y=0），拼合后是连续地面，角色不会掉下去，
  也不需要给缝做「隐形桥」。地面网格（GridHelper）继续按包围盒铺。
- **缝靠描边表示**：每块地板沿边画 6 cm 暗色描边 + 该地块主色细线（`lab-scene` 里已有 flat 材质与
  polygonOffset，直接复用），俯视角下能看出「这是几块板」但不干扰脚下的指示环。
- **标识盘不变**：`radius` / `shape` 继续只决定盘的大小与样子，盘画在地板中央。
- 地块名继续贴在地块南沿（`labelDz` 从板边算，不再从圆心算）。

## 7. 影响面

| 面 | 影响 | 处置 |
|---|---|---|
| `core/world.ts` 构造 | 需要拼合结果参与 `buildBoxes` | 组装层先 `assemblePlots` 再 `createWorld`，Core 仍纯函数 |
| determinism golden | 碰撞盒 1 → 9，hash 必变 | `-u` 重生成，journal 记「契约变更」 |
| `worldBounds` | 从 ±15.5 改为推导值 | 相机 / 移动 / 分离共用，需回归「走不出边界」 |
| 草地 | `grass` 格坐标是相对地块中心的，模数 5 / 格 0.5 = 10 整数 | 无需改；但 `absolute:true` 的老草块要重新标 |
| 测试 | `plot-assembly.test.ts` 的半径/重叠断言失效 | 改为「整数占用无重叠 + 加地不挪旧地 + 面积守恒」 |
| smoke | 需新增「第 N 块地在地面范围内」 | 读 `plotDebug().slabs` 校验 |
| 文档 | `plot-assembly.md` 大改 | 同时更新 `test-scene-policy.md` 规则 2 |

## 8. 验收标准

1. 新增第 10 块地 = 只加一个 `config/plots/<id>.json`，**不改任何共享文件**，不出界、不重叠；
2. 同一组 JSON 跑两次，`assemblePlots` 输出逐字节一致（`JSON.stringify` 比对）；
3. 玩家从 hub 走到任意地块不掉落、不卡缝（smoke 走一遍南北向）；
4. `npm run verify` 全绿；`smoke` 增加 slabs 断言后仍全过；
5. `plotDebug()` 能报出每块板的 `plotId / 格子 / 世界矩形`。

## 9. 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| 地块 id 顺序影响落位 | 按 id 排序是确定性的前提 | 约定 id 发布不改名；改名视为重排，需 journal 说明 |
| 30×40 比原来大 | 相机跟随、阴影范围、网格段数都要跟着扩大 | 都走 `worldBounds` 推导，避免再写死常量 |
| 板与板之间是「构造性无缝」 | 若以后想做物理缝隙 / 高低差，模型要再变 | 当前只做同高齐边；高度差留给后续 ADR |
| 老工位坐标变了 | 7 个 pinned 的实际位置从手写变成拼合结果 | 首版允许一次性重排，截图对比确认观感无回退 |
