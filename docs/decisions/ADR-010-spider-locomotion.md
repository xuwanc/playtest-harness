# ADR-010 · 蜘蛛角色：能复用的是解算器，不是动画；不引入 FullBodyIK

> 状态：**待批准（设计稿 + 可跑原型）** · 2026-11-09
> 关联：[`../systems/animation.md`](../systems/animation.md)（连击规范）、
> [`../systems/dummies-fighters.md`](../systems/dummies-fighters.md)（现有两套骨架）、
> 原型：`prototype/spider/`（独立目录，不进 `src`、不参与构建）、
> 复现截图：`python3 tools/spider-proto-shot.py`（产物落 `shots/spider-proto/`，按仓库规矩不入库）

## 1. 问题

要加一只蜘蛛。需要先回答三件事：

1. 现有动画能不能**复用**；
2. 要不要引入 **FullBodyIK**（UE5 那套全身 IK 解算器）；
3. 有没有第三条路。

先把一句话结论放在前面，后面逐条论证：

> **动画没有「数据」可复用，只有「算法」；算法里能复用的部分很多，腿的步态不能。**
> **不要 FBIK —— 它解决的是「烘焙动画的后期修正」，本项目没有烘焙动画，且它会破坏确定性快照。**
> **要的是「多足步态发生器 + 每腿两骨闭式解」，原型已跑通（8 腿 / 0 迭代 / 每帧 8 次 acos）。**

## 2. 现状测绘：这里的「动画」是每帧算出来的，不是片段

| 层 | 文件 | 行数 | 蜘蛛能否复用 |
|---|---|---|---|
| Core 驱动（无骨架） | `movement` / `turn-in-place` / `orientation` / `combat` / `hits` | ~1800 | ✅ 整套，只要体型参数化 |
| 步态解算（纯函数） | `presentation/gait.ts` | 758 | ❌ 双足相位对偶对 8 腿无意义；**思路**可复用 |
| 其它姿势解算（纯函数） | `hurt-pose` / `inertia` / `balance` / `program-anim` / `swing-pose` | ~1200 | ⚠️ 躯干与受击可用，挥击/持械层弃用 |
| IK（纯函数） | `presentation/ik.ts` | 152 | ✅ **同一族数学，换一个轴就能用** |
| 装配（THREE） | `voxel-rig.ts` 2882 / `dummy-rig.ts` 690 | 3572 | ❌ 拓扑完全不同；`dummy-rig` 是**模式**参考 |

三个必须知道的事实：

1. **仓库里没有任何 `.glb` / `.fbx` / `AnimationClip` / `AnimationMixer` / 蒙皮**。
   姿势 = `f(state) → 关节角度`，每帧重算，可快照、可单测、帧率无关。
2. **「两套平行骨架」是本项目已经验证过的扩展方式**：`dummy-rig` 与 `voxel-rig` 是
   平行实现，共用同一批解算器，不是复制粘贴。蜘蛛走的是同一条路（第三套）。
3. **`fighter-rig` 是反例也是证据**：它没有另写骨架，直接复用 `voxel-rig`，
   因为陪练「要同款挥击」。判据是**需求同构性**，不是「能不能省代码」。

所以「复用动画」这个问题本身要拆成两问：**复用片段？**（没有片段）**复用解算器？**（可以）。

## 3. 决策一：动画数据不可复用，解算器与装配模式可复用

| 资产 | 蜘蛛 | 说明 |
|---|---|---|
| Core（移动 / 碰撞 / 朝向 / 受击 / 仇恨 / 分离） | ✅ 直接复用 | 与骨架无关。需要补一份体型参数（半径 / 体高 / 锁定点高度） |
| `ik.ts` 两骨闭式解 | ✅ 直接复用 | 每条腿就是「根 → 膝 → 脚」两根骨；8 条腿调 8 次 |
| `gait.ts` 的步态**思路** | ✅ 概念复用 | 「支撑相抵消位移 + 摆动相回摆 + 重心转移」——但曲线要重写，不能改参数 |
| `gait.ts` 的相位/曲线本体 | ❌ | 双腿 `phase` 与 `phase+π` 的对偶，8 腿不存在这种关系 |
| `hurt-pose` / `inertia` | ⚠️ 部分 | 躯干后仰 / 侧倾 / 重心偏移可用；四肢分层要重接 |
| `swing-pose` / 武器挂点 / 连击骨架 | ❌ | 蜘蛛无持械手；若做「扑咬」，走 `program-anim` 的通用曲线，不复用连击结构 |
| `voxel-rig` / `dummy-rig` | ❌ 不复用 | 新增 `spider-rig.ts`，`dummy-rig` 只作写法参考 |
| `pose-clip` / `pose-interp` | ✅ 可选 | 若蜘蛛要「前扑 / 收腿 / 死亡」这类一次性动作，这套剪辑机制可直接用 |

**工作量估算（方案 A）**：`spider-gait.ts` ≈ 320 行、`spider-rig.ts` ≈ 420 行、
Core 接入 ≈ 120 行、测试 ≈ 25 例。合计 ≈ 900 行，是现有角色代码（≈3600 行）的 25%。
**不动 `voxel-rig.ts` 一行** —— 这是判断「该不该复用」的实际价值所在。

## 4. 决策二：不引入 FullBodyIK

### 4.1 FBIK 解决的是什么问题

FullBodyIK 是**骨骼动画的运行时修正器**：给一组末端效应器（脚、手、头）和关节约束，
用迭代法（FABRIK / 雅可比）反解整条骨架，用来解决「烘焙动画的脚踩不进斜坡」
「手够不到门把手」「身体前倾时腿自动补位」这类问题。

它的前提是：**你已经有一段动画，这段动画的末端位置是错的，需要事后掰回来。**

本项目没有这个前提 —— 姿势是解出来的，脚的位置就是解的一部分。

### 4.2 四条硬冲突

| 冲突 | 说明 |
|---|---|
| **确定性** | 项目底线是「同输入 → 逐字节同输出」：`tests/determinism.test.ts` + `__snapshots__` + `portable.test.ts`。FBIK 是迭代收敛，迭代次数依赖初值与阈值，浮点误差会渗进快照。这条一破，一半回归测试失效 |
| **预算** | 8 腿 × 3 关节 × 每帧 N 次迭代，相对现在「8 次 `acos`」差两三个数量级。项目有 `pinch` / 隐形摇杆，明确要上手机 |
| **可测性** | 现在的每个解算器都能写「给定输入 → 断言角度」。迭代解算器只能断言「误差小于 ε」，回归时无法定位是哪一帧开始漂 |
| **可调性** | 现有调参工作流是 `clip-lab` 扫角度出曲线 + 截图比对。FBIK 出问题时你调的是迭代次数和链权重，不可解释、不可回归 |

### 4.3 需求里真正需要 FBIK 的那 20%，用闭式解就够

| 需求 | FBIK 做法 | 本方案做法 | 是否够 |
|---|---|---|---|
| 脚贴地 / 不滑步 | 脚部效应器 + 迭代 | 支撑相**锁死世界坐标**，摆动相才更新落点 | ✅ 绝对不滑（几何上不可能滑） |
| 身体随地形起伏 | 骨盆效应器 | 落脚点高度取均值 + 平面拟合 | ✅ |
| 转身时腿重新落位 | 全身解算 | 相位加「等效线速度」项（见 §6.5） | ✅ 原型实测有效 |
| 关节不穿插 | 关节约束 | 可达范围 `clamp` + 关节角限位 | ✅ 够用（体素风格容错高） |
| 手够武器 / 扶墙 | 手部效应器 | 暂不需要 | — |

> 结论：**FBIK 的收益在本项目接近于零，成本是确定性与性能。**
> 如果未来真要做「蜘蛛爬不规则地形 + 上身独立瞄准」，那时再评估也不迟，
> 且届时更可能引入的是「每腿一条射线 + 落点平滑」，仍然不是 FBIK。

## 5. 决策三：三个梯度方案，先做 A

| 方案 | 做法 | 成本 | 什么时候选 |
|---|---|---|---|
| **A（推荐）** | 固定相位表 + 每腿两骨闭式解 + 支撑相锁脚；平地、固定体高 | ≈900 行 / 1.5 天 | **现在**。测试场是平地，够用 |
| **B** | A + 每脚向下 1 条射线取地面高度 + 落点平滑 + 身体平面拟合 | A + 200 行 / +1 天 | 有台阶 / 斜坡地形时。`core/step.ts` 已有台阶概念可接 |
| **C** | 抽 `LegChain` 描述（根位置 / 节长 / DOF 掩码）+ 通用相位组发生器 | A + 2 天 | 出现第二只多足（四足 / 蜈蚣）时再重构。现在做是 YAGNI |

**明确不选的两条路**：

- ❌ **把双足 `gait` 改参数**：8 腿不存在「左右反相」的简单推广，硬改会把 758 行纯函数变成
  一堆 `if (legCount === 8)`，两个角色都变难维护。
- ❌ **引入带骨骼动画的 glTF 蜘蛛**：与「体素白盒 + 程序动画」的表现语言冲突，且要引入
  蒙皮 / AnimationMixer / 骨骼重定向，直接违背 ADR-002 的 Core 边界。

## 6. 方案 A 的技术细节（原型已按此实现）

### 6.1 骨架

```
group（世界位置 + 朝向）
└ body（体高 / 起伏）            头胸 + 腹 + 8 只眼（装饰）
  └ hip[i]（rotation.y = 腿方位角）
    └ femur（rotation.x，长 0.38）
      └ tibia（rotation.x，长 0.38）
        └ tip（脚端小块，接触点）
```

8 条腿 = 4 对髋点（`z = 0.26 / 0.09 / −0.09 / −0.26`）+ 扇形落点（`±56° / ±18°`）。

### 6.2 每腿两骨闭式解

与 `ik.ts` 同族：**先定腿平面，再平面内余弦定理**。差别只在「摆到平面」这一步
—— 竖直悬挂的腿用 `rotation.z`（roll），水平外伸的腿用 `rotation.y`（yaw）。

```
ψ = atan2(f, d)                        目标方向（相对竖直向下，正 = 向外）
α = acos((L1² + D² − L2²) / 2·L1·D)    膝盖偏角
t1 = ψ + α                             股节绝对角（膝盖在上侧的解）
t2 = atan2(f − L1·sin t1, d − L1·cos t1)
```

取「膝盖在上侧」的解，股节先向外略拱、胫节再落下 —— 这是蜘蛛的侧面轮廓。
另一支解会得到「膝盖朝地」的昆虫直腿，观感完全不同，不要写错符号。

零迭代、零随机、纯 `acos`/`atan2`，可直接写单测，也可原样翻成 C# 静态类。

### 6.3 三角步态相位表

| 腿 | L0 | L1 | L2 | L3 | R0 | R1 | R2 | R3 |
|---|---|---|---|---|---|---|---|---|
| 组 | A | B | A | B | B | A | B | A |
| 相位偏移 | 0 | 0.5 | 0 | 0.5 | 0.5 | 0 | 0.5 | 0 |

任何时刻恰好 4 脚着地、4 脚摆动 —— 这是「三角步态」的定义，也是它比「8 腿同相」稳的原因。
`phase = (φ + offset) % 1`，`φ` 由 Core 按 `速度 / 步幅` 累加（与双足的 `gaitPhase` 同构）。

### 6.4 不滑步的唯一来源：支撑相锁世界坐标

- **支撑相**（`ph < duty`，默认 0.6）：脚的**世界坐标一帧都不改**。身体在动，腿被拉伸。
- **摆动相**：`from = 当前脚位`、`to = 静止落点 + 前进方向 × stride × (1 − duty/2)`，插值 + 抬起。
- 前伸量按 `duty` 补偿，落地时脚正好在身体中线前后对称，支撑与摆动两侧净位移为 0。

这条不能改成「脚相对身体固定」—— 那就成了滑步。

### 6.5 转向：必须给相位加「等效线速度」

原型实测：**原地转身（`turn = 1.2 rad/s`）时，脚锁在世界、身体在转，
腿被拧到 `reach = 1.43`（超过 1.0 即够不到），2 条腿触发 clamp。**

修法一行：

```ts
spin      = |ω| × legRootRadius        // 腿根到身体中心的半径
effSpeed  = |v| + spin
phase    += (effSpeed / stride) × dt
```

改完 `reach` 降到 0.85、clamp 归零。**双足也有这个问题**（`turn-in-place.ts` 里那套
「一步 = 半圈」就是在处理它），只是双足只有两条腿，容错高、不容易被看见。

### 6.6 站定收脚

速度归零后，脚要慢慢收回静止落点，否则会「张着腿定格」。
对应双足里 `solveStopGait` 的收步相，但蜘蛛不需要「并脚」，只要 8 个落点回位即可。

## 7. 与 Core 的接口变化（真正的成本在这里）

| 项 | 现状假设 | 蜘蛛需要的 | 影响面 |
|---|---|---|---|
| 体型 | capsule 半径 ~0.35、高 1.2 | 体高 0.4、跨距 1.2、躯干半径 0.22 | `collision` / `hits` / `targeting` 的锁定点高度 |
| 命中体积 | 圆柱近似 | 低矮扁盒（跨距大但躯干小） | 挥刀命中判定要按「躯干盒」而不是「跨距」 |
| 相机目标 | 胸口高度 | 躯干中心高度 | `camera-rig` 的 `targetY` |
| 站立 / 移动 | 无「多足」概念 | 相位组 | `CharacterState` 需要 `legPhaseGroup` 或在表现层内部管理 |
| 爬墙 / 天花板 | 无 | **第一版明确不做** | 要改 Core 的「上方向」概念，是另一个量级的改动，单独 ADR |

> 建议第一版把蜘蛛限制为**地面爬行**，且**作为假人类型接入**
> （`DummyMode` 那套 AI / 仇恨 / 攻击已经齐了，蜘蛛只换骨架与步态），
> 这样 Core 侧改动最小，也符合「先证明观感，再决定玩法」的节奏。

## 8. 原型证据

| 用例 | 参数 | maxReach | clamped | 结论 |
|---|---|---|---|---|
| 静止 | `speed 0` | 74% | 0/8 | 八腿对称、膝盖拱起、脚全贴地 |
| 常速 | `1.4 m/s` | 79% | 0/8 | 4 脚支撑 / 4 脚摆动，无滑步 |
| 高速 | `3.0 m/s` / `stride 0.78` | 87%→103% | 0~1/8 | **接近极限**，需要加长腿或压步幅 |

## 9. 如果批准，验收标准

1. `spider-gait.ts` 纯函数、零 THREE、零随机；单测覆盖：相位表不重叠、支撑相脚位不变、
   站定收敛到静止落点、转向时 `reach` 不超 1.0。
2. `ik` 复用 `ik.ts` 或与其共享测试向量（同一组输入两边算出的角一致到 1e-9）。
3. `determinism` 快照通过（新增角色不能引入本地时间）。
4. `smoke` 增加：8 腿全部着地（0.02 m 容差）、任意时刻支撑腿 ≥ 4、走 3 m 后脚位漂移 < 1 cm。
5. 截图对比：静止 / 直行 / 转向 / 低速四张，与原型逐张对照。

## 10. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 8 腿 × 3 段 = 24 个 `Mesh`，比人类角色多 60% 绘制调用 | 手机上掉帧 | 腿用合并几何 / `InstancedMesh`；或先只做 1 只 |
| 三角步态在低速时「一顿一顿」 | 观感差 | 低速切换到「四足交替」或用 duty 随速度插值 |
| 蜘蛛体型与现有命中判定不匹配 | 打不到 / 判定过宽 | 先按躯干盒判定，跨距只做视觉 |
| 转向时腿仍可能瞬间拉伸 | 观感 | 等效线速度 + 落点切向预判（方案 B 再细化） |
| 与原「双足」共用的 `turn-in-place` 假设冲突 | 行为异常 | 蜘蛛走独立分支，不硬塞进现有解算器 |
