# ADR-001 · 文档分层：README 只当地图

- 状态：已采纳（2026-11-08）
- 影响范围：`README.md`、`docs/**`

## 背景

上一版 README 长到 4220 行：项目简介、系统说明、68 个版本的变更日志、验收清单、已知限制全在一起。后果是：

- 想知道「现在怎么工作」的人，要先翻过几屏「那天改了什么」；
- AI 接手时会把历史结论当成现状（例如「假人不会被击退」在 v9s.38 已经不成立）；
- 同一个事实在 README 和 `docs/` 各写一遍，改一处忘一处。

## 决策

按**内容类型**分流，一个事实只住一个地方：

| 内容类型 | 位置 | 写法 |
|---|---|---|
| 入口地图 | `README.md` | ≤100 行：是什么、怎么跑、去哪找。**禁止**追加变更记录 |
| 今天做了什么 / 修了什么 | `docs/journal/YYYY-MM-DD-NN.md` | 追加，只记「为什么这么改」，不改写历史 |
| 某系统如何工作 / 接口 / 数据流 | `docs/systems/<系统>.md` | 就地编辑，永远描述**当前**行为 |
| 当前进度 / 进行中 / 下一步 | `docs/state/CURRENT.md` | **覆盖写**，不累积历史 |
| 重要技术决策 | `docs/decisions/ADR-NNN-*.md` | 一决策一文件，写背景 / 后果 |
| 路径与命名规范 | `docs/assets/conventions.md` | 就地编辑 |
| 全部文档的索引 | `docs/INDEX.md` | 新增 / 改名 / 删除文档时同步 |

## 后果

- **好处**：查现状不会被历史干扰；AI 检索路径固定（INDEX → systems）；历史仍可追溯（journal 按日期）。
- **代价**：一次改动可能要动两个文件（systems 改现状 + journal 记原因）。这是刻意的 —— 两件事本来就有两拨读者。
- **约束**：单文件超过 300 行就拆，并在 INDEX 登记。`docs/systems/animation-notes-1/2/3.md` 就是这么来的。
- **反面案例**：`docs/animation-guidelines.md`（803 行）已按此规则拆成 1 份规范 + 3 份补充记录。

## 自检

`npm run verify` 前先跑 `npm run docs:check`：README ≤100 行、INDEX 里的链接全部存在、`docs/**` 无 >300 行的文件、`docs/` 下不允许出现裸的旧路径引用。
