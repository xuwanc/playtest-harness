# 框架风险与优化方向（滚动评审）

> 约定：每批改动完成并发布后更新本文件，同时在交付说明里给出本轮结论。
> 只记录**结构性问题**与**可执行建议**，不写「以后再说」的愿望清单。

## 当前活跃风险（v9s.39 更新）

v9s.38 的五条（特效看不见 / 面板重排 / 文档 / 击退默认开 / 三个持械陪练）已闭环；
v9s.39 只加了一件：**陪练的一轮连击**（`attackInterval` 管「多久来一轮」、
`comboCount` 管「一轮几刀」，冷却按轮记，所以起手频率不变）。

### 特效看不见：两个根因，都不在「数值」上

1. 白盒地块 `transparent: true`（即便 `opacity: 1`）→ 进透明列表 → 按「`renderOrder` →
   距离由远到近」排；32m 地面盒的排序距离取**包围球中心**，角色站到场边时地面被排到
   刀光之后、`opacity: 1` 整片盖掉。所以只在**某些地块**复现，场中央永远测不出来。
2. 贴地特效 `y` 写死 → 站上台阶就埋进方块里。

修法分别是「地块走不透明（仅线框调试时切回）」与 `groundHeightAt()` 查真实地形。
顺手把散落的 `renderOrder` 魔数收进 `FX_ORDER` 单调序列。

### 持械陪练：机制复用，不是第二套实体

`DummyState.weapon + combat` 做胶水，`fighter-rig` 直接复用主角 `voxel-rig`，
所以「同模型 / 同武器 / 同挥击」是**结构上保证**的，不是对着调出来的。
攻击欲望靠站位带 + 冷却期只走位 + 首击错开，而不是单纯调大间隔。

### 文档

新增 `docs/INDEX.md`（按症状 / 模块检索）+ 系统文档分层，README 缩成 62 行地图。
约定：**新增机制 = 在 INDEX 加一行**，历史写 journal、现状写 systems（见 ADR-001）。

### 风险

| 级别 | 风险 | 现状与触发条件 | 建议 |
|---|---|---|---|
| 中 | **`transparent` 是编译期属性，改它不 `needsUpdate` 会静默无效** | `setCollidersVisible` 已四处一起改并标脏。但若以后有人在别处改 `material.transparent`（比如给地块加「半透明高亮」），着色器不会重编译 → 表现是「设置没生效」，容易误判成排序问题复活。它还会让地面重新进透明列表，把刀光盖掉。 | `fxDebug().boxOpaque` 已经是守门（smoke 里断言 `materials.every(m => !m.transparent)`）。任何改地块材质的新代码都要在切换处调 `needsUpdate`；若真需要半透明地块，改用 `MeshBasicMaterial + 顶点 alpha`，不要动 `transparent`。 |
| 中 | **`FX_ORDER` 是约定，不是编译期约束** | 类型上仍是 `number`，`three-scene.ts` 里也还有几处直接赋 `renderOrder = X`（历史遗留）。有人写裸数字就绕过了整条单调链，且**只在特定镜头角度**看得出来。 | 把 `setFxOrder()` 做成唯一写入口：给 `Object3D.renderOrder` 加 lint 规则（搜 `\.renderOrder\s*=`），或统一走 `fx-layer` 的工厂函数。 |
| 中 | **`spar` 的站位带在狭窄地形会顶墙** | `standoff = 起手距离 × 1.7`，大剑 reach 2.0 → standoff 3.4m，而「地形 / 门洞」工位宽 2.4m。陪练会被夹在墙与站位带之间反复进退（视觉上是「原地抽搐」）。 | 给 standoff 加「可用空间收缩」：用 `groundHeightAt`/射线查背后 0.8m 是否有墙，有就临时降 standoff；或给 `spar` 加「顶墙 1.2s 后改走切向」。 |
| 中 | **陪练的 `combat` 与主角同构，但缺卡肉** | 没有 `hitstop`（AI 侧没有冻结路径）。连击已在 v9s.39 补上，卡肉仍缺 —— 表现上「陪练打中你」比「你打中陪练」软。 | 要补就只给**玩家受击**补短卡肉，别给 AI 补（三个一起停会把混战拖成慢动作）。 |
| 中 | **连击让单轮伤害事件 ×3，占空比要按「轮」算** | 现在 3.4s 间隔 / 一轮约 1.7~2.4s，占空比 50~70%。改 `attackInterval` 或 `comboCount` 时若只看「一刀多长」会严重低估压迫感。 | 调参前先算 `一轮时长 ÷ (一轮时长 + attackInterval)`；超过 80% 就会读成「没有喘息」。 |
| 低 | **`groundHeightAt` 只按中心点取高度** | 环跨台阶边缘时一半埋进去、一半浮空。当前关卡所有高台都够大（≥2m），未触发。 | 需要贴合边缘时给环做顶点级采样（`RingGeometry` 顶点逐个查高度），代价是每帧 N 次盒查询；建议先做 LOD：只在跨边缘帧启用。 |
| 低 | **`fighterColors` 只有三套** | 加第四个陪练必须手加配色，否则吃默认色（与玩家同色）→ 混战里分不清哪个是自己。 | 把配色改成「按 id 从调色板取模」，或至少在 `createDummies` 里对缺配色的陪练打一条 `console.warn`。 |
| 低 | **`noDamageToPlayer` 默认翻转让「无伤害契约」失效** | 4 个旧用例已在用例内显式写回 `true` 并注明「守的是旧契约」。但**外部脚本 / 旧文档**若依赖默认值，会突然「玩家被推走」。 | 把「默认值」和「测试限制」在配置注释里分开写；外部验收脚本一律显式设置该字段，不要依赖默认。 |

### 处置优先级

具体做什么、按什么顺序，只在 [`state/CURRENT.md`](state/CURRENT.md) 的「下一步」里维护 —— 本文件不重复排期，避免两处漂移。

### 不做 / 暂缓

- **特效全设 `depthTest: false`**：会把特效画到墙后面去（站在门洞一侧能看到另一侧的刀光）。
  排序问题用排序解决。
- **给假人 AI 加卡肉**：三个陪练互相拖慢，且观感上「谁在打我」更难读。（连击不在此列 —— 那是玩家能读到的节奏，已做。）
  真要做，先给玩家受击侧加。
- **陪练用独立的骨架 / 动画数据**：一旦分叉，「和主角一样」这条需求就再也保不住，
  且混战强度不可比。

## 历史结论（按版本，已关闭）

### v9s.37

两件事：**卡肉节奏重做**（用户问「减速 + 加速是否更合适、战神怎么做」）与
**大剑第三击击地 + 扫掠数据自动采样**（用户要求）。

### 卡肉

定性：硬冻结的问题不是「不够重」，而是**把整段动作拉长**。改成三段式
（5% 保持 45~130ms → 55ms 缓回 1 → 1.5× 偿还）后总帧数守恒（38 / 41 / 38）。
`hitstopComboFalloff = [1, 0.85, 0.72]` 解决「每击都卡 → 三连发黏」——
这是战神式「每击都有卡肉」能成立的隐含前提。

### 击地

`slamU=0.6` 来自采样（刃尖 y 在 u≈0.605 穿 0），半径 2.4m，`onlyUnhit` 默认 true
（扩大覆盖不叠伤害）。实测一刀 3 目标。表现层尘环半径 = 判定半径。

### 工具

`npm run sweep`：减根节点 yaw + 预热 16 帧 + u→progress 换算。
顺手验证九段现有曲线偏差 2~3°，不需要重写。

### 风险

| 级别 | 风险 | 现状与触发条件 | 建议 |
|---|---|---|---|
| 中 | **偿还与「取消窗口」相互作用** | `payback` 只在 recovery 内生效，而 recovery 过 `cancelWindow` 比例后允许提前接下一段。偿还把 phaseTimer 推快 → 取消窗口提前到达 → 连招节奏整体前移约 1~2 帧。单测锁了总帧数，但没锁「取消窗口的实际时刻」。 | 真机若觉得「连招接得比预期早」，把 `payback` 降到 1.3，或 `paybackBudget` 降到 0.4；不要改 `cancelWindow`（那是另一件事）。 |
| 中 | **`holdRate` 越低越像卡死** | 5% 是「还能看出在动」的下限附近；软件渲染只有 12fps 时，5% ≈ 每帧 0.06°，画面上可能读作「完全静止」。 | 低帧率设备上反而应该**调高** holdRate（8~10%），否则瓦片退化成冻结。已做成面板滑杆，真机可调。 |
| 中 | **击地的 `onlyUnhit` 语义** | 默认只打「刀没碰到的人」。如果玩家用第三击只打单个正面目标，击地**完全不产生额外命中** —— 会有人觉得「范围攻击没生效」。 | 想要「砸地再补一刀」就把 `onlyUnhit` 设 false（伤害翻倍，属于平衡改动，需单独评估）。当前选择是「不改变数值，只扩大覆盖」。 |
| 中 | **大剑第三击刃尖入地 0.40m** | 采样显示 u≥0.7 时刃尖 y=-0.40m。当前镜头角度下读作「插进地里」，但换到低角度 / 近景会明显穿模。 | 要么收敛该段最后的腕部俯角（动画改动，需重采 `hitSweep` 与 `slamU`），要么在表现层给武器加「地面钳制」。后者更快但会改变挥击末端轨迹，建议真机确认后再动。 |
| 低 | **采样工具的 u=0 点不准** | 第一点从上一次姿态跳过来，预热 16 帧仍差 16°（其余点 2~3°）。u=0 是身后蓄势点，不产生命中，影响可忽略。 | 若要精确，把第一个点单独 `warm=40`；或采样前先把 u 置 0 跑 30 帧再开始。 |
| 低 | **`warp` 只缩动画，不缩世界** | 卡肉期间世界时间照走（受击计时、AI、投射物）。这是刻意的（与 v9s.29 一致），但意味着「卡肉时敌人还能动」——如果将来加敌方攻击同步，会出现「我卡住挨打」。 | 保持现状；若要做「全局顿帧」，那是另一套机制（`world.timeScale`），不要混进 `warp`。 |

### 可优化方向（按投入产出排序）

1. **把 `--write` 接进 `npm run verify` 的 dry-run**（1 小时）：每次发布前跑 `--check`，
   偏差 > 6° 就失败 —— 现在只是打印警告，靠人看。
2. **击地尘环按实测半径自适应**（1 小时）：现在环半径读配置；如果以后给不同武器配击地，
   环和判定必须同源（已经同源，但缺一条测试）。
3. **`slamU` 自动写入**（半天）：`--heights` 现在只打印，可以让 `--write` 顺带把
   「刃尖穿地点」写进 `groundSlam.slamU`，彻底消掉手抄。
4. **低角度穿模修正**（半天）：见上表「刃尖入地 0.40m」。

### 不做 / 暂缓

- **全局顿帧（`world.timeScale`）**：会破坏确定性契约，且与「卡肉不缩世界」的既有语义冲突。
- **卡肉期间加轻微镜头变焦**：战神的做法是靠音效 / 受击姿势，镜头是刻意克制的；我们已经有 shake + kick，再加会盖住目标。
- **给每段连击单独配 holdRate**：目前只有三段 × 四把武器，参数还不够多到需要分层。

### v9s.36

用户报的「卡肉发生在武器还没打到人」定性为**判定时机**问题，不是表现层滞后：

- 卡肉载体 `CombatState.hitstop` 冻结 Core 的攻击时间轴 / 前冲 / 连击窗口，还进插值离散键，
  **不能只在表现层延迟**（逻辑停了画面还在走，解冻要补跳）；
- 根因是 `hitWindow.start = 0`：active 第一帧就扫扇形，而此刻 `swingCurve = -1`（刃身在身后蓄势），
  于是「刀在身后」就命中并定格。

修法：`WeaponProfile.hitSweep` —— 每段连击一条「刃尖相对角随 u」的曲线（clip-lab 逐进度采样
`bladeWorld()` 得到，与真实剪辑同源），Core 只在本帧扫掠区间覆盖目标方位角时结算。
剑盾一段命中 `progress 0.217 → 0.362`、刃尖离目标 `2.0m → 0.33m`；三段连击 3/3 命中，
范围 / 伤害 / 击退 / 卡肉时长全不变；删配置即回旧行为。代价：按键到命中 +40~70ms。

### 风险

| 级别 | 风险 | 现状与触发条件 | 建议 |
|---|---|---|---|
| 中 | **命中延后与「跟手」的取舍** | 剑盾一段最明显（+56ms），大剑二段几乎为零。动作游戏 0.15~0.2s 属于可接受区间，但快节奏玩家会觉得「出刀慢」。已经用 `tolDeg=12` 留了余量。 | 真机若嫌慢，先把 `tolDeg` 调到 24~32（每 +10° 约提前 0.03u），再不行按段删 `hitSweep`。不要直接改 `hitWindow.start` —— 那会让「刀还没到」重新出现。 |
| 中 | **曲线与剪辑漂移** | `hitSweep` 是采样值，不是运行时算的。任何一次改关键帧 / 调节奏（`windup`/`active`/`recovery` 比例变化也会改变 `u ↔ progress` 映射）都会让判定重新错位，且**测试抓不到**（单测锁的是配置自洽，不是画面）。 | 改动画的批次必须重跑采样探针；或把「采样 → 写配置」做成一条命令（见优化方向 2）。 |
| 中 | **突刺段用 `stabU` 是近似** | 剑盾第 3 段刃尖角 48°→36° 几乎不变，用「u ≥ 0.42」代替几何接触。目标贴身或偏侧时，实际接触可能更早/更晚。 | 若真机觉得第三段「顿一下才响」，把 `stabU` 调到 0.36~0.38；或改成「刃身线段到目标距离」判定（更准，但要给 Core 传 base/tip 两点的曲线）。 |
| 低 | **扫掠区间跨 ±180° 的边界** | 区间用 `[min(a0,a1), max(a0,a1)]`，隐含「刃尖单向扫过」。若某段动画出现「扫过去又扫回来」（回刀），区间会错误地包含回程，导致回程也能命中。当前 9 段都是单向，未触发。 | 加这类动画时，把区间改成「按方向的有向区间」，或直接换 `pts` 多点采样 + 逐帧相邻区间判定。 |
| 低 | **`tolDeg` 是全局单值** | 所有武器共用 12°，但各段扫掠角速度差 3 倍（大剑慢、双剑快）。同一容差在不同段对应的「提前量」不一样。 | 需要精调时把 `tolDeg` 下放到 `byCombo` 每段单独给。 |

### 可优化方向（按投入产出排序）

1. **`npm run verify` 加「命中时机」闸门**（已完成一半）：smoke 已断言 `progress ≥ 0.30`，
   还差「三把武器 × 三段」全跑一遍（现在是剑盾一段）。
2. **采样 → 写配置脚本化**（2~3 小时）：`tools/sweep-sample.mjs` 一次跑完 9 段 × 21 点，
   直接改写 `config/game.json` 的 `hitSweep`，消除「改了动画忘了重采」这一类风险。
3. **刃身线段判定**（半天）：把 `pts` 从「一个角度」升级成「base + tip 两个点」，
   Core 做线段-目标距离判定。彻底解决突刺段的近似，也能顺带修「1.9m 外隔空命中」
   （`reach 1.6 + 半径 0.3` 大于刃身实际 1.15m）。
4. **命中延迟进调试面板**（1 小时）：把 `tolDeg` 做成滑杆，真机 A/B 时不用改配置重启。

### 不做 / 暂缓

- **在表现层延迟卡肉**：Core 已冻结时间轴，延迟只会制造逻辑 / 画面错位。
- **直接收 `reach` 到刃身长度**：能消掉隔空，但那是平衡改动（索敌 `idealRange=1.35` 也要跟着改），
  应单独一轮评估，不混在手感修复里。
- **把 `swingCurve` 搬进 Core 让两边共用**：方向对，但表现层的 `swingCurve` 只负责姿态，
  与「刃尖实际位置」还隔着臂长 / 腕部 IK / 副手握持；采样曲线反而更接近玩家看到的画面。

### v9s.35

**上一轮列的 3 条优化方向落地了 2 条半**：
① 「离散字段显式标注 + 插值白名单」→ 快照补齐 `velocity` / `dash.timer` / `turnInPlace.progress` /
`playerLink.progress` / 假人速度，三套状态机的**阶段**进 `discreteKey`，每条字段在 `pose-interp.ts`
里注明「表现层哪里读它、不插值会怎样」，规矩写进 `docs/systems/animation-notes-2.md`（v9s.35 一节）。
② 「发布自检脚本」→ `npm run smoke`（8 项画面层事实）。
③ 「clip-lab `--strike` 口径」仍未做（见下）。

用户报的「慢放时角色方向一顿一顿」定性为**角速度台阶**，不是掉帧也不是朝向没插值：
位置是一阶量、朝向乘以 0.4~0.8m 半径才现形。修法是两层 —— 根因层补数据，手感层加
35ms 低通（`renderInterp.yawSmoothMs`，0 = 关闭）。量化：0.25× 转身 240 帧，
画面不动帧 180 → 0，单帧最大 4.6° → 1.08°，终点朝向差 < 0.1°。

### 风险

| 级别 | 风险 | 现状与触发条件 | 建议 |
|---|---|---|---|

| 低 | **视觉验收仍以截图为主** | clip-lab 覆盖了九段挥击的角度与截图，但**待机 / 移动持械姿态**没有自动化视觉基线；本轮靠 5 张截图人工确认。改一个 stance 数值，回归只能靠人眼。 | 给 `clip-lab` 加 `stance` 模式：五把武器 × 两种体型 × idle / walk，输出固定机位截图与刃身世界角度，和基线图做像素差 / 角度阈值。 |
| 低 | **角度单位混用** | 挥击数据用度（`bladePitchDeg`），`stance` 的手臂偏移用弧度，同一份 JSON 里两种单位。写配置的人很容易把 `0.15` 当度写成「几乎没动」。 | 统一在 JSON 层用度（`armR.pitchDeg`），加载时转弧度；或至少在 schema 里对字段名强制 `Deg` 后缀。 |

### 可优化方向（按投入产出排序）

1. **配置校验脚本**（0.5 天）：一次投入，之后每次改 JSON 都能在发布前挡住低级错误。
2. **动画层管线化 + 黄金姿态**（1~2 天）：只读重构，先把「层序」变成数据，再谈加层。
3. **卡肉去重 / 上限**（0.5 天）：补一条双目标命中用例，避免手感被长冻结拖闷。
4. **待机姿态视觉基线**（1 天）：扩展 clip-lab，把「五把武器站姿」纳入自动截图。
5. **包体拆分**（1 天，按需）：先测首屏，再决定是否拆 `three` 与调试模块。
6. **体型切换的战斗态收尾**（0.5 天）：清刀光、战斗权重归零，补用例。
