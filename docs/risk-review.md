# 框架风险与优化方向（滚动评审）

> 约定：每批改动完成并发布后更新本文件，同时在交付说明里给出本轮结论。
> 只记录**结构性问题**与**可执行建议**，不写「以后再说」的愿望清单。

## 当前活跃风险（v9s.61 更新）

### 沙盒里 `git fetch` 会卡死在 HTTP/2（v9s.61）

现象：`git fetch origin --prune` 稳定卡 134 秒后报
`Failed to connect to github.com port 443`，但 `git ls-remote` / `git push` 都正常。
本方连续三次 `npm run feat:finish` 都死在第一步 fetch，看起来像网络抖动，实际是
https 传输的 HTTP/2 多路复用在这个出口被中断 —— 单次请求（ls-remote）不受影响，
只有 multiplexed 的长连接会挂。

处置：`git config http.version HTTP/1.1`（只写 `.git/config`，不入库），
之后 finish 一次跑通（领号 → build → golden → verify → PR #8 → 合并 → 发布）。

**别反复重跑**：症状和「网络抖一下」完全一样，但每次都会固定耗掉 134 秒。

### 「表现层采样、Core 下一帧消费」的差一帧，会吃掉整批命中（v9s.60）

可破坏物「有时候砍不到」的第二个根因：`computeHits` 在 `render` 里跑、把候选塞进队列，
真正结算在下一个 `step`。如果挥砍恰好在这一帧结束时关闭 `currentMeleeShape`，
闸门 `if (!shape.active) return` 会把**整批**候选丢掉 —— 与位置、角度无关，
只跟帧序有关，所以现场表现为「随机砍不到」。

处置：`world.meleeGatePrev` 记住「上一帧形状是开的」，只放行**一个 tick**。
**结构性教训**：凡是「表现层采样 → Core 消费」的通道（命中候选、贴地高度、注视目标），
都要问一句「跨帧时这个开关还在吗」，否则就是一个只在特定帧序复现的 bug。

### `world.boxes` 是共享引用，不能 `filter` 重建（v9s.60）

可破坏物要加碰撞，很自然会写 `world.boxes = world.boxes.filter(b => !b.id.startsWith('dest-'))`
再 push 新的。但 `boxes` 被移动、相机、贴地特效同时持有 —— 替换数组后它们继续读旧对象，
表现为「刚砍断还能撞一下」「断完了相机还卡着」。

处置：碰撞盒一次生成，之后**原地改 `maxY`**（`gone ? minY : y + standU*height`）。
**结构性教训**：`World` 上被多个模块读的数组，生命周期只能「原地改」，不能「换引用」。
同类：`health.bars`、`grass.patches`。

### golden 漂移：先证明「没变」，再更新（v9s.60）

本批 `health.sever` 与 `world.meleeGatePrev` 两次让 determinism 快照漂移。
两次都先用临时测试**剔除新字段重算 hash**，等于旧值（`c6465bcb…` / `753e12af…`），
再 `vitest -u`。不这么做的话，「结构变化导致的漂移」和「行为真的变了」长得一模一样。

**结构性教训**：任何改动 `World` 形状的提交，都要能回答「旧字段的 hash 还是不是原来那个」。

### 地块 `span` 是全局槽位，动它等于动别人的位置（v9s.60）

把 `x-destructibles` 从 `[2,2]` 撑到 `[3,3]`，整数格 first-fit 把别的工位推到了
假人测试位置，smoke 的踱步 / 命中三项直接挂。**加物件优先在本地块内散开（坐标），
不要改 `span`**；真要撑大，跑完 `npm run smoke` 再看 `plotDebug().slots`。

### 发布链路：「推到 preview」≠「线上已是新版」（v9s.55）

本批发布时踩到一次：`npm run ship` 报了推送成功，`preview` 分支上的 `index.html` 也确实
指向新的 `main-DGeEthZi.js`，但**线上仍在发旧包**。查下来是 Pages 的
`pages build and deployment` 连续两次 `abandoned` / `failed`，而 CDN 继续用上一次成功
构建的 `index.html`（缓存 10 分钟）—— 表面现象是「版本号没变」，很容易被当成没发出去。

三条处置：

- **`ship.sh` 末尾自动核验**：`python3 tools/check-online.py --wait 120` 比对「线上
  `index.html` 引用的 JS 文件名 / 大小 / 徽标版本」与本地 `dist/`。只提示、不改退出码。
- **失败了就重触发**：`POST /repos/.../pages/builds`（带 token）。同一 commit 重跑一次即可，
  不要改代码、不要重复 ship。
- **别用 `curl` 的 `?cb=` 判断成败**：加随机参数能绕开 `index.html` 的 CDN 缓存，但绕不开
  「构建还没完成」；两者现象一样，先查 Actions 的 `pages build and deployment` 结论。

**残余风险**：Pages 构建的排队时间不受控（本次 6~10 分钟）。若哪天彻底挂掉，
退路是 `preview` 分支改由 Actions 部署（`build_type: workflow`），但那要改仓库设置，
不在代码可控范围内。

### 底板地块化：装得下，但地图从原点向东北长（v9s.49）

**问题**：单块 32×32 底板装不下第 10 块测试地（`sparring-demo` 北缘已出界 0.5 m），
而底板是单体、地块位置是手写绝对坐标 —— 加一块地既改共享文件，又要手工找空位。

**做法**：每块地自带 `span × 5 m` 的承重地板，进场景按整数格 first-fit 拼合；
`worldBounds` / 寻路格网 / 阴影相机全部从拼合包围盒推导。地形 / 门洞 / 障碍 / 初始假人 /
草块一并写进地块文件（`dx/dz` 相对坐标）。

**结构性代价**（都已确认可接受，写在这里免得下次再纠结）：

- **地图只往东北长**：`hub` 钉在原点（出生点就在它板上），first-fit 只扫描 `+c / +r`，
  所以西南侧永远是边界。想居中要给 `PlotDef` 加 `at:{c,r}` 或改环形扫描 —— 都会引入
  「谁先占谁得」之外的新规则，暂不做。
- **`id` 改名 = 重排**：按 id 字典序占位，排在后面的顺延。id 一旦发布就不能改。
- **填充板是隐形地板**：`plotId === ''`，不进工位面板、不画板框，但它在碰撞盒里。
  排查「这里怎么有地面」时先看 `plotDebug().slabs` 里有没有空 `plotId`。
- **地块内物件可以出界**：拼合器只解算坐标、不校验物件是否落在本板上。
  目前靠单测「每块地的自带物件都落在自己的地板范围内」兜住，新加物件要跑一次。

**残余风险**：`worldBounds` 是矩形，而地板理论上可以是非矩形（当前 9 块刚好填满，
只有 r6-r7 的 c2..c5 是填充板）。若将来出现大面积空洞，`bounds` 会允许角色走到没地板的地方
—— 现在的兜底是「填充板补齐包围盒」，这条不能删。

但推送前仍应 `git branch backup/<名字>` 留一份。

### 下盘偏转的时间基准：慢放 / 低帧才是照妖镜（v9s.45）

v9s.44 的闸门用**渲染帧 dt** 算身体角速度。0.25× 慢放时身体转过同样角度要多花 4 倍
真实时间 → 角速度只剩 1/4 → 闸门从「全关」变「半开」，限速率的 `free·3400°/s` 逃生口
又把半开当成放行：单帧 18.6°、摆幅 25°。修法是五条配套（游戏时间角速度 / 一阶闸门 /
线性限速 / 前后相位各一档 / 零速淡出），单帧 18.6° → 1.4°。风险与边界：

- **所有跟手感有关的时间常数现在都吃「游戏时间」**（闸门、限速、`hipYaw` 平滑）。
  常速下 `gameDt ≡ frameDt`（逐位相同），但**暂停（timeScale = 0）时它们会冻住** ——
  这是想要的（暂停画面不该继续「缓动到位」），但如果以后有「暂停时也要动的装饰层」，
  不能直接复用这几个状态。
- **`coreTime` 不传就退化为 `frameDt`**（单测 / 旧调用路径）。新加骨架必须传，漏传
  不会崩，只是那个单位在慢放里仍会抖。
- **速度 < 0.5 m/s 时偏转目标按比例淡出**：低速侧移（< 0.5 m/s）时下盘不再带转。
  实测这个速度下步子本身已经很小，看不出来；但「贴墙慢慢蹭」的观感变了。
- **前后相位两档限速（240 / 150 °/s）是手调值**，不是物理量。后退族压得更低意味着
  「从斜后方快速切到正后方」时下盘会有 ~0.2s 落后（脚的对轴晚一点），换来扫掠期间
  不被拽出去。
- **A/B 开关仍是 `hipYawTrackRateDeg = 0`**（整套关掉，含新增的后退档）。

### 下盘转向对策：靠「身体自己在转」这个判据（v9s.44）

「朝向切换时下盘晃一下」的根因是下盘偏转目标有两个族（侧移 +50° / 后退 −48°），
身体转动时 θ 扫过 90°→132°，目标只能跳族（单帧 52.7°，整条 S 摆幅 57°）。
修法是`身体自己在转的时候，胯不自己拧`：转身闸门 + `hipYawTrackRateDeg = 200°/s`。
风险与边界：

- **判据只有身体角速度一个信号**。30°/s 以下完全不限速（与旧行为逐位一致），100°/s
  以上才完全接管。刻意转身很慢（< 30°/s）时下盘仍会跟着 θ 走 —— 那时 θ 本身也走得
  很慢，实测摆幅 < 10°，看不出来；但「极慢地原地画圈」这种玩法没有被优化过。
- **转身期间斜向倒退的下盘对轴会暂时失效**（停了侧移族的翻转）。转身结束、闸门松开
  后由节流在 ~0.2s 内补上。所以「一边快速转身一边斜后方撤退」的 0.2s 里，脚的对轴
  是旧的、会有一点滑；速度低，实测不可见。
- **闸门用 `turnRate` 的瞬时值**。传送 / 复活那种 `bodyYaw` 突变的帧会被判成「转身」，
  于是那一帧下盘不动 —— 反而是想要的（避免瞬移后甩胯）。
- **状态同样活在骨架里**（`lastHipYawTarget` / `sideYawTarget` / `prevHipBodyYaw`），
  加第三个 rig 要接；漏接不会崩，只是那个单位仍会晃。
- **A/B 开关是 `hipYawTrackRateDeg = 0`**，面板滑杆可实时拉；注意它是「整套对策」的
  总开关，不是单纯的限速。

### 换向融合：0.16s 的「收腿窗」是有代价的（v9s.43）

「前进切后退腿抽一下」的根因是**摆腿方向的符号**一帧取反（整条腿位镜像，实测单帧
1.06~1.26 rad）。修法是让符号在 `dirFlipSec = 0.16s` 内走过 0，摆幅跟着收放 ——
换向那一帧现在不比正常走一步更激烈（0.55 vs 0.53）。

代价与边界：

- **换向途中腿会「收一下」**（约 0.16s 摆幅收窄再长回来）。物理上这是对的（人换向要先
  落脚再蹬地），但短促，看得仔细会觉得「顿了一下」。觉得太重就调小 `dirFlipSec`（0.1），
  觉得太生硬就调大（0.25）；拉 0 = 精确回到旧行为，可直接 A/B。
- **只在符号真的翻转时生效**。同一方向上转圈（yaw 扫过 90° 导致局部前后分量翻号）也会
  走这个窗口 —— 那一瞬间腿本来就在侧摆主导，收窄量很小，实测无可见差。
- **状态活在骨架里，不进 Core / 快照**（与停步收相、击退步态同一层）。确定性快照不受影响；
  但两个 rig（`voxel-rig` / `dummy-rig`）各存一份，加第三个 rig 时要记得也接上
  （漏接不会崩，只是那个单位换向仍会抽）。
- **零滑步前提只在稳态成立**。`|dirF| < 1` 的那 0.16s 里脚前伸距离按比例缩短，
  支撑脚理论上会有毫米级滑移；因为发生在速度接近 0 的窗口，实测看不出来。

### 手感面板的相位：可视化了，但只是「相位」不是「脚」（v9s.42）

手感面板第三区现在画 `sin φ`，并按踩地侧分色（琥珀左 / 紫右 / 灰双踩 / 青腾空）。
两个刻意的简化，调参时要记着：

- **判据是相位，不是脚的真实高度**。`|sin φ| ≤ 0.16` 一律算「换脚的双支撑」，
  但实际脚位还受停步收相、侧跨、IK 钉地影响 —— 极端姿态下「面板说踩地、画面里脚其实半抬」
  是有可能的。要更准就得把 `solveGait` 的 `lift` 暴露出来（成本不高，但当前没必要）。
- **插值补点只影响观感**。低帧率下按 2px 一个点补，形状对了，但补出来的中间点没有
  真实采样 —— 拿它做数值断言会自欺，断言一律走 `motionDebug.samples()` 的原始帧。

### 攻击跨步：一次一刀 = 一步（v9s.41）

用户反馈「攻击跨步之时，再接跨步攻击没有换腿跨步」。根因不在腿部动画，而在**相位**：
旧的攻击等效驱动是 `基准 + π × 往返脉冲(p)`，每段结束都回到同一基准 —— 连着打三刀，
下盘姿态逐帧完全重合；而段间取消（`cancelWindow`）会把还没走完的相位硬拽回基准，
实测单帧腿角跳 **0.82 rad**（47°），读起来是「脚被拽回去」。

现在每段 = 迈一步（`smoothstep(p) × π`），起点接上一段停下的相位，步序 `attackStepIndex`
单调递增（不用 `comboIndex`，它 3 连击后会回到 1）。同时 `applyStep` 的骨盆前跨 / 侧跨 /
下沉改成指数趋近，换段不再一帧退回 8.7cm，而是 0.2 秒的体重转移。

> 判据：**不要**用「每段腿角峰值符号」。幅度包络在 active 段才涨起来，峰值位置随打击帧漂移，
> 我第一版断言就是这么假失败的（1/2 段同号）。要看段起始相位，相邻段之差 ∈ [0.5π, 1.2π]。

### 对峙走位：从「一直绕圈」到「走走停停」

「陪练保持距离时疯狂磨脚」不是动画问题，是**走位策略**问题：死区内每帧都给切线方向
（永不归零），且径向是开关式的（±0.35 / −0.45，阈值附近逐帧反转）。修法是
**连续径向 + 时间门控横移**（`strafePeriod / strafeDuty`，按 id 错相位），
外加修掉 `fighter-rig` 把击退并进 `velocity` 的双计。详见
[`systems/dummies-fighters.md`](systems/dummies-fighters.md)「对峙时走走停停」。

> 方法论：先在 Core 里量「移动帧占比 / 移动时均速」再动表现层。v9s.40 之前若先去调
> 步幅、抬膝、停步阈值，全部是白忙 —— 数学层（`solveGait`）本来就是 C¹ 连续的。

### 特效看不见：两个根因，都不在「数值」上

1. 白盒地块 `transparent: true`（即便 `opacity: 1`）→ 进透明列表 → 按「`renderOrder` →
   距离由远到近」排；32m 地面盒的排序距离取**包围球中心**，角色站到场边时地面被排到
   刀光之后、`opacity: 1` 整片盖掉。所以只在**某些地块**复现，场中央永远测不出来。
2. 贴地特效 `y` 写死 → 站上台阶就埋进方块里。

顺手把散落的 `renderOrder` 魔数收进 `FX_ORDER` 单调序列。

### 风险

| 级别 | 风险 | 现状与触发条件 | 建议 |
|---|---|---|---|
| 中 | **`transparent` 是编译期属性，改它不 `needsUpdate` 会静默无效** | `setCollidersVisible` 已四处一起改并标脏。但若以后有人在别处改 `material.transparent`（比如给地块加「半透明高亮」），着色器不会重编译 → 表现是「设置没生效」，容易误判成排序问题复活。它还会让地面重新进透明列表，把刀光盖掉。 | `fxDebug().boxOpaque` 已经是守门（smoke 里断言 `materials.every(m => !m.transparent)`）。任何改地块材质的新代码都要在切换处调 `needsUpdate`；若真需要半透明地块，改用 `MeshBasicMaterial + 顶点 alpha`，不要动 `transparent`。 |
| 中 | **`FX_ORDER` 是约定，不是编译期约束** | 类型上仍是 `number`，`three-scene.ts` 里也还有几处直接赋 `renderOrder = X`（历史遗留）。有人写裸数字就绕过了整条单调链，且**只在特定镜头角度**看得出来。 | 把 `setFxOrder()` 做成唯一写入口：给 `Object3D.renderOrder` 加 lint 规则（搜 `\.renderOrder\s*=`），或统一走 `fx-layer` 的工厂函数。 |
| 中 | **`spar` 的站位带在狭窄地形会顶墙** | `standoff = 起手距离 × 1.7`，大剑 reach 2.0 → standoff 3.4m，而「地形 / 门洞」工位宽 2.4m。v9s.40 把开关式径向换成比例控制后，「阈值附近抽搐」没了，但顶墙时径向仍持续朝外、被边界清掉 → 空踩（速度满格、位移为 0）的**残留风险**还在。 | 给 standoff 加「可用空间收缩」：起手前查背后 0.8m 是否有墙，有就临时降 standoff；或顶墙 1.2s 后改走切向。 |
| 中 | **陪练的 `combat` 与主角同构，但缺卡肉** | 没有 `hitstop`（AI 侧没有冻结路径）。连击已在 v9s.39 补上，卡肉仍缺 —— 表现上「陪练打中你」比「你打中陪练」软。 | 要补就只给**玩家受击**补短卡肉，别给 AI 补（三个一起停会把混战拖成慢动作）。 |
| 中 | **连击让单轮伤害事件 ×3，占空比要按「轮」算** | 现在 3.4s 间隔 / 一轮约 1.7~2.4s，占空比 50~70%。改 `attackInterval` 或 `comboCount` 时若只看「一刀多长」会严重低估压迫感。 | 调参前先算 `一轮时长 ÷ (一轮时长 + attackInterval)`；超过 80% 就会读成「没有喘息」。 |
| 中 | **收势淡出会把相位「扫回」真实步态** | 攻击结束时 `drive.phase` 与 `real.phase` 可能差最多 π（3 连击累计 3π ≡ π）。淡出用最短弧插值抹平，**边走边收招**时这段会在 ~0.5s 里多扫半圈（实测单帧最大 0.28 rad，且幅度同时在衰减）。静止收招看不出来。 | 若真机觉得「收招那一下腿甩了一下」，把 `view.animation.attack.blendRate` 从 14 降到 9（拉长淡出），或让 `attackPhaseBase` 在 combo 结束时取「最近的真实相位等价点」。不要改回往返归零 —— 那会退回本轮的 bug。 |
| 低 | **`groundHeightAt` 只按中心点取高度** | 环跨台阶边缘时一半埋进去、一半浮空。当前关卡所有高台都够大（≥2m），未触发。 | 需要贴合边缘时给环做顶点级采样（`RingGeometry` 顶点逐个查高度），代价是每帧 N 次盒查询；建议先做 LOD：只在跨边缘帧启用。 |
| 低 | **`fighterColors` 只有三套** | 加第四个陪练必须手加配色，否则吃默认色（与玩家同色）→ 混战里分不清哪个是自己。 | 把配色改成「按 id 从调色板取模」，或至少在 `createDummies` 里对缺配色的陪练打一条 `console.warn`。 |
| 低 | **`noDamageToPlayer` 默认翻转让「无伤害契约」失效** | 4 个旧用例已在用例内显式写回 `true` 并注明「守的是旧契约」。但**外部脚本 / 旧文档**若依赖默认值，会突然「玩家被推走」。 | 把「默认值」和「测试限制」在配置注释里分开写；外部验收脚本一律显式设置该字段，不要依赖默认。 |

| 低 | **踱步门是「全局时间」驱动，不感知战斗** | `strafeGate` 只看 `world.time + id × 2.37`，所以出手前那一瞬可能正好在「站定」段 —— 读起来像「愣了一下才砍」。目前靠 `attackCooldown <= 0` 的压上分支盖住，未观察到明显问题。 | 若以后有人调大 `strafePeriod`，要同时确认「冷却结束那一帧」不会落在关门段：可让门在 `attackCooldown < 0.4s` 时强制开门。 |

### 处置优先级

具体做什么、按什么顺序，只在 [`state/CURRENT.md`](state/CURRENT.md) 的「下一步」里维护 —— 本文件不重复排期，避免两处漂移。

### 不做 / 暂缓

- **特效全设 `depthTest: false`**：会把特效画到墙后面去（站在门洞一侧能看到另一侧的刀光）。
  排序问题用排序解决。
- **给假人 AI 加卡肉**：三个陪练互相拖慢，且观感上「谁在打我」更难读。（连击不在此列 —— 那是玩家能读到的节奏，已做。）
  真要做，先给玩家受击侧加。
- **陪练用独立的骨架 / 动画数据**：一旦分叉，「和主角一样」这条需求就再也保不住，
  且混战强度不可比。
