# 框架风险与优化方向（滚动评审）

> 约定：每批改动完成并发布后更新本文件，同时在交付说明里给出本轮结论。
> 只记录**结构性问题**与**可执行建议**，不写「以后再说」的愿望清单。

## 本轮（v9s.34）结论

**上一轮的三个「中」全部关闭**：`splitSpine` 时序依赖 → `torsoTotal()` + 帧尾残差守卫
（`spineDebug().leak`，用例断言 0）；平衡闭环相位滞后 → 速度前馈 + 负载加权（`predLead / counterBoost`，
可 0 关闭回旧行为）；`test:affected` 正则解析 → 换 esbuild 真实模块图（多入口需给 `outdir`，已验证）。

### 风险

| 级别 | 风险 | 现状与触发条件 | 建议 |
|---|---|---|---|
| 中 | **渲染插值给画面加了半帧延迟** | `blend(prev, cur, alpha)` 的标准代价 ≈ 8ms。动作游戏里「跟手」是主观项，8ms 大多无感，但叠加触控采样延迟后可能被抱怨。而且插值只在 `alpha < 0.999` 时启用，帧率越高用得越多。 | 若真机反馈「有点钝」，先关 `view.renderInterp.enabled` 做 A/B；需要极致跟手时可改成「外推半帧」（用上一步速度推测当前时刻），代价是瞬移 / 闪现会过冲。 |
| 中 | **插值的 snap 判定是白名单** | `discreteKey()` 手写列举了武器 / 阶段 / 连击段 / 攻击 id / 卡肉开关 / 假人模式。将来 Core 新增一个「离散但影响姿态」的字段（比如姿态状态机 id），忘了加进 key 就会被插值抹成两帧之间的中间态，不报错、只是偶发怪姿势。 | 把「离散字段」从 Core 类型里显式标注（`/** @discrete */`），或改成「只对已知连续字段做插值」的白名单（现在是反过来的：黑名单式 snap）。加字段时的检查清单写进 `docs/animation-guidelines.md` 第五节。 |
| 中 | **clip-lab 收工改成「杀进程」** | `browser.close()` 在 swiftshader 下卡 30s，改成按 `--user-agent=cliplab-<pid>-<n>` 标记 `pkill -9`，再 `os._exit()`。副作用：① 依赖 chromium 把自定义 UA 放进命令行（版本升级可能要复核）；② `os._exit` 跳过 `atexit`，若以后有人在这里注册清理逻辑会被静默跳过；③ 杀掉的是「所有匹配该标记的进程」，同机并行跑两个 clip-lab 时标记不同（含 pid）所以安全。 | 升级 playwright / chromium 后跑一次 `check`，看耗时打印里「清理」是否仍 <1s、`pgrep -f cliplab-` 是否为空；异常就回退到 `page.close()`（实测 4.2s，可接受）。 |
| 低 | **esbuild 图看不见「隐式依赖」** | 模块图只覆盖真实 `import`。测试通过 `window.__harness` 接口间接依赖实现（比如所有 clip-lab 相关用例都依赖 `app.ts` 的暴露），这类关系图里没有。本轮实测 82 个测试文件「正则 vs esbuild」零差异 —— 说明当前代码里正则本来也够用，换图的价值是**不再依赖手写解析规则**，而不是修了某个漏检。 | 若要覆盖隐式依赖：给 `tests/` 加一份「契约 → 用例」映射表（例如 `app.ts` 改动强制带上 `v9s27-clip-lab` 相关用例）。 |
| 低 | **`predLead` 与 `reactionTime` 语义重叠** | `reactionTime`（0.18s）是 XCoM 的物理外推常数，`predLead`（0.12s）是控制器自己的提前量。两个都在「预测未来」，调参时容易只改一个、效果互相抵消。 | 中期把两者合成一个「预测时域」（物理项与控制项按固定比例派生），减少一个自由度。 |
| 低 | **动画数据的设计值与工具读数不是一回事** | `bladePitch = 1.62`（92.8°）是挂点语义，clip-lab 在 `t=0` 读到 41.5°，因为段首姿态按 `strike` 曲线淡入。这轮已写进工具文档，但「配置值 vs 世界值」两套口径仍靠人记。 | clip-lab 的 scan 增加 `--strike 1` 口径（强制满幅），并把两列并排显示，减少「改了数据看着没反应」的误判。 |

### 可优化方向（按投入产出排序）

1. **离散字段显式标注 + 插值白名单**（半天）：现在这套插值的正确性依赖「记得同步 key」，是典型的会随时间腐化的地方。
2. **clip-lab `--strike` 口径**（2 小时）：把「设计值 / 淡入后」两列并排，直接消掉一类误判。
3. **发布自检脚本**（2 小时，承上一轮）：仍未做，本轮推送 GitHub 又被权限卡住，说明「凭据 / 产物」这一层需要一个统一的校验入口。
4. **GVG / 低帧率下的插值收益量化**（半天）：当前只用 Node 单测证明了连续性，没在 30fps / 120Hz 真机上量「主观是否更顺」。

### 不做 / 暂缓

- **外推式插值**（用速度预测当前时刻）：能去掉半帧延迟，但瞬移 / 闪现 / 卡肉这类不连续运动一定过冲，收益不抵风险。
- **连击段首姿态改成「从上一段收势开始」**：本轮确认身体是连续的（身体跳变 0~10°），刃身跳变大是淡入造成的；真要改得重写三段剪辑的起手关键帧并逐帧截图验收，单独一批做。
- **clip-lab 出图自动化对比**：`--shots` 仍是人眼看的 PNG，像素基线成本高于本轮收益。

## 上一轮（v9s.33）结论

### 风险

| 级别 | 风险 | 现状与触发条件 | 建议 |
|---|---|---|---|
| 高 | **发布目录没定死，会静默退回 dev server** | 本轮线上页面「每隔十几秒自动刷一次」的根因不是代码，是发布流程：manifest 里 `runtime.language` 落成 `node`，发布脚本于是按 Node 项目起 `npm start`（= `vite` dev server），HTML 被注入 `/@vite/client`，HMR 一有文件变动 / 心跳就整页重载。改成以 `dist/` 为发布目录后走 `static`（`python3 -m http.server`）才正常。**这类问题本地完全复现不出来**（本地一直是 dev server，刷新是「正常现象」）。 | 发布前固定一条自检：抓一次线上 HTML，断言不含 `@vite/client` / `/src/main.ts`，且 `#version-badge` 的构建时间与本次 build 一致；不满足直接失败。把「发布物必须是 `dist/`」写进 `package.json` 的 `publish` 脚本，不靠人记。 |
| 中 | **`splitSpine()` 是「最后一刻改写」的隐式时序依赖** | 分段把「写 `upper` = 写躯干总角」变成「写 `upper` 之后还会被拆走 42%」。任何在 `splitSpine()` **之后**读 `upper.rotation` 的代码拿到的都是腰段局部角，而它以为那是总角。本轮实际撞了 5 处（副手 IK 的 `worldToLocal` 父节点、头部补偿、`applyWrist` 的 yaw、受击网格取 `children[0]`、四个测试的断言）。都不报错，只是数值偏。 | 加一个只读访问器 `torsoTotalYaw/Pitch/Lean()` 并在类型上把 `upper.rotation` 标成内部字段（命名 `upperLocal`）；配合「层管线化」把这层固定成管线末端的一个 stage，谁在它之后加层必须显式声明「我要局部角」。 |
| 中 | **平衡反馈是闭环，存在相位滞后** | 「读 IK 后脚位 → 算 XCoM → 写骨盆侧移」在同帧内完成，但骨盆位移会让下一帧脚位变化（IK 把脚拉回锚点），形成一圈反馈。`counterRate = 8`（≈0.125s 时间常数）是按「不抖」调的，不是按「跟得上」调的；剧烈位移（击退 + 转身同时）时余量会滞后 1~2 帧。 | 若要做「失衡 / 踉跄」玩法，反馈量必须改成**前馈**：从 Core 的速度 / 击退冲量直接预估倾倒方向，而不是等脚位算出来。当前实现只适合「静态度量 + 小幅修正」。 |
| 中 | **`test:affected` 靠正则解析 import，是不完备的** | 从 `git diff` 出发解析 `import` 闭包，只认静态 `from '...'` 与 `import('...')` 字面量；动态拼接路径、`require`、以及「测试通过 `__harness` 接口隐式依赖实现」都看不见。命中率 > 65% 时退回全量算是保险，但阈值是拍的。 | 短期：`config/game.json`、`tests/helpers.ts`、`tests/rig-nodes.ts` 已强制全量；再补一条「本轮改了 `src/presentation/**` 就直接全量」的兜底（表现层耦合最密）。中期：用 `vitest --changed` 的模块图（Vite 已有真实依赖图，不必自己解析）。 |
| 低 | **`hitstop` 时长与「本次命中」的绑定仍然靠状态读取** | 方向微推要在命中上升沿拿到受击者坐标，实现是从本帧 `world.events` 里找第一条 `hit`。同一帧多目标命中时只取首个；若 Core 将来把 `hitstop` 与 `hit` 分帧发出（例如先去重再冻结），这里会取不到方向，退化成「无方向震动」——不报错。 | 让 `hitstop` 事件自己带上 `x/z`（现在 `value` 只带时长），表现层不再跨事件类型拼信息。 |
| 低 | **`diagnostics()` 是采样读数，不能当峰值用** | `camera.kick` 是包络值，衰减 `exp(-13t)`，采晚 0.35s 就读成 0；本轮冒烟因此误判「微推没接上」，实际 `kickCount = 1`。同理 `maxHs` 读到的是**剩余量**而不是初始时长（0.13 = 0.1×1.3 是对齐的，但更早一次采到 0.0633）。 | 诊断里补「累计 / 峰值」类字段（`kickCount` 已加），凡是需要判断「有没有发生」的都读计数、需要判断「多大」的读测试里的确定性数值，不读瞬时采样。 |

### 可优化方向（按投入产出排序）

1. **发布自检脚本**（2 小时）：抓线上 HTML 断言非 dev server、版本号与构建时间一致、无 `@vite/client`。本轮这个坑花的时间比写功能还多，且只有线上能发现。
2. **`torsoTotal*()` 访问器 + `upperLocal` 改名**（半天）：把「总角 / 分段角」的区分从注释搬进类型，下一轮加层不会再踩。
3. **`test:affected` 换成 Vite 模块图**（半天）：现在的手写解析够用但脆，Vite 已经有真图。
4. **`hitstop` 事件自带坐标**（1 小时）：顺手把「同帧多目标」的方向取首个也一起解决。
5. **低帧率兜底**（1 天，承上一轮）：卡肉 / 震动在 7fps 下整段落在两帧之间，仍是未修项。

### 不做 / 暂缓

- **`hitflash`（受击者闪白）与重击时间缩放**：卡肉分层这轮只做了「时长 × 武器 + 方向微推」，闪白要改材质 / 后处理，时间缩放会牵动 Core 的确定性（所有 `dt` 都要乘），单独一批做。
- **脊柱三段以上（腰椎 / 胸椎再细分）**：两段已经吃掉绝大部分「一根棍在转」的观感，再加段需要真正的蒙皮或更多挂点，收益递减。
- **平衡做成玩法（失衡 / 踉跄）**：先解决上面的相位滞后，否则会变成「莫名被推倒」。

## 上一轮（v9s.32）结论

### 风险

| 级别 | 风险 | 现状与触发条件 | 建议 |
|---|---|---|---|
| 中 | **动画层序靠约定，没有显式管线** | `voxel-rig.update()` 已到 2400+ 行，步态 → 持械 → 战斗混合 → 受击 → 惯性 → 跨步 → 肩 → 形变 → IK 的先后顺序写在注释里，新增一层只能靠「读完整段代码」判断该插在哪。本轮 `stance` 就分别插在步态后、混合后、挂点反解内三处，任一处放错都会静默出错（动作看起来「有点怪」但不报错）。 | 把层拆成有序 `AnimationStage[]`（`name + apply(ctx)`），每帧按数组执行并输出每层写入的通道快照；配 3~5 个「黄金姿态」逐字节对比。先做只读重构，不改数值。 |
| 中 | **配置只靠 TypeScript 类型，没有运行时校验** | `game.json` 加载时直接断言成 `AppConfig`。`stance` 少写一个武器、把角度写成度、`notifies` 的 `u` 超出 0..1，都不会报错：要么静默回退，要么在真机上表现为「这把武器没姿态」。现有 `validateNotifies / validatePoseClip` 只在测试里调用，没有覆盖 stance 与 clip 引用。 | 新增 `npm run config:check`：JSON Schema + 业务校验（五把武器 stance 齐全、角度范围、`combo` 引用的 clip 存在、`notifies.u ∈ [0,1]`、`hitWindow.start < end`）。CI / 发布前强制执行。 |
| 中 | **打包是单块 776KB，调试面板与工具台全在主包** | `three` 全量 + 所有 panel / clip-lab 钩子打进一个 chunk。桌面无感，低端手机首屏与内存压力偏大；调试代码在生产环境也常驻。 | `manualChunks` 拆 `three` 与 `debug`；`lab / clip-lab / telemetry` 用动态 `import()`，只在按 `?dev=1` 或点开工位时加载；先量一次 4G 手机的首屏时间再决定是否值得。 |
| 低 | **卡肉档位会被更重的命中抬高** | `hitsUpdate` 取「本次命中时长与当前剩余」的最大值：轻击冻结 45ms 期间命中重击，会把这次冻结抬到 70ms（只抬一次，不会累加）。语义上「重击更重」说得通，但轻重混击的实际节奏没有用例验收。 | 若希望一次冻结只认**首次**命中，改成「`hitstop === 0` 才写入」；补一条「轻击后 1 帧重击」的时序测试，把两种语义都钉住。 |
| 低 | **持械姿态只覆盖上半身** | 腿仍共用步态：剑盾没有侧身脚位，跳起回到统一空中姿态。视觉上「上身换了、下盘没换」，大幅侧身时更明显。 | 若要做，给 `stance` 加 `hipYaw` 与脚位偏移；但会和停步收相 / 转身踏步抢 `lower.rotation.y`，需要先定优先级（建议「持械姿态只在上半身，下盘仍由步态独占」保持现状，直到有明确的脚法需求）。 |
| 低 | **低帧率下卡肉与震动可能整段错过** | 卡肉是 Core 的 45~70ms 时间冻结，镜头震动只在「有帧渲染且 `hitstop>0`」的上升沿触发。远程 / 低端机实测 7fps（143ms/帧）时，整段卡肉落在两帧之间：状态确实冻了，但画面没有定格、也没有震动 —— 玩家只看到伤害数字跳了一下。 | 记录 `hitstop` 的**事件时间戳**，表现层在下一帧补一次「短震动 + 一帧定格」，或对低帧率设备把卡肉时长按帧间隔下限夹取；先加一条低帧率模拟用例。 |
| 低 | **攻击中切体型仍有过渡** | `setBodyType` 重建整套骨架；本轮已补 `playerTrail.reset()` 清掉旧刃尖采样。新 rig 的 `stanceWeight / combatPoseW` 从 0 起手，攻击中切换会有一次 0.1~0.26s 的姿态淡入。中立状态切换已验证，攻击中切换还没有用例。 | 若需要无缝：在新 rig 首帧直接把 `combatPoseW` 置 1 并写入当前战斗姿态；补一条「active 段切体型」的用例。 |
| 低 | **视觉验收仍以截图为主** | clip-lab 覆盖了九段挥击的角度与截图，但**待机 / 移动持械姿态**没有自动化视觉基线；本轮靠 5 张截图人工确认。改一个 stance 数值，回归只能靠人眼。 | 给 `clip-lab` 加 `stance` 模式：五把武器 × 两种体型 × idle / walk，输出固定机位截图与刃身世界角度，和基线图做像素差 / 角度阈值。 |
| 低 | **角度单位混用** | 挥击数据用度（`bladePitchDeg`），`stance` 的手臂偏移用弧度，同一份 JSON 里两种单位。写配置的人很容易把 `0.15` 当度写成「几乎没动」。 | 统一在 JSON 层用度（`armR.pitchDeg`），加载时转弧度；或至少在 schema 里对字段名强制 `Deg` 后缀。 |

### 可优化方向（按投入产出排序）

1. **配置校验脚本**（0.5 天）：一次投入，之后每次改 JSON 都能在发布前挡住低级错误。
2. **动画层管线化 + 黄金姿态**（1~2 天）：只读重构，先把「层序」变成数据，再谈加层。
3. **卡肉去重 / 上限**（0.5 天）：补一条双目标命中用例，避免手感被长冻结拖闷。
4. **待机姿态视觉基线**（1 天）：扩展 clip-lab，把「五把武器站姿」纳入自动截图。
5. **包体拆分**（1 天，按需）：先测首屏，再决定是否拆 `three` 与调试模块。
6. **体型切换的战斗态收尾**（0.5 天）：清刀光、战斗权重归零，补用例。
