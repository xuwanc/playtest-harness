# 2026-11-09 · v9s.43 换向融合：前进切后退，腿不再抽一下

## 需求

> 前向移动切后向移动时 腿会抽一下，看看是怎么融合的，好修的话修下

## 现状（先量，别先猜）

`solveGait` 本身是 C∞ 的（只有 sin/cos + 一条 C¹ 的 `plantOffset`），乍看「数学没问题」。
所以第一步不是改曲线，是**把抽动量化**：逐帧记录 `hipL.rotation.x − hipR.rotation.x`，
前进 60 帧后把摇杆拉反，看单帧跳变。

| 场景 | 正常跨步单帧 | 换向那一帧 |
|---|---|---|
| 注视锁定、原地倒走 | 0.53 rad | **1.06 rad（61°）** |
| 不锁朝向、边转身边滑 | 0.53 rad | **1.26 rad（72°）** |
| 左右横移换向 | 0.53 rad | **1.21 rad** |

## 根因

```
footZ = dirF × wF × (stride × reachRatio) × off(φ)
dirF  = localForward >= 0 ? +1 : −1      ← 硬符号
```

速度穿过 0 时 `dirF` 一帧取反 = **整条腿位镜像**。而：

- `wF` 这时并不小（纯前后移动 `wF ≈ 1`）；
- 摆幅是按**步幅**定的（`stride/4`，与速度无关）—— 反向那一帧速度只有 0.43 m/s，
  摆幅仍是满的。

两个因素叠起来，那一帧脚等效瞬移 0.5m。侧轴 `dirR` 同理（侧摆 / 交叉步 / 侧倾 / 抬膝领先量
整套镜像）。

## 做法

符号不再硬翻，改成 −1..1 的**驱动量**按秒推进（`gait.ts`）：

```ts
dirF = slewDirSign(dirF, drive.localForward >= 0 ? 1 : -1, dt, gaitCfg.dirFlipSec); // 0.16s
const dirF = dirDrive(input.dirF ?? 硬符号);   // sign(x)·smoothstep(|x|)
```

- 匀速推进（`|Δ| = 2/sec`）：峰值单帧变化最小；smoothstep 形状会让峰值 ×1.5。
- `dirDrive` 在 `|x| = 1` 时逐位等于旧的 ±1 → **稳态零差异**，只有换向途中才衰减摆幅。
- 左右轴走同一条通道；抬膝「领先多弯」改写成 `0.1 × (1 + side·dirR)`（|dirR|=1 时与旧写法逐位相同）。
- 两个 rig 各接一份（`voxel-rig` 玩家/陪练、`dummy-rig` 普通假人），停步分支也传同一组符号。

结果：**换向那一帧不比正常走一步更激烈**（0.55 vs 0.53）。再压下去没意义 —— 自然动作成了主导项。

## 留下的坑 / 取舍

1. 换向途中腿会「收一下」（0.16s 摆幅收窄再长回来）。物理上合理（人换向要先落脚再蹬地），
   觉得太重调小 `dirFlipSec`，太生硬调大；拉 0 = 精确回到旧行为。
2. 状态活在骨架里（不进 Core / 快照），加第三个 rig 时要记得接 —— 漏接不崩，只是那个单位还抽。
3. `|dirF| < 1` 的 0.16s 内脚前伸距离按比例缩短，理论上支撑脚毫米级滑移；发生在速度近 0，实测不可见。
