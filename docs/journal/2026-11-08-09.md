> 本文件是「那天为什么这么改」，**不是**当前行为规范 —— 现状看 [`systems/dummies-fighters.md`](../systems/dummies-fighters.md)。
> 文中出现的旧文档名（`tech-map.md` / `animation-guidelines.md` / `sparring-fighters.md`）已在本次重构中拆分 / 改名，按 INDEX 找新位置。

需求原话：**「陪练加连击」**。

## 难点不是「怎么连」，是「别把上一条约束弄丢」

上一轮的约束是「攻击欲望放低」，靠三件事实现：站位带（1.7× 起手距离）、冷却期只走位、
首击错开。如果连击按「每刀间隔 0.2s、刀刀重置冷却」实现，起手频率会变成 3 倍 ——
站位带就白做了，观感回到「三个 AI 围着你猛砍」。

所以把**两个旋钮分开**：

- `attackInterval` 管「多久来一轮」（3.4s，不动）；
- `comboCount` 管「一轮几刀」（0 = 随武器的 `comboCount` = 3）。

冷却在**整轮起手时**记满，于是「一轮 3 刀 + 3.4s 间隔」与「一刀 + 3.4s 间隔」的起手频率完全一致，
只是每次压上来的内容变多了。测试里有一条专门守这个：12s 内仍是 3~4 轮。

## 实现：在原来的三段循环外面套一层计数

不加新状态机，只给 `DummyState` 三个字段：

```ts
attackComboIndex  // 1..N，本轮段号；0 = 不在连击中
attackComboLeft   // 本轮还剩几段
comboGap          // 段间缝隙剩余秒数
```

原状态机 `idle → windup → active → recovery → idle` 一行没改，只在两处加判断：
进入 idle 时有剩余段就设 `comboGap`（并**保留**段号），`updateOne` 起手时先看
「有剩余段 → 接续」再看「冷却好了 → 新起一轮」。

## 四个细节，每个都是踩过的

**1. 接续判定必须比 `reach` 宽 30%（`COMBO_CHASE`）**
第一击命中会把玩家推开（大剑 0.45m）。严格按 `reach` 判，第二段永远接不上 ——
恰好在「打中过」的对局里失效，而那是唯一需要连击感的时候。
放宽只用于「要不要接」，命中结算仍走 `hits.reach`。

**2. 缝隙期表现层要写 `settle`，不能写 `idle`**
0.16s 的 idle 会让 rig 把手放下再抬起，读成「两刀之间发了个呆」。
写成 `phase='settle'` + `progress=1` 就落进主角收招的同一路径（`attacking = phase !== 'idle'`），
姿势自然保持。段号在缝隙期也要保留，否则 `swing-pose` 会闪到别的段。

**3. 连击里不许退回 standoff**
`spar` 的站位逻辑是「打完退回 1.7× 距离外」。连击中间照做的话：玩家被第一击推开 0.45m →
陪练自己再退 → 必然打空。改成 `inComboRound(s)` 时只做「够不着就压上 / 贴太近让一点」。

**4. 大剑的 `knock` 档只给最后一段**
三段全 knock（0.42s 受击 × 3）会把玩家打得一拖一拖 —— 那不是连击，是卡住。
现在前两段 `light`、最后一段 `knock`，与主角「第三击才是重击」同构。

## 顺带修的一个隐患

`attackInterval` 被调到比一轮还短时（面板滑杆能调到 0.5s），一轮打完冷却已归零 →
下一帧立刻起手 → 无限连。补了个兜底：最后一段结束时若冷却已归零，补 `attackInterval × 0.4`。
兜底**只对持械陪练生效**，普通假人的行为逐帧不变。

## 行为等价性怎么证的

改完先跑全量单测，只有 `determinism` 快照变了。但「快照变了」不等于「只有新字段变了」，
所以另做了一次逐字节对比：用 `git worktree` 把 HEAD（v0.9.59）拉出来，两边跑同一段
600 步脚本化输入，dump `snapshot()` 后 diff。

结果：**12 处差异，全部是四个普通假人身上新增的三个字段**，其余（玩家位置 / 速度 / 战斗 /
朝向 / 全局计数 / 事件序列）逐字节一致。这才敢更新快照。
