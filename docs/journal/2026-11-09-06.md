# 2026-11-09 · v9s.45 慢放还抖，是「时间基准」错了

## 用户说了什么

> 「慢放还是会抖下，看看有没成熟解决方案，或者前/后相位独立 hip 补偿偏移限制计算，
> 发生前/后相位转换时，重新计算应该的相位」

## 先量：同一场景，只改播放倍率

沿用 v9s.44 的探针（跑步中把摇杆从 W 切到 A，身体跟着转 90°），只把
`debug.timeScale` 设成 1 和 0.25 各跑一遍：

| 0.25× 慢放，W → S 反 180° | 常速 1× | 慢放 |
|---|---|---|
| 转身期间 `hipYaw` | 全程 **0**（闸门全关） | 9.1° → 15.1°（单帧 6°），目标冲到 21° 再回落 |
| 单帧最大跳变 | 2.6° | **18.6°** |
| 整体摆幅 | 2.8° | 25.1° |
| 最深反向 | −2.8° | −19.7° |

同一个公式、同一段输入，只有播放倍率不同 —— 变量不是公式，是**时间**。

## 根因：闸门读的是「渲染帧」角速度

```ts
const turnRate = wrapAngle(c.bodyYaw - prevBodyYaw) / dt;   // dt = 渲染帧步长
const spinGate = turnSpinGate(turnRate);                    // 30°/s 起、100°/s 满
```

慢放 0.25× 时，身体转过同样角度要多花 4 倍真实时间，算出来的角速度只剩 1/4：
本来 400°/s 的转身被读成 100°/s，闸门从「全关」掉进「半开」。而 v9s.44 的限速率是

```ts
rate = free · (maxRate + free · FREE_RATE)   // FREE_RATE = 60 rad/s ≈ 3400°/s
```

`free = 0.5` 时还有 ~950°/s —— 半开等于放行，目标照样一帧蹿出去十几度。
**v9s.44 把「常速」这一条路径调好了，但把判据建在了随时间缩放漂移的量上。**

## 修法（五条，用户提的「前后相位独立限速」是第 4 条）

1. **角速度走游戏时间**：`ΔbodyYaw / Δworld.time`（`voxel-rig.update` 已经拿到
   `coreTime`）。常速下 `gameDt ≡ frameDt`，逐位相同；只有慢放 / 低帧才有区别。
2. **闸门变一阶状态** `slewGate`：升 0.06s、降 0.22s。瞬时值在转身尾部几帧里会从 1
   掉到 0；状态化之后「半开」只可能连续出现，不会一帧完成。
3. **限速率与放行程度线性挂钩**：`rate = maxRate · (1 - spin)`，删掉 `FREE_RATE`。
   spin=1 精确冻结，spin=0 就是 `maxRate` 本身（240°/s），中间没有近道。
4. **前 / 后相位各一档上限**：侧移族 240°/s、后退族 150°/s，用同一个 `hipFlipWeight`
   平滑混合（目标与限速共用一个权重，否则互相打架）。后退族那个 −48° 是
   「把摆动轴对齐行走轴」的**稳态解**，压低上限后快速扫过 θ∈100°..132° 就来不及
   把它拖出来再拖回去。
5. **速度 < 0.5 m/s 按比例淡出目标**。`latRatio` 是**方向比值**：贴着墙被夹住时
   v 只剩 1e-5、方向一帧能翻 90°（实测把下盘拧到 −22°）。速度趋零时方向没有意义。

顺手把 `hipYaw` 的指数平滑也换成游戏时间 —— 否则慢放下 83ms 的时间常数会被摊成 330ms。

| 0.25× 慢放，W→S | 修复前 | 修复后 |
|---|---|---|
| 单帧最大跳变 | 18.6° | 1.4° |
| 整体摆幅 | 25.1° | 4.5° |
| 最深反向 | −19.7° | −1.5° |

## 踩到的坑

1. **「成熟方案」不是换个公式，是换时间基准**。查了一圈（Overgrowth 式的解析摆腿、
   Unity 的 pelvis yaw + smoothdamp、UE 的 aim offset），共同点都是「状态按**模拟时间**
   积分，按**渲染帧**只做插值」。我们恰好反了：姿态解算按渲染帧积分（这没问题，
   本来就是表现层），但把「模拟量」（身体角速度）也算在渲染帧上。
2. **`speed > EPS` 拦不住方向噪声**。`EPS = 1e-6` 只防 NaN。被墙夹住时
   `velocity = (2e-4, 0)`，比值 `latRatio` 照样是满幅 ±1，下盘被这点噪声拧了 22°。
   要按**大小**淡出，不是按是否为零。
3. **不能只看一帧**。我第一版把「单帧 18.6°」当成「一帧内发生的事」，其实那是
   0.25× 下 4~5 个固定步累积的；真正要看的是「每步变化」。判据换成 `|Δ| / steps`
   之后才和常速可比（也因此 smoke 里那条判据得除以步数）。
4. **A/B 开关要能一次关干净**。`hipYawTrackRateDeg = 0` 现在同时关掉闸门、限速和
   后退档（`hipTrackRate` 返回 0 = 透传），才能精确复现旧行为做对照。
