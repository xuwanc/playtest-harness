- 独立种子 mulberry32，不推进 `world.rngState`（否则会连带改变假人游走）。
- 网格桶局部查询（4 格 = 2m），压弯 `bendRate=18/s`、恢复 `recoverRate=3.2/s`，
  固定步长指数积分、可快照。
- 割断**复用 `hits.ts`**：新增 `currentMeleeShape` / `inMeleeShape` / `inSlamShape`，
  不改 `playerHits` 主体。刀扫到哪一帧才割到哪片草（剑盾第 1 段 u=0.4 时正前方还没扫到）。
- 表现层：1 个 InstancedMesh（2 draw call 含碎片）、`instanceColor` 色阶、
  `transparent:false`、关阴影、`setFxOrder(FX_ORDER.grass=8)`、
  **脏标记 + `addUpdateRange` 局部上传**、碎片对象池。
- 演示页 `grass-demo.html` 自动循环：走进草丛压开 → 挥刀割断 → 弹性恢复 → 断茬 5.5s 再生；

## 踩过的坑（留给下一个 agent）

1. **golden hash 必然变**：`World` 加任何字段都会改 `snapshot(w)` 的哈希。
   这是契约变更，不是回归；`-u` 更新后要在 journal 记一笔。
2. **扫掠门不是摆设**：`hitSweep` 让剑盾第 1 段在 `u=0.4` 时刀还在 148°→68°，
   正前方目标 / 草都判不到。写「刀风」相关测试要把 `phaseTimer` 放到刀真的扫过正前方的帧
   （`u≈0.62`），别绕开扫掠门去硬改 `arcDeg`。
3. **玩家站草地中央时朝哪都能割到草**：方向性测试必须把角色放到草地**外侧**、
   身后保证无草，否则「背对不割」的断言会假阴性。
4. **再生测试要先退出攻击态**：`grassUpdate` 每帧都会调 `grassCut`，
   combat 仍是 `active` 的话刚长回来的草会被立刻再割一遍。
5. `groundHeightAt()` 按中心点取高，草跨台阶边缘会一半埋进去；生成时已避开台阶
   （`avoidMargin`），不是靠运行时修正。

## v9s.40 补记（空地上放一块，供真人测试）

用户要在主场景空地放一块草自己操控测试。做法：`GrassSceneSpec` 新增可选 `plots[]`
（`GrassPlotSpec`），常规草场遍历先跳过 plot 覆盖区（按 `clearMarginCells` 外扩留空），
随后 plot 内以 `density=1` 强制铺满，两者共用同一份 `emitPatch` 生成逻辑。

线上 `plots[0]` = 格 `[-4,4]×[0,6]`（世界 x −2~2m、z 0~3m，四周留空 1m）。
角色出生 `(0,0)`、面朝 `+z`，主场景已有全屏隐形摇杆 + 攻击按钮，往前一步即可压开 / 割断。

两个关键取舍：

1. **常规遍历在跳过前仍消耗同一次 `rnd()`**，所以非 plot 区域的既有草分布逐字节不变，
   不牵动任何既有手感用例；plot 生成放在常规遍历之后，也不污染其随机序列。
2. **格网对齐**：plot 起点取偶数，与 `spec.minCellX/Z` 同奇偶，否则 patch 格网会错位。

测试新增 2 例（强制铺满 12 patch / 四周留空 / 走过去压开 + 挥刀割断），全量 896 例全绿。
另有一处 `-0` 坑：plot 的 `cellZ` 小于 `spec.minCellZ` 时 `(差 % 2)` 得到 `-0`，
`toBe(0)` 用 `Object.is` 会失败，断言改为 `Math.abs(... % 2)`。

演示页同步做了手机竖屏适配：相机按注视点后拉补回水平 FOV、面板改上下分区、
补上 `#controls` 缺失的 `position: absolute`（原有 bug，按钮曾跑到页面顶部）。
静态产物已发布为公网预览；**本轮改动尚未同步到线上**，等用户确认后再覆盖。

## v9s.41 补记（GPU 风吹麦浪）

用户问「草用的什么技术，能不能加风吹麦浪」。技术复盘：Core 纯 TS 确定性状态 +
单个 InstancedMesh（2 draw call）+ 脏标记局部上传；风是**全局持续动画**，
若按老办法在 CPU 逐帧重算 1578 个矩阵，会一直吃满上传带宽（正是 `grass.md` 第 8 节
点名的风险）。所以兑现文档里预留的 Phase 2：把摆动放进 vertex shader。

做法：

1. **公式唯一来源在 Core**：`windPhase()` / `windShaderParams()` / `windSample()` /
   `windAdvance()`；`GrassState.wind = {time, gust}` 进快照、`grassReset` 归零。
   双正弦行波 `sin(k·p − ω·t)`，`p` = 位置在风向上的投影 → 沿风向依次错相、
   垂直风向同相，天然形成一条条推进的浪带。
2. **表现层只做搬运**：两个静态 `InstancedBufferAttribute`（`aWindPhase` / `aWindData`）
   创建时上传一次；每帧只改 8 个 uniform。`onBeforeCompile` 替换
   `<common>` / `<begin_vertex>` / `<color_fragment>`，`customProgramCacheKey` 隔离缓存。
3. **关键细节**：世界风向用 `instanceMatrix` 列向量投影重构到实例局部轴，
   草被压弯后仍沿同一世界风向倒；`h²` 高度加权让根钉住；
   `alive = 当前段高/设计段高` 让断茬自动减弱摆幅、隐藏的上段自动不摆（零额外上传）；
   fragment 乘明暗系数形成色带。
4. **抖动由已有 `blade.yaw` 派生**，不新增 `rnd()`，草的分布逐字节不变。
   初版 `jitter=0.9` 把浪带打散成「各自乱倒」，调到 0.16 才出现整齐的浪。

演示页加「风：开」按钮 / `W` 键 / `?wind=0` / `?view=3` 迎风低机位、HUD 显示阵风系数。
浏览器 A/B 实测：无风草直立、颜色均匀；有风整片朝同一方向倒伏并出现斜向明暗带，
零 shader 报错。测试新增 7 例（含「时间推进 Δ ≡ 空间回退 speed·Δ」的行波精确断言），
全量 903 例全绿，golden hash 因 `World.grass.wind` 更新为 `77dcd328…`。

  用户可直接确认线上换版了。
