# 2026-11-09 · v9s.42 手感面板：相位曲线 + 踩地分色

## 需求

> 在手感页面类似 sin 曲线那样显示相位，如果可以相位踩地用不同颜色标识出来

## 现状

手感面板（V 键 / 顶部「手感」胶囊）原本只有两块：位移速度折线 + 每帧 Δv 柱，外加收进来的
方向罗盘。相位（`gaitPhase`）在面板上是**看不见的** —— 上一轮刚做完「连击换腿」，
验收只能靠腿角读数和截图，调参时完全靠猜。

## 做法

面板加第三区（总高 92 → 128），画 `sin φ`：

| 相位 | 腿 | 颜色 |
|---|---|---|
| `sin φ > 0.16` | 左腿支撑相（踩地） | 琥珀 `#fbbf24` |
| `sin φ < −0.16` | 右腿踩地 | 紫 `#a78bfa` |
| `\|sin φ\| ≤ 0.16` | 换脚双支撑 | 灰 |
| 相位不推进 | 站定双踩 | 灰 |
| 离地 | 腾空 | 青 |

映射来自 `solveGait`：左腿取 φ、右腿取 φ+π，`lift = (1 − sin φ) / 2`，所以 `sin φ > 0`
就是左脚低（踩地）、右脚抬。

## 三个坑（都是真踩过的）

1. **不能读 Core 的 `gaitPhase`**。攻击时 Core 锁移速，`gaitPhase` 按实际位移推进 → 几乎冻住，
   面板上是一条平线，而腿明明在迈步。改成读 `voxel-rig` 暴露的
   `gaitDebug().phase`（本帧真正喂给 `solveGait` 的那个，攻击段由等效跨步驱动给）。
   顺手在 `gaitDebug()` 里补了这个字段 —— 之前只有腿角，没有相位。
2. **不能拿速度判「在不在走」**。同理：攻击时 `velocity` / 位移速度都是 0。
   唯一可靠判据是**相位自己有没有推进**（一帧 > 0.02 rad）。
   第一版就是拿 `Math.max(speed, drive)` 判的，结果整段攻击全显示「双踩」，白做。
3. **低帧率要插值补点**。软件渲染 ~10fps，6 秒窗口只有几十个点，直接连折线把正弦画成锯齿。
   相位帧间连续单调，按 2px 一个点补，形状才对，颜色切换点也更准。

## 结果

- `motion-debug.ts`：`Stance` / `stanceOf()` / `wrapPhase()` / `unwrapNear()` 纯函数 +
  相位区绘制（背景色带 + 逐段分色描线 + 当前点）。
- `gaitDebug()` 新增 `phase`；`three-scene` 两处类型同步；`app.ts` 注入
  `phaseSource: () => view.gaitDebug().phase`。
- CSS：`#motiondbg-graph` 92 → 128px（必须与 `CSS_H` 一致，否则画布被拉伸）；
  `#motiondbg-read` 加 `white-space: pre-line`（读数现在两行）。
- 测试：`tests/v9s42-motion-phase.test.ts` 5 例（stance 四种态 / 归一 / 走路正负半周都出现 /
  攻击段相位推进且大于 Core）。
- smoke：+2 项（站定判双踩、走路左右交替 ≥ 3 次换脚），23/23。
