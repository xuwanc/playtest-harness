### v9s.27 · clip-lab：动作剪辑验证台

> 需求：「写一个专门用来你做 clip 看角度，截图，收集必要数据验证的工具或环境？」

上一轮做双持旋身时踩了一个坑：截图里剑看着是竖的、数据说仰角 5°，最后靠临时脚本
读世界坐标才确认是斜俯视投影的错觉。这种「眼睛和数据吵架」的事每改一次动作就要
重来一遍，所以把它固化成工具。

**它不是编辑器**（v9s.25 的判断没变：数据仍在 `game.json`，不拖关键帧），
只回答「改完以后事实是什么」。

#### 1. 三条命令

| 命令 | 做什么 | 产物 |
|---|---|---|
| `check` | 9 段全跑，逐段判定 | `report.md`（结论表 + 失败原因）+ 关键帧 |
| `scan` | 单段 0→1 逐帧采样 | 扫角 / 仰角 / 带转 / spin |
| `shot` | 指定进度定格 | 带标注的 PNG |

#### 2. 定格不是另算一套姿态

`__harness.clipLab.preview()` 改的是 `world.combat` 的 `weapon / comboIndex /
attackProgress`，然后跑**真实** `view.render()`。手臂链、挂点反解、刀光都走真机
链路，读数和游戏里看到的是同一个东西。

配套两个必要机制：

- **锁画面**：preview 之后主循环下一帧会把姿态刷回待机，`clipHold` 让 `render` 跳过；
- **给足收敛帧**：腕部滞后是指数平滑，从 t=0 直接跳到 t=0.5 曾测到 40° 偏差，
  工具用 `warm=45` 收敛。

#### 3. 截图必须能自证

- 相机固定 18° 低俯角（游戏默认 50° 斜俯视会把水平剑投成斜线）；
- 右手刃身画红线、左手画绿线，端点用真实世界坐标投影；
- 每条纹旁标 `pitch / yaw`；角色前方画蓝色虚线 `facing`；
- 左上 HUD 给 `t / strike / rootYaw / spin / swingYaw`。

「扫到身后」不再靠感觉，看图就能指出剑尖在朝向箭头哪一侧。

#### 4. 第一次跑就抓到一个真问题

全量 `check` 出来：双持第三击 `spin = 360°`、扫角 331°，**但 R/L 两条刃身的 yaw
几乎重合**（-34° 与 -23°，差 10.5°）。这一击只有「原地转一圈」，两把剑并没有
向两侧展开。

用工具做参数扫描（热改 `ds.spin` 关键帧后逐组读数）：

| 改动 | R 刃身 yaw 变化 |
|---|---|
| `armYaw` −1.4 → 0 | −9° → −34°（25°） |
| `armRoll` −1.6 → 0 | −9° → −35°（26°） |
| 两者 > 0 | 不再变化（被夹住） |

结论：**手臂 `yaw/roll` 只能让剑偏 25°，做不出「向两侧展开」**。真展开需要新增
`bladeYaw`（刃身世界水平朝向）语义、由 rig 反解挂点，而不是继续拧手臂。
这轮记为待办，不半成品上线。

#### 5. 边界

- 只测稳态姿态：preview 固定进度反复渲染，腕部会收敛；真机连击里腕部是滞后值。
- 不参与命中：`hits.arcDeg` 仍在 Core，表现层扫 240° ≠ 判定扫 240°。
- 段间过渡不采样：`segBlend` 属于连击节奏，不在单段剪辑范围内。

#### 6. 验证

- `python3 tools/clip-lab/clip_lab.py selftest` → **9/9**（unwrap / 判定 / 规则覆盖）
- `check` → **9 段全部 PASS**，无 pageerror / 4xx
- 用法与实现要点见 `tools/clip-lab/README.md`

### v9s.29 · 刀不是手臂的延长线：刃口朝向、起手融合、命中卡肉

> 反馈：「双刀攻击的时候刀不要和小臂完全平行太直了，稍微有点角度，现在刀都是以刀侧面在扫，
> 连击开始和结束都没和待机对齐，且没有融合直接跳帧的」＋「可以参考成熟方案，加上打到人的卡肉处理」

三件事分别对应**几何、时间轴、打击反馈**，都落在不同的层，所以分开做。

#### 1. 「以刀身侧面在扫」是几何问题

模型约定刀身「薄在 X、宽在 Z」，挂点把刀身放平之后，宽面法线正好指向挥击方向 ——
横扫时就是拿侧面拍过去。解法不是继续拧手臂，而是**绕刀身长轴滚转**：

```
mount（俯仰 + 外撇）
  └ grip（rotation.y = bladeTwist，绕刀身长轴）
      └ 武器模型
```

分成两个节点是因为滚转**不能影响刀尖指向**：写在挂点上会被挂点俯仰 / 外撇卷进去
（实测让横扫段仰角多塌 4°），写在 grip 上则只转刃口。

新增语义通道：

| 通道 | 含义 | 取值参考 |
|---|---|---|
| `bladeTwist` | 主手刃面滚转（绕刀身长轴） | 右→左扫 −1.55、左→右扫 +1.55 |
| `bladeTwistOff` | 副手刃面滚转 | 双持默认跟主手同向，`ds.spin` 镜像 ±1.35 |
| `bladeYaw` | 刃身相对小臂的水平外撇 | 默认 0，靠 `swordCantDeg=10°` 常量给 |

怎么验收「刃口真的在切」：读刃尖速度与宽面法线的点积。

- 法线 ⟂ 速度 → 刃口迎着运动方向 = 在切（|cos| → 0）
- 法线 ∥ 速度 → 宽面正对运动方向 = 在拍（|cos| → 1）

`tests/v9s29-blade-edge.test.ts` 用这条判据做 A/B：把 `bladeTwist` 清零，中位 |cos|
从 0.2 涨到 0.6+，证明这个通道确实在起作用，而不是「改了个看不见的数」。

#### 2. 「刀和小臂完全平行」靠握刀外撇

刀身仰角是**世界语义**（0 = 水平），挥击时手臂也几乎水平，两者共线 → 看起来像手臂加长。
给挂点加 10° 外撇（`view.weaponMount.swordCantDeg`），刀尖在水平面里向体侧张开，
就成「握着刀」而不是「手臂延伸」。

大剑是 `greatswordCantDeg = 0`：双手握持的几何本来就紧（两肩 0.6m、单臂 0.42m），
再拧 10° 会把副手甩出臂展（实测到柄轴 0.19 → 0.23m）。

#### 3. 起手 / 收招的融合：每帧记下「不打这一击会是什么姿态」

旧版上半身是硬切：起手那一帧整体换成起手姿态、收招那一帧直接跳回待机。
现在每次 `update()` 在写战斗姿态**之前**快照一份骨架（躯干 / 骨盆 / 双臂 / 整体转体），
写完再按权重混回去：

```
w: 0 → 1（poseIn 0.1s）   起手
w: 1 → 0（poseOut 0.16s）  收招
```

两个配套细节，缺一个就白做：

- **收招淡出期间不能清状态**：`applyCombatPose` 的 idle 分支要等 `combatPoseW` 归零才清，
  否则最后一帧直接跳回待机，淡出没有「来源」；
- **腿不参与**：腿的进出仍由 `attackBlend` 负责，它还要和跨步相位对齐。

实测（`tests/v9s29-pose-blend.test.ts`，与 `poseIn/poseOut = 0` 的硬切做 A/B）：
过渡那一帧的上臂俯仰跳变压到硬切的 1/2 以下。

#### 4. 卡肉：为什么必须进 Core

历史上 `hitstop` 是纯表现层：数 `hitCount`，涨了就跳过 `voxel.update()` 冻 70ms。
问题是 **Core 还在走** —— 前冲位移继续积分，冻结结束那一帧身体会补滑一段；
而且每次命中都冻这么长，和武器重量、受击档位无关。

现在改成 Core 的 `combat.hitstop`（秒）：

| 环节 | 行为 |
|---|---|
| 命中结算 `applyHit` | 按 `hits.hitstop.{light,heavy,knock}` 取**最大值**写入（同帧多目标不叠加） |
| `advancePhase` | `hitstop > 0` 时整段冻结：不推进阶段 / 不推进 `attackProgress` / 不看连击窗口 |
| `combatUpdate` | 冻结期间把前冲 `impulse` 与水平速度清零（否则画面定格时脚在飘，实测 0.85mm/帧） |
| `linksUpdate` | 派生招计时一起暂停 —— 否则「冲撞打中后少冲一段」（1.75m 只剩 1.48m） |
| 计时扣减 | 放在 `combatUpdate` **末尾**：本帧所有模块都读到「还在冻结」，多扣会少冻一帧 |

默认时长参考成熟做法（60fps 下轻击 2~4 帧、重击 5~7 帧、击飞 7~9 帧）：
`light 0.045 / heavy 0.07 / knock 0.10`。

表现层只读这份计时，做两件事：骨架定格 + 命中镜头震动（`cameraRig.addShake`，
大剑 0.85、其余 0.5，位移式不转朝向）。「停」和「震」同帧出现才有重量。

#### 5. 验证

- `tests/v9s29-blade-edge.test.ts`（3 例）：通道数据形状 / 命中帧 |cos| 中位 < 0.45 / 清零对照
- `tests/v9s29-pose-blend.test.ts`（3 例）：起手与收招的单帧跳变小于硬切 / 淡出后精确回待机
- `tests/v9s29-hitstop.test.ts`（4 例）：命中触发 / 冻结期间进度与位置不动 / 分档 / 多目标不叠加
- `npx vitest run` → **64 文件 / 761 例**全通过；`npx tsc --noEmit`、`npm run verify:portable` 通过
- `python3 tools/clip-lab/clip_lab.py check` → **9 段全部 PASS**（扫角 130~349°、仰角 ≤ 12°）

### v9s.30 · 举顶仰角、整圈回正、体型切换

> 反馈：「修复四元数问题」「双持第三段回正会反转回去，刀光特效不够圆了（好修就修麻烦可以不管）」
> 「新增一个瘦高体型的角色给我切换，我来看看动画系统适配效果」

#### 1. 举顶：不是四元数，是「外张把仰角上限吃掉了」

上一轮把问题归给欧拉反解的精度，其实主因更简单：**挂点带着 ±16° 的静态 yaw**。
欧拉 XYZ 序下 `rz` 先作用，长轴被从 +Y 偏出去，仰角变成

```
仰角 = asin(cos(z) · cos(θ + chain))
```

`cos(z)` 就是天花板 —— z = 16° 时最高只能到 74°，数据要 92.8°，怎么调 x 都到不了。
手臂上举时肩还带 roll/yaw，链角按 x 相加也不准，两条误差叠在一起 = 78°。

修法不是换四元数重做整个求解（试过，会把手臂 roll 一起抹平，大剑副手当场脱柄到
0.37m），而是**让外张跟着仰角收缩**：

```
zEff = sign(z) · min(|z|, 90° − |e|)
```

- 横扫（e ≈ 0）：`90° − |e|` 接近 90°，外张用满 → 与旧版逐帧一致
- 举顶（e = 92.8°）：上限收到 0，外张归零 → 单轴俯仰可以覆盖全程

实测从 78° 提到 87°（`atan2(dy, hz)` 口径），与数据 92.8° 的差只剩「超过 90° 由
`asin` 镜像」这一层，视觉上是往正上方偏后仰，读得对。

#### 2. 整圈回正：2π 与 0 等价，但线性插值不知道

`blendCombatPose` 原本对 `root.rotation.y` 做数值插值。双持第三击把 `spinYaw` 推到
2π，收招淡出时「待机姿态」的 rootY 是 0 ——

```
mix(0, 6.28, 0.5) = 3.14    // 半圈，画面上就是倒着转回去
```

整圈角必须走最短弧：`b.rootY + wrapAngle(cur − b.rootY) · k`。2π 与 0 的差是 0，
淡出对朝向零影响；只有「半圈被打断」才真的回正（那本来就该回）。

#### 3. 刀光不再是八边形

`weaponTrail` 只保留 8 个采样点，转一圈 30 帧、每 4 帧一个点 —— 画出来是八边形。
改成 30 点 / 最小步长 1.5cm，一圈有二十多个点，弧线连续。

#### 4. 体型：`view.bodyTypes` + `setBodyType`

体型不是换模型，而是**换一套骨架尺寸**：腿长决定髋高与跨步、臂长决定握持与 IK 臂展、
躯干宽决定肩距。同一套动画数据在不同尺寸下会暴露不同的适配问题，所以做成可切换的观测手段。

| 预设 | 总高 | 腿 / 躯干 / 头 | 臂长 | 宽 / 粗 |
|---|---|---|---|---|
| `standard` | 1.20 | 0.40 / 0.40 / 0.40 | 0.42 | 0.46 / 0.14 |
| `tall` | 1.32 | 0.68 / 0.28 / 0.36 | 0.50 | 0.34 / 0.10 |

切换时做三件事：重建 rig（`dispose` 旧几何）、脚底重新对齐（`-ROLL_PIVOT_Y`）、
把 `height / radius` 同步进 Core 配置（否则碰撞与眼睛高度还是旧体型的值）。
`headPivot` 原本直接读 `orientation.headPivotHeight`（按标准体型写的 0.4），
瘦高躯干只有 0.28，改成 `min(ori.headPivotHeight, bodyHeight)` 后头才接在脖子上。

验收：`B` 键循环、顶部提示当前体型；`__harness.setBodyType('tall') / bodyTypes()` 可脚本调用。
`tests/v9s30-body-type.test.ts` 校验「总高 = 腿 + 躯干 + 头」与「髋高 / 头枢轴 / 头顶」三处对齐。
