### v9s.22 · 夸张化：形变、副手握持、刀光、定格

> 反馈：动画不够夸张，想用「隐藏骨骼 + 可伸长变粗」解决「手不够长打起来僵」和
> 「大剑双手拿不到」。

#### 先回答方案问题：无限伸缩解决不了这两个问题

「挂一根隐藏骨骼、让它能伸长变粗」在技术上完全可行（THREE 里就是给骨骼段做非均匀缩放），
但**它解决的不是这两个痛点**：

| 诉求 | 无限伸缩能不能解决 | 为什么 |
|---|---|---|
| 打起来僵 / 手不够长 | 只能部分 | 伸缩是「事后补偿」，视觉上会变成橡皮人；玩家读到的是「手臂在拉长」，不是「打到更远」 |
| 大剑双手拿不到 | **不能** | 瓶颈不是长度，是**几何**：剑柄根本不在左手能够到的位置（详见下） |

实测数据（改之前）：

```
左肩 → 剑柄副握点     0.847 m
单臂总长（两段之和）   0.360 m
→ 需要把胳膊拉长 2.35 倍才能碰到，这不是「夸张」，是「面条」
```

所以这一轮拆成四件事，各自解决一个问题：

| 通道 | 解决什么 | 做法 |
|---|---|---|
| 副手握持 IK | 大剑双手拿不到 | 反解左手角度去够柄上一点，而不是给左臂写死角度 |
| squash & stretch | 动作不夸张 / 手显得短 | 挥出瞬间沿骨长拉长 + 体积守恒收细，命中压扁 |
| 挥击刀光 | 打击感 | 刃尖轨迹 ribbon，按年龄淡出 |
| 命中定格 | 冲击力 | 命中帧冻结姿态 70 ms，Core 照常推进 |

#### 一、副手握持：从「写死角度」改成「够一个点」

旧版大剑的双手只是给左臂写了两个常数：

```ts
armL.root.rotation.x = both + 0.06;
armL.root.rotation.z = 0.38;
```

左手和剑柄之间**没有任何几何关系**，所以无论怎么调都在剑外面。现在改成两骨 IK：

1. 取柄上副握点的**世界坐标**（`mountR.localToWorld(0, gripY, 0)`）；
2. 转进上半身局部空间，减去左肩的局部位置 → 相对肩的目标向量；
3. `solveTwoBoneIK(target, seg, seg, -1)` 反解肩 / 肘角度（复用足部 IK 的同一套数学）。

**握点滑动**：举剑过顶时主手离身体很远，固定副握点会超出副手臂展。此时沿柄轴把目标
按 0.45 的步长向主手收，直到可达 —— 左手虽然握得偏上，但**始终在柄上**，
而不是悬在空气里。这是「够不到」和「拉面条」之间的折中。

**前提：主手也必须往中线收。** 两条关键修正：

```ts
// ① 武器本体向中线内收 9 cm（双手武器专属）
mountR.position.x = -twoHandInsetX;

// ② 右臂绕 Y 摆 —— 手臂已经前举时，绕 Z 转几乎无效（向量本来就沿 Z）
const armFwd = -Math.sin(armR.root.rotation.x);
armR.root.rotation.y = -0.72 * Math.tanh(armFwd * 4);
```

第 ② 条的符号随「手在身前 / 身后」翻转（tanh 平滑过零），否则挥到后半段手会被甩到
身体另一侧，副手又够不到了。

结果：

```
左肩 → 副握点    0.847 → 0.286（举剑蓄势时）
左手 → 柄轴距离  最差 0.134 m（手掌本身 0.15 宽，视觉上就是握住了）
```

#### 二、squash & stretch：只做「短促、带体积补偿」的形变

`limb-stretch.ts` 是纯函数（零 THREE），输出每段骨骼的「沿骨长缩放」与「粗细缩放」：

```
windup   swing = -1  → arm = 0.88（压短变粗，像屈臂蓄力）
active   上升        → 按 easeOut 拉向 1.42
拐点     swing 掉头  → impact 脉冲把整体压到 0.8，再回弹
recovery swing → 0   → 回到 1
```

三条约束让形变不廉价：

1. **幅度小、时间短**：只有挥出的那 4~6 帧非零，其余时间恒为 1；
2. **体积补偿**：拉长时垂直方向按 `along^-0.5` 收细（泊松效应），压扁时自动变粗
   —— 读起来是橡皮，不是面条；
3. **限速**：输出经指数平滑，姿态跳变时不会「啪」地弹一下。

落到骨骼上有两个维护点（`applyStretchPose`）：**子关节的 `position` 必须同步放大**，
否则前臂 / 手掌留在原处，手臂从肘部断开。骨长改成链式推导后，武器挂点也跟着手自然前移。

#### 三、挥击刀光：打击感来自轨迹，不是姿势

`weapon-trail.ts`：每帧取武器的「刃根 / 刃尖」世界坐标，按最小位移采样，
用三角形带连成带状，颜色按年龄衰减（加色混合下「变暗」＝「淡出」）。

两个经验点：

- **刃根只取靠近刀尖的一小段**（大剑取 0.64→0.85 m）。整条刀身都参与的话，
  拖尾会变成一根和刀一样长的白棍（实测 0.69 m 宽），读不出「划过的轨迹」；
- **门槛看位移不看速度**：暂停 / 单步调试时同一帧会被渲染多次，速度算出来是 0，
  用位移判断才稳定；速度只用于亮度。

顺带把旧的「斩击弧」从轻击移除了 —— 那是一个固定在身前的白色圆环，和真实刀轨无关，
反而会盖住贴刀身的拖尾。只有 `comboIndex >= 3` 的重击保留弧光。

#### 四、命中定格

```ts
if (view.hitstop.enabled && w.hitCount > prevHitCount) freezeLeft = view.hitstop.duration;
if (frozen) { /* 不刷新骨架，只让拖尾自然衰减 */ }
```

Core 照常推进（位置、判定、冷却都在走），表现层只是「不把新姿态刷到骨架上」，
画面在命中瞬间静止 4 帧。这是格斗游戏里性价比最高的一招，完全不用改物理。

#### 顺带：手臂基准长度 0.36 → 0.42

0.36 比肩宽（0.6）还短，是这个体型「打起来僵」的物理根源。0.42 接近真实比例下沿
（身高 1.2 → 臂长 0.42），既缓解了「够不到」，也没有把手做得像长臂猿。

### v9s.23 · 挥击的身体与肩部：大剑三段各一条方向

> 反馈：「这个角色虽然有肩膀骨骼，可以适当调整上臂的位置让其看起来像肩膀在动；
> 攻击时可以给身体更多幅度；双手剑三段可 1. 从右往左砍 2. 接左边 pose 往右砍
> 3. 举过头顶往下砍」。

#### 诊断：旧版「不够夸张」的根因不是幅度，是通道太少

把一段挥击拆开看，旧版只写了三样东西：

| 部位 | 旧版 | 结果 |
|---|---|---|
| 手臂 | `armR.root.rotation.x` 一条曲线 | 只有俯仰，没有横向 |
| 躯干 | `upper.rotation.y = -0.18 * swing` | 最多 10° 扭转 |
| 骨盆 / 重心 | 只有 `applyStep` 的前跨 | 前后有、左右没有 |
| 肩部 | `shoulder.position` 是常量 | 手臂抬到头顶，肩点钉在躯干侧面 |
| 三段差异 | 三段共用 `both = -1.6*back + 1.25*forth` | 1、2、3 段一模一样 |

而且 `shoulder.position` 是 `makeArm()` 里一次算好的常量，之后**从不更新** ——
所以哪怕手臂举到头顶，肩关节也像装在固定支架上，这是「肩膀不动」的直接原因。

#### 做法：一段挥击 = 两帧关键姿态

新建 `presentation/swing-pose.ts`，把每段攻击抽象成一对关键帧（起手 / 命中），
逐项插值成 9 个通道：

| 通道 | 语义 | 作用 |
|---|---|---|
| `yaw` | 上身相对骨盆扭转（+ = 向右） | 横扫的主要来源 |
| `pitch` | 上身前后倾（+ = 前压） | 下劈时压上去 |
| `roll` | 上身侧倾 | 起手重心压向一侧 |
| `pelvisZ / pelvisX` | 骨盆前后 / 左右 | 全身重心跟着走 |
| `armR` | 主手三轴 + 肘 | 手臂轨迹 |
| `armL` | 副手（大剑作 IK 初值） | 双手握持 |
| `mountPitch` | 挂点俯仰覆盖（仅举顶段） | 见下文「剑穿头」 |

三段的关键帧：

```ts
// 段 1：右 → 左（躯干 +0.85 → −0.95，跨度 103°）
wind: { yaw: 0.85, pitch: -0.12, roll: -0.14, pz: -0.06, px: +0.045, ap: -1.20, el: -0.48 }
hit:  { yaw: -0.95, pitch: 0.14, roll: 0.17, pz: 0.10, px: -0.05, ap: -1.46, el: -0.14 }

// 段 2：左 → 右（承接段 1 左侧收势）
wind: { yaw: -0.75, ... }
hit:  { yaw: 0.92, ... }

// 段 3：举顶 → 下劈（手臂 −1.90 → +0.05，躯干后仰 −0.32 → 前压 +0.55）
wind: { yaw: 0.12, pitch: -0.32, ap: -1.90, el: -0.55 }
hit:  { yaw: 0.00, pitch: 0.55, ap: 0.05, el: -0.10 }
```

**横扫由躯干扭转完成，不由手臂横摆。** 双手大剑的两手之间距离必须稳定，
手臂一旦横摆，副手立刻够不到柄；而躯干转 100° 时，肩、手、剑整体一起扫过去，
既够得到柄，视觉上又是「腰胯带剑」。

#### 肩部：用「手臂当前俯仰」反推三个位移

`applyShoulderPose()` 每帧无条件写 `armL/armR.root.position`：

```ts
lift = shoulderLift × clamp((-pitch - 0.5) / 1.45, 0, 1)   // 抬得越高，肩越耸
push = shoulderPush × clamp((-pitch - 0.2) / 1.9, 0, 1)    // 抬到身前，肩前送
in   = 双手武器攻击时向中线收（让副手够得到柄）
```

上限 5.5cm / 4.5cm / 3.2cm：体素躯干只有 0.4m 高，再大就穿帮。
走路摆臂（`gait.armL/armR` 本来就写在 `rotation.x` 上）也会带一点肩部浮动，
所以「肩膀在动」不只出现在攻击里。

#### 段间过渡：`segBlend`

连击换段时 `attackProgress` 从 1 直接跳回 0，段 2 起手在左侧、段 3 起手在头顶，
不插值就是「啪」地换姿势。做法是**只在 comboIndex 变化那一帧冻结起点姿态**，
用 `segBlend`（默认 0.1s）+ smoothstep 过渡过去：

```ts
if (combat.comboIndex !== swingSeg) { swingFrom = swingPose; swingFade = 0; }
const pose = swingFrom && swingFade < 1
  ? blendSwingPose(swingFrom, target, segEase(swingFade))
  : target;
```

段内的挥出速度完全不受影响 —— 刻意不做逐帧平滑，否则会吃掉冲击力。
实测换段那一帧的 `upper.rotation.y` 单帧跳变 < 0.35 rad（旧版是整段姿态差，约 1.7 rad）。

#### 顺带修掉的三处硬伤

**① 举剑过顶时，那截下段柄从头顶穿出来。**

武器挂点是固定 58°（相对前臂），这个值只在「手臂大致前举」时成立；手臂绕 X 转到
−169° 后，58° 被翻成「剑尖朝后下方」—— 实测刃尖在 `(0.58, 0.36, −0.61)`，
即插在身后腰侧，同时 0.46m 的下段柄正好从头顶穿出。

修法是给「举顶段」单独一个挂点俯仰通道 `mountPitch`（2.45 → 1.50 rad），
让剑与手臂大致同向：举顶时剑尖朝前上、劈下时朝前下。

```
改前 段3 起手 刃尖 (0.58, 0.36, −0.61)   ← 身后、腰高
改后 段3 起手 刃尖 (0.20, 1.90, −0.21)   ← 头顶上方 1.1m
改后 段3 命中 刃尖 (0.06, −0.06, 0.93)   ← 身前、贴地
```

同时挂点的**内收量随手臂抬高衰减**：`twoHandInsetX` 是为让副手够得到柄，
但它把剑柄从 `x = 0.30`（头右侧外）拉到 `x = 0.15`（头内），举顶时必然穿模。
举高时内收归零，副手靠握点滑动 + 臂长拉伸去够，够不到时允许短暂半松。

**② 命中帧其实只挥到 16%。**

`swingCurve` 的断点是 0.3 / 0.62，但大剑的 active 段结束在 `progress ≈ 0.486`：

```
swing(0.486) = -1 + (0.486 - 0.3) / 0.32 × 2 = 0.16
```

也就是说判定已经结算、剑还在半路，真正的「挥到位」发生在既无位移也无判定的
recovery 段。断点改成 0.22 / 0.50 后，active 末 swing ≈ 0.9 —— 命中那一帧
手臂、躯干、刀光基本同时到位。

**③ 旧斩击弧和真实刀光重复。**

v6a 的斩击弧是固定朝向的半圆、半径 1.3m、不透明度 0.7，v9s.22 加了跟剑走的
刃尖拖尾之后，两者叠在一起就是「凭空出现一个半圆 + 一条划痕」，近距镜头下直接
把角色挡住。默认关闭（`projectiles.slashEnabled = false`），调试面板保留开关做 A/B。

拖尾本身也收了一轮：只在实际挥出的 active 段采样（`windup` 的慢速位移会先拉出
一条长带）、`maxSamples 22 → 6`、`life 0.2 → 0.06`、按年龄沿刃根方向收窄、
衰减从 `t²` 改 `t³` —— 6 个点里只有最近 2~3 帧可见，才像一条短促的刀光而不是拱门。
