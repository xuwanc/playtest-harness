# 2026-11-08 · src/ 大文件职责梳理（两拆 + 五不拆）

> 本文件是「那天为什么这么改」，**不是**当前行为规范 —— 现状请看 `docs/INDEX.md` 里对应的系统文档。
> 文中出现的旧文档名（`tech-map.md` / `animation-guidelines.md` / `sparring-fighters.md`）已在本次重构中拆分 / 改名，按 INDEX 找新位置。

## 触发

`src/` 下 7 个文件超过 600 行，最大 2830 行。要的不是「都拆开」，而是先回答每个文件**有几个职责**：
只有并列职责才拆，同一条流水线的相邻阶段拆开只会变成「参数列表搬家」。

## 判据

1. **并列职责**（各自能被独立替换 / 独立测试）→ 拆。
2. **同一条流水线的阶段**（共享大量跨帧状态）→ 不拆，写清为什么不拆。
3. 拆之前先找**重复**：如果两处是复制粘贴，先合并再谈拆分，否则只是把复制品分到两个文件。

## 拆了两处

### 1. `voxel-rig.ts` 2830 → 2737（拆出 `rig-parts.ts` 124 行）

拆出的是 8 个**纯几何函数**（剑 / 大剑 / 盾 / 杖 / 弓 / 箭 / 方块 / 组）：
只依赖 `THREE` 与配色表，没有闭包状态，是「造模型」与「驱动模型」之间唯一干净的分界线。

剩下的 `createVoxelRig` 2474 行**不拆**：内部是一条固定流水线
（读 Core → 步态 → 攻击混合 → 受击分层 → IK → 平衡配重 → 写回骨骼），
相邻阶段共享 40+ 个跨帧状态（停步窗口 / 惯性脉冲 / 段间过渡起点 / 腕部滞后……）。
拆成函数要先把这些状态穿成 context，每帧多一层间接，收益只有「文件变短」。

### 2. `three-scene.ts` 1433 → 1283（拆出 `scene-burst-fx.ts` 271 行）

拆之前先发现**三份复制**：冲刺尘环（6 个池）、派生招光环（5 个）、击地尘环（4 个），
结构完全一样 —— 定长池 + `find(life <= 0)` + 每帧衰减 + 到期隐藏，只有峰值透明度、
缩放曲线（线性 / `t^1.8` / `t^1.3`）和几何不同。

合并成一个 `makePool(spec)`，三个池各给一份 `PoolSpec`；触发逻辑（读 `dash.id` /
`playerLink.id` / `combat.slamAttackId` 这三个**持久字段**）也一并搬进 `update()`。

> 为什么读持久字段而不是事件：`step` 每帧开头清空事件队列，低帧率一帧多步时只有最后一步的事件会留下。

剩下的 `createSceneView` 不拆：初始化与 `render()`（600 行）共用一个闭包，
贴地高度、特效锚点、相机、rig 是逐帧互相引用的，属同一条渲染管线。
