# 三连节奏从「同一动作点三下」变成三段三个性格（v9s.75）

> 2026-11-11。`animation.md` §3.1 自己点名了两轮的问题：三种武器、九段配比**完全一致**。
> 这批把它做掉，顺手发现两个隐藏依赖 —— 都比改数字本身麻烦。

## 1. 病：三段共用一组时长

`core.combat.weapons.<id>` 只有一组 `windup/active/recovery`，`startSwordCombo` 不论第几段
都拿这组。于是九段实测配比是 23/26/51、20/29/51、20/28/52 —— 读起来就是「同一个动作点三下」，
玩家感受不到「连段」这回事。

## 2. 做法：逐段时长，缺项回落

```jsonc
"comboTimings": [
  { "windup": 0.125, "active": 0.125, "recovery": 0.25 },   // 25/25/50 建立节奏
  { "windup": 0.09,  "active": 0.125, "recovery": 0.285 },  // 18/25/57 承接动量
  { "windup": 0.19,  "active": 0.11,  "recovery": 0.25 }    // 35/20/45 终结技
]
```

`comboTimings?.[index - 1]`，缺项回落统一值 —— 老配置与回滚路径零改动。

| 武器 | 段1 | 段2 | 段3 |
|---|---|---|---|
| 剑盾 | 0.50s | 0.50s | 0.55s |
| 双持 | 0.35s | 0.35s | 0.42s |
| 大剑 | 0.70s | 0.70s | 0.80s |

两条硬约束（都来自 `animation.md`）：`active` ≥ 5 帧（83ms，刀光才成形）、
`windup` ≤ 38%（再长 `swingCurve` 已经在挥，判定还停在蓄势）。

## 3. 三个坑

**① `clip:lab` 只读统一值 —— 配了也看不出来。** 改完跑 `combo`，报告里的节奏表
还是 23/26/51，一行都没变。因为工具直接 `wc.get("windup")`。改完工具（按段读、
表里加「段」列、再加一条「三段配比相同」的告警）才看得见。

**② 改时长必须重采 `hitSweep`。** 这条曲线是「刃尖相对角随 **active 进度 u**」，
而 active 在时间轴上的位置由 `windup / (w+a+r)` 决定。windup 从 23% 抬到 35%，
u=0 对应的剪辑时刻就往后挪 —— 整条曲线错开（实测剑盾 c1 在 u=0.4 偏 **34°**）。
后果不是「手感差一点」，而是 `v9s36-contact` 直接红：命中帧的刃尖已经越过目标方位
（大剑 c1 区间 `[3.6, 152]` 不含 0°）。修法是 `npm run sweep -- --write` 重采，
不是手调数字。

**③ 扫掠门把「同帧多目标」变成「分帧命中」。** `v9s29-hitstop` 的「多目标不叠加」
靠两个假人同帧命中。有了扫掠门，刀从左扫到右 —— 实测第 10 帧命中左边、第 14 帧命中右边，
前提就不成立了。这条测试要**显式摘掉 `hitSweep`** 再测卡肉聚合，否则它测的其实是门的粒度。

**④ 真机挥刀那条自检突然红，根因不在这批改动里。** 表现是连砍三次全部空刀，
诊断打印里 `phase` 恒为 `idle`、`pz` 每次涨 0.44m。两个独立问题叠在一起：

- `page.keyboard.up` 在软件渲染下偶发丢事件 → 前面用例按过的 `w/d` 留在 `keys` 里，
  角色一直朝旧方向走，越走离杆越远；
- 更致命的是 `j` 也残留。输入层 `onKeyDown` 开头有 `keys.has(k)` 去重，残留的 `j`
  把之后每次 keydown 都吞掉 —— 按十次也不会出一刀。

追下去发现是**产品缺陷**而不只是测试脏：`releaseAllInputs()`（窗口 blur / 切后台时的
兜底清理）只清 pointer、摇杆、按钮，**键盘是漏的**。真机上表现为「切走再切回来，
角色自己走、攻击键失灵，必须把那个键重按一遍才恢复」。修法是在 `releaseAllInputs`
里 `keys.clear()`（`src/adapters/input.ts`），自检侧改走真实路径 `dispatchEvent(new Event('blur'))`，
不再逐个补发 keyup。回归测试 `tests/v9s75-input-blur.test.ts` 3 例（摘掉修复后 2 红 1 绿）。

## 4. 契约变更

`comboTimings` 改变攻击时间轴的推进 → `tests/determinism.test.ts` 的 golden hash 变了
（`-u` 更新）。这是预期内的契约变更，不是漂移：同输入同帧数仍然逐字节一致。

## 5. 验收

| 项 | 结果 |
|---|---|
| `npm run clip:lab:check` | 九段全 PASS（扫角 / 仰角 / spin 与改前一致 —— 曲线按归一化进度走） |
| `npm run clip:lab -- combo` | 九段配比逐行 ✅；衔接跳变 7.5 / 39.4 / 11.9 / 84.3 / 26.1 / 23.0°（阈值 ≤130°） |
| `npx vitest run` | **130 文件 / 1321 例**（新增 `v9s75-combo-rhythm` 6 例、`v9s75-input-blur` 3 例） |
| `npm run smoke` | 77/77（修掉失焦不清键盘后，真机挥刀那条恢复稳定通过） |
| `python3 tools/sweep_sample.py --write --step 0.05` | 最大偏差 19.3°（active 位移导致，重采后正常） |

剑盾段 2 的刃身衔接跳变 84.3°（报告提示 >70°）：这是「连续承接」路线的固有代价，
段末满幅、段首按 `strike` 淡入，两者天然差 100° 量级。要压下去得改走共享锚点，
不是调时长能解决的（见 `animation.md` §1.1）。
