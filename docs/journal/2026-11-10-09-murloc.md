# v9s.63 · 鱼人：换造型不等于加骨架

## 决定：先问「运动方式也一样吗」

需求是「设计一个魔兽世界里的鱼人角色」。摆在面前两条路：

| | 做法 | 代价 |
|---|---|---|
| A | 照蜘蛛的样子新写一套 `murloc-rig.ts` | 步态 / IK / 挥击 / 受击 / 断肢 / 倒地物理**全部重写**，约 700 行 |
| B | 复用 `voxel-rig` 的双足骨架，只换几何 | 约 240 行造型代码，但走路姿势仍是人类 |

判据不是「工作量」，是**运动方式是否同构**。蜘蛛必须走 A：8 条腿、三角步态、
两骨闭式解，人类骨架装不下。鱼人是双足、髋膝踝肩肘腕、攻击时上半身前压 —— 和人类
完全同构。所以选 B，代价（走路像人）写进「已知限制」，不假装它不存在。

B 的路换来的东西比想象中多：**骨骼名一字未改 → 断肢（`SEVER_NODE` 按节点名查找）、
`boneAtWorld`（插箭按肢体挂）、IK、倒杆物理全部白拿**。实测对鱼人重击打 `hitU 0.9`
五刀砍死，`sever.part` 直接就是 `head`，一颗鱼头掉在地上。

## 造型：三次失败

第一版：**吻部做成伸出去的长条**（前凸 0.3HS）。侧视读作鳄鱼，不是鱼人。
原因是把「鱼」理解成了「长嘴」。

第二版：砍短吻部、加颅顶——**眼睛却埋进了颅骨内部**。眼窝中心 `z 0.14`，
而颅骨前表面在 `0.38`，从正面只能看到两条黄缝，读作「眉毛」。
这一版同时在头顶堆了 5 片小鳍，俯视是一串珠子。

第三版（定型）：**整个头就是脸**。一块方颅，横裂的嘴在正面下缘，两颗眼球凸在
正面**上方的前角**（`(±0.24, 0.66, 0.30)`，前缘凸出脸 4cm）。冠鳍与背鳍都改成
**一整块长板 + 亮色顶边**。

「整块板」是这一轮最重要的一条：

> 2.5D 俯视相机看到的是鳍的**顶面**，而它只有 `x` 那么宽（3~4cm）。
> 分片堆叠时每片的顶面高度不同，看到的就是一排高矮不一的方块 —— 珠子。
> 一整块板 + 一条亮顶边，才读作「一片鳍」。

同理，鳍必须比身体**亮**（`#4fa985` vs `#4f9c78`），顶边再亮一档（`#9ce0bc`）。
全用暗色时它和身体渐变糊成一片，现场读作「背上长了一排骨刺」。

## 单只假人血量：为什么不能改全局

鱼人要看得到断头，就得能被砍死。最省事的做法是把 `dummies.health` 从 0 改成 90 ——
但那会让**所有**普通假人变成可击杀单位，而它们是「测距离 / 测 AI」的测试桩，
被打死一批工位直接失效。

所以加的是 `DummySpawn.health`（单只覆盖），全局默认仍是 0。配置链一路透传：
`PlotDummyDef.health` → `PlotDummySpawn.health` → `DummySpawn.health` → `createDummyState(maxHp)`。

两个旧测试因此挂了，都是**硬编码了工位数量**的老假设：
`expect(fighters.map(s => s.id)).toEqual([7, 8, 9])` 和「所有无武器假人血量必须是 0」。
前者改成 `[count+1, count+2, count+3]`（要断言的是「紧跟其后且连续」），
后者改成「没声明 `health` 的才必须是 0」。**测试跟着契约走，不是反过来。**

## 顺手修掉一个 flaky

smoke 的「踱步是大步」在加完工位后稳定 FAIL（均速 0.94 / 0.77）。查下来不是行为退化：

- 判据 `sp > 0.15` 把**起步 / 收步**的过渡帧也算成「移动」，而同一只陪练的稳态步速
  是 1.5~1.9 —— 均值被 0.05/0.16 这种帧稀释到 0.8。
- 采样窗口 4s < 横移周期 5.2s。窗口一旦落在「门关着」的停顿段，`moveRatio` 直接 0.14。

改：阈值取「大步」的下限 0.6，窗口拉到 6.2s（覆盖一个完整周期），`moveRatio` 加下限
（5%，证明它确实在走，不是卡住）。**没有放宽 1.1 m/s 这条线** —— 那是这条用例的意义。

## 教训

1. **「加角色」先问运动方式是否同构**：同构就换几何，不同构才加骨架。
   新骨架的成本不在写，在**它要重新失去一遍已经调好的东西**（步态、IK、卡肉、断肢）。
2. **俯视游戏的造型要按「看到哪个面」设计**：鳍、发、鳍状物在 2.5D 下几乎只能看到顶面。
   按侧面三视图做出来的东西，进游戏可能是一条线。
3. **检验造型靠截图迭代，不靠想象**：三版之间有两次是「数值上更合理、画面上更差」。
4. **加一种出场方式要顺手检查「硬编码数量的测试」**：工位增减是常态。
