# 2026-11-10 · 可破坏物的「壳」/ 仙人掌第三版 / 残留分支清理（v9s.61）

两条反馈：① 可破坏物会有一个方盒子显示；② 仙人掌还是不好看，简单抓形就行。
第 ① 条查下来不是造型问题，是**碰撞盒被当成场景方块画了出来**。

## 一、那个方盒子是碰撞盒

现场描述是「可破坏物旁边有个红棕色大方块」。先按造型查（`buildStanding` 的四个分支），
没有兜底盒；再按场景查 —— 扫场景里所有 mesh 的世界包围盒，条件「三向都 > 0.9m」：

| 名字 | 尺寸 | 位置 | 颜色 |
|---|---|---|---|
| `(anon)` | 1.2×2.2×1.2 | (-4, 13.6) | `#9c5a5a` |
| `(anon)` | 1.4×1.2×1.4 | (12.5, 17.6) | `#5f8ab0` |

`#9c5a5a` 是 `view.colors.obstacle` —— 白盒色。这两个是**场景原有的障碍物 / 台阶**
（`pillar-sw` / `block-120`），一直存在，不是本轮的。

真正的 bug 在 `world.boxes`：v9s.60 给每个可破坏物加了 `dest-<id>` 的 AABB，
而白盒层无条件遍历 `world.boxes` 建不透明方块：

```ts
for (const b of world.boxes) { ... new THREE.Mesh(BoxGeometry(w, h, d), mat) ... }
```

盒子宽度 = 物件直径（罐子 0.56 / 仙人掌 0.64），**正好把造型整个包住** ——
所以「仙人掌不好看」有一半原因是根本看不见仙人掌，只看见一个红棕色方块。

修法一行：

```ts
if (b.id.startsWith(DEST_BOX_PREFIX)) continue;   // 只服务碰撞，不画
```

## 二、仙人掌：第三版，只抓三个特征

| 版本 | 做法 | 问题 |
|---|---|---|
| v9s.59 前 | 方柱 + 两条直角横杆 | 像旗杆刷了绿漆 |
| v9s.60 | 6 段收腰 + 明暗交替 + 每段错位旋转 | **碎**：条纹读成一摞小方块，错位让轮廓起毛刺 |
| v9s.61 | 4 段 + 统一本色 + 顶端圆头 | 直、粗、两臂 |

关键取舍：

- **去掉 `darkMat`**：同色系明暗差本来是为了「有体积」，但一层一亮就把柱身切成斑马。
  体积感交给光照（`MeshLambertMaterial` + 侧光），不交给条纹。顺手删掉一个材质。
- **去掉错位与旋转**：`sin(i·2.3)·R·0.05` 的错位在 0.32 半径上只有 1.6cm，
  屏幕上表现为轮廓抖动，不是「长歪」。
- **顶端分两态**：没被砍过 → 同色小圆头（仙人掌的顶是长出来的）；砍过 → 浅色斜切面。
  之前一直用 `capMat`，站着的时候像「被切了一刀的绿柱子」。
- **视觉半径 0.82R**：碰撞盒仍按 `R`，但画 1.0R 太粗，读作绿柱子。

侧臂参数（`makeCactusArms`，Core）：

| 参数 | v9s.60 | v9s.61 | 为什么 |
|---|---|---|---|
| `armRad` | 0.45R | 0.34R | 手腕细才像手臂，粗到接近主干就是钩子 |
| `outLen` | 1.7R | 1.15R | 刚出主干就上折，萨瓜罗不长横杆 |
| `upLen` | 1.45R | 2.1R | 上扬要明显长于伸出 |
| `atU` | 0.58 / 0.72 | 0.52 / 0.68 | 手臂长在柱身中上部，不是顶在头上 |

这些值在 `DestructibleState.arms` 里、进快照，但 determinism 没漂 —— 快照只统计
可破坏物的数量 / 断裂态，不含 arms 数值。改完 1115 例仍全绿。

## 三、smoke 挂了一项，是「测试站位」的历史债

改完造型后「真机挥刀能打断」变 FAIL（`broken=0`）。逐帧打印：

```
传送后  x=0  z=28.36     ← 目标 28.0，被推开 0.36
第1刀后 x=0  z=28.81  phase=settle  broken=0
第3刀后 x=0  z=29.40  broken=0
```

测试把玩家放在「地块中心 − 2.0」= z 28.0，而 `pole-b` 在 `centerZ − 2.05` = 27.95 ——
**人和杆本来就重合**。v9s.60 能过是靠「重叠」，刀扫过时必然相交；物件有了碰撞盒之后
玩家一落位就被推到 28.36，再被持续挤到 29.4，刀就够不着了。

改成显式站位：

```js
const st = h.world.destructibles.find(s => s.id === 'pole-b');
o.position.x = st.x;  o.position.z = st.z + 1.0;   // 正北 1m，朝向它
```

53/53 恢复。**教训**：测试依赖「地块中心」这类推导坐标时，只要场上有摆件，就会
某天突然撞上 —— 要么对准具体物件，要么留出明确余量。
