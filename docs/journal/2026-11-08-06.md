#### 1. 「某些地块上看不见」= 两个独立根因

#### 1.1 根因 A：白盒地块是透明材质

地块原来是 `transparent: true, opacity: 1`。看起来「和不透明一样」，但 Three.js 的排序路径完全不同：

| | 不透明通道 | 透明通道 |
|---|---|---|
| 排序 | `renderOrder`，同序**由近到远**，有深度测试 | `renderOrder`，同序**由远到近**，后画覆盖先画 |
| `depthWrite` | 默认开 | 贴地特效默认关 |

透明物体在所有不透明物体之后绘制，于是地块变成「和刀光抢先后」的普通一员。
关键在**距离怎么算**：整块地面是一个 32m 的大盒，排序距离取**包围球中心**。
角色站到场边、相机在另一侧时，地面中心比角色更靠近相机 → 地面被排到刀光 / 斩击弧
**之后**绘制 → `opacity = 1` 把它们整片盖掉。

这解释了「为什么只有**某些**地块」：取决于角色相对场地中心与相机的方位。
在场中央测试永远复现不出来。

修法（`three-scene.ts` → `setCollidersVisible`）：地块走不透明，只有开「碰撞盒线框」
调试时才临时切回透明，并且把 `transparent / depthWrite / wireframe / opacity` 一起改、
末尾 `needsUpdate = true`（`transparent` 是材质编译期属性，不标脏会静默无效）。

#### 1.2 根因 B：贴地特效的高度写死

`y = 0.03`（或 `角色 y + 0.03`）。站上 0.2 / 0.6 / 0.9 / 1.2m 台阶或高台时：

- 写死 `0.03` → 环在方块**内部**，被方块盖住；
- 用 `角色 y` → 从台阶边缘释放 / 跳跃时会飘在空中。

新增 `core/collision.ts`：

```ts
/** 该 XZ 上「从 refY 往下看的最高实体表面」；maxY > refY + tol 的盒子（墙 / 过梁）忽略 */
export function groundHeightAt(boxes, x, z, refY, fallback = 0, tol = 0.05): number
```

表现层包一层 `groundFxY(x, z, fromY) = groundHeightAt(boxes, x, z, fromY + 0.55, 0)`，
落点预览圈 / 电环范围 / 冲刺环 / 派生招光环 / 击地尘环全部改走它。
实测站在 (11.4, 1.2, -9.8) 的 1.2m 方块上挥大剑，尘环压在**方块顶面**（`shots/v9s38/10-swing-on-block.png`），
平地对照（`03-fx-on-ground.png`）高度一致。

#### 1.3 顺手收口：`FX_ORDER`

透明修掉之后还有第二个问题：贴地特效之间的 `renderOrder` 是**各写各的**
（贴地冲击 0、范围圈 2/3、假人环 5、玩家环 6、刀光 6、进度弧 8、预警弧 9）。
相同 `renderOrder` 时只剩距离排序，而贴地环全在 `y ≈ 0.03` —— 谁压谁基本靠运气。

新增 `src/presentation/fx-layer.ts` 作为**层级唯一来源**，一条带间隙的单调序列：
贴地层 `labPlate 10 / groundArea 12 / groundAreaEdge 13 / ringHalo 20 / ring 22 /
ringMeter 24 / ringWarn 26 / groundFx 30`，身体层 `trail 40 / slash 44 /
projectileTrail 46 / projectile 48 / projectileGlow 50`。规则写进注释：
贴地 10~39、身体 40+，光晕永远画在本体之前，不透明物体不进表。

**没有**采用「特效全设 `depthTest: false`」这个偏方 —— 那会把特效画到墙后面去。
排序问题用排序解决。

#### 2. 三个持械陪练：不是第二套实体，是「带武器的假人」

`config/game.json`：

```jsonc
"fighters": {
  "weapons": ["sword-shield", "dual-swords", "greatsword"],
  "spawn": [{ "x": -3.6, "z": 3.8 }, { "x": 3.9, "z": 3.6 }, { "x": 0.2, "z": 5.9 }],
  "initialModes": ["spar", "spar", "spar"],
  "moveSpeed": 2.1, "attackInterval": 3.4, "attackRangeScale": 0.9,
  "knockbackScale": 0.6, "leashRadius": 7
}
```

**为什么要「和主角一样」**：另写一套骨架 = 两套挥击数据、两套武器挂点，混战强度就不可比了。
所以做法是**复用**：

```
DummyState（假人三段状态机）
  → syncFighterCombat()  每帧抄成 CombatState（phase / attackProgress / timings / weapon）
  → createFighterRig()   复用 voxel-rig，只做 DummyState → CharacterState 的翻译
  → rig.update()         主角同款挥击 / 受击 / 步态 / IK
```

`three-scene.ts` 里只多一行：`s.weapon ? createFighterRig(...) : createDummyRig(...)`，
两者收敛成同一个 `AnyDummyRig` 接口，所以点击轮转 / 威胁环 / 受击击退 / 渲染插值全部白拿。

**一个必须踩过的坑**：`voxel-rig` 的 `root.rotation.y = rootYaw + spinYaw` 被挥击的
「整体带转 / 整圈旋转」占用，位置和身体朝向不能再写进 root（会双倍旋转）。
所以外层多套一个 `group` 承担位置 + `bodyYaw`，root 只承担带转。

**攻击欲望怎么降**（不是简单调大间隔，那只会变成「偶尔冲上来猛砍」）：

| 手段 | 参数 | 效果 |
|---|---|---|
| 站位带 standoff | 起手距离 × **1.7** | 冷却期停在 1.7 倍距离外，不贴脸 |
| 冷却期只走位 | `attackCooldown > 0` → 切向 strafe | 绕着你转，不推进 |
| 首击错开 | `attackInterval × (0.25 + 0.22i)` | 三个不同时挥刀，不会读成「被集火」 |

带 `±0.35 / ±0.45` 滞回带，站到边界不会一帧进一帧退地抖。
实测三个陪练与玩家距离 **2.13 / 2.09 / 3.02 m**，配色红 / 金 / 紫（`view.dummies.fighterColors`）与蓝色玩家可区分。

**刻意没做**：卡肉（AI 不做 `hitstop`，否则玩家被打时双倍顿帧）与连击（假人状态机只有单段三阶段）。

#### 3. 玩家受击击退默认打开

`core.hits.noDamageToPlayer: false`。这个开关的语义是「只写受击动画、不推位置 / 速度」，
默认关掉之后玩家和假人走完全相同的击退公式（`dummyKnockback` × 武器）。
调试面板上的**反向**命名「测试限制：玩家不被击退」改成正向开关「玩家受击击退」
（`get enabled(){ return !ht.noDamageToPlayer }`），勾上 = 真的会被推。

顺带处理了 4 个旧用例：`dummies.test` / `links.test` / `v9s25-skills-data` 在用例内显式
`noDamageToPlayer = true` 并注明「本用例守的是旧契约，与默认值无关」；
`determinism` 快照按流程 `-u` 更新后**再跑一次**确认不再漂移。

#### 4. 调试面板重排

按「你要调的是什么」重排成 7 个一级分类，标题不带版本号：

| 一级 | 子分组数 | 说明 |
|---|---|---|
| 模拟 / 显示 | 1 | 时间控制、线框、模块总闸 |
| 移动 / 输入 | 4 | 基础移动、摇杆、冲刺、分离 / 挤压阻力 |

| 战斗 / 命中 | 6 | 连击时序、卡肉节奏、命中 / 击退、受击分层、派生招、目标辅助 |
| 表现 / 特效 | 3 | 挥击幅度 / 刀光、夸张化、握持 / 腕部 |
| 假人 / 混战 | 2 | 普通假人 AI、**持械陪练** |
| 相机 | 3 | 基础、智能构图、缩放 |

**删掉的废弃项**：「旧斩击弧 开（已被刀光替代）」`view.projectiles.slashEnabled` ——
v9s.22 起刀光才是主要打击反馈，这个开关只剩考古价值，留着只会让人以为它影响手感。
**新增**：「持械陪练」子分组（移速 / 攻击间隔 / 起手距离 / 击退比例 / 牵引半径 +
「陪练行为（全部）」下拉，一次把三个陪练切到同一行为，读第一个陪练的当前状态）。
