2026-11-10 · v9s.56 / v0.9.77

## 需求

> 1.现在动作好很多，合下 git。
> 2.增加命中飙血表现
> 3.增加陪练死亡重新刷新

第一条是收尾（v9s.55 已合并推送，`main` 与 `origin/main` 齐平、工作区干净）。
后两条是一件事的两半：**能打死，才有「打死的表现」**。

## 一、血：三层，缺一层就读不出来

第一版只做了血珠。截图一看：一地红色小方块，像打碎了一罐红油漆，完全没有「从哪儿喷出来」的感觉。
补了两层才成立：

| 层 | 给的信号 |
|---|---|
| 血珠（沿击打方向抛 + 重力 + 落地） | 方向 |
| 血雾（命中瞬间一团，0.15s 涨开淡出） | 冲击 |
| 地面血迹（6.5s 留痕） | 环境痕迹 |

调参踩到的两个坑都记在 `systems/blood.md` 里：

1. **血雾半径 0.42 是一块红布**，实测把角色整个盖住。收到 0.22 才读得出「一团」。
2. **颜色与衣服撞车**。第一次拿红衣剑盾陪练当靶子，血珠贴上去完全看不见 ——
   换成紫衣大剑陪练才验证得了「红方块确实在飞」。

数据源没用事件队列，用了 `world.hitMarks`（短环形 + `seq`）。原因很直接：

```
step() 每帧开头 events.length = 0
```

低帧率一帧跑 5 步，只有最后一步的事件活到渲染那一帧 —— 连击的血花会一段一段地丢。
`seq` 只增不减、复位也不归零，表现层按它补播，幂等。

## 二、死：木桩不能死，陪练必须死

这一条是设计取舍，不是实现细节。普通假人是**测试桩**（量距离、测 AI 行为），
被打死会让工位失效；陪练是对手。所以血量分成两个旋钮：

| 配置 | 值 | 结果 |
|---|---|---|
| `dummies.health` | 0 | 木桩打不死，行为逐字节不变（夹具 hash 可证） |
| `dummies.fighters.health` | 120 | 剑盾 9 刀、双刀 13 刀、大剑 4 刀 |

伤害按**受击类型**查表（`light / heavy / knock`）× 武器倍率，而不是每个调用点自己传：
受击类型本来就已经按「武器 × 连段段数」定过档，跟着同一档走不会漂移。
四条命中链路（近战 / 击地 / 派生招 / 远程）共用 `applyHit` 一处，
所以「箭能射死、刀不能」这类事故从结构上就不存在。

死亡之后**所有读假人的系统都要跳过它**，一口气改了七处：命中结算、近战/击地/派生扫描、
AI、索敌、注视、分离、脚下环。少改一处就是「打尸体有反馈」。

## 三、刷回来：原地站起来，别瞬移

重生没有回 `home`，就地在原地满血。回 home 会让刚打死的那个瞬移到远处，读作「换了一个人」；
原地站起来时上一刀的血迹还在地上，读起来是「同一个人又站起来了」。

**复活保护 0.45s** 是必须的：玩家站在尸体上连打时，下一刀正好落在重生那一帧，
刚刷出来就被秒，等于没刷新。保护期与表现层的「从地里升起」同长。

## 四、表现：倒 → 沉 → 升

体素材质不透明。改透明度要逐材质开 `transparent` 再重排渲染顺序 —— v9s.38 刚修完那一类坑
（透明地面盖掉刀光），不想再来一次。所以尸体不做淡出，做**被地面吞掉**：

```
deadT  0 → 0.42s   绕脚底向后倒 84°
respawn 3.5 → 0.38 之后  下沉 1.05m
revive  0.45 → 0      从地下升回来
```

三段首尾相接（沉完那一刻正是 `revive` 开始），中间没有跳帧。
整条曲线是**表现层叠加在骨架上的整机变换**，两条骨架（简化假人 / 持械陪练）共用一份
`applyDeathPose` —— 写进 rig 就要写两遍，而且会污染「按 Core 状态解算姿态」的接口语义。

`group.rotation.order = 'YXZ'`：先转身再后倒，X 轴才是身体局部的前后轴。
用默认的 `XYZ` 会朝侧面倒。

## 六、遗留

1. 尸体**不能撞**：`separation` 跳过死者，玩家可以穿过尸体。要做得更实需要给 Core 加「尸体是障碍」的语义。
2. 血**不跟姿势**：命中点在 Core 里是「脚底 + 身高比例」，不看实际骨骼。打头打脚喷的位置一样。
3. 血迹**不分地面材质**：台阶侧面也会贴一块平的血迹（`groundY` 取的是脚下支撑面）。
4. 陪练**没有血量 UI**：只有 HUD 一行摘要 + 倒地本身。要不要头顶血条是个产品决定，本轮没做。
