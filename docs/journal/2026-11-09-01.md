## 2. 「保持距离」为什么像磨脚

先把现象量化（真实页面，玩家钉住，只留剑盾陪练，采样 90 帧）：

| 指标 | 旧行为 |
|---|---|
| 移动帧占比 | 100%（没有一帧是站着的） |
| 平均速度 | 0.67 m/s |
| 5 秒位移路径 | 3.08 m |
| 停步收相帧 | 11 / 90 |

两条独立根因，都在 `desiredDirection()` 的 `spar` 分支：

1. **死区内每帧都给切线方向** `sin(t × 0.55 + id) × 0.55`。玩家不动，陪练也一刻不停绕圈；
   幅度只有 55% 移速 → 1.1 m/s 的碎步。观感 = 原地磨脚。
2. **径向是开关式的**：`dist > standoff + 0.35` 全速进、`dist < standoff − 0.45` 全速退。
   玩家在阈值附近微动（或自己被分离力推 2cm）→ 方向逐帧反转，速度在 0 附近来回拉锯，
   腿却一直在迈。

### 修法

```ts
// 径向：连续比例，越界才逐渐加满
const radial  = clamp((dist - standoff) / 0.5, -1, 1) * 0.9;
// 切向：时间门（按 id 错相位、两端 smoothstep、关门给 0）
const tangent = strafeGate(world.time, s.id, cfg.strafePeriod, cfg.strafeDuty) * SPAR_STRAFE;
```

- `strafePeriod = 5.2s`、`strafeDuty = 0.34` → 走 1.8s、站 3.4s；三个陪练相位错开，
  混战里总有人在动，但没有人一直动；
- 开门时幅度 0.9（≈1.9 m/s 接近它自己 2.1 的上限）→ 走就走得像样，不是碎步；
- 关门后方向为 0 → 速度指数衰减 → 表现层走「停步收相」，自然站定；
- `keep-distance` 的普通假人共用同一个门（它也不该在玩家不动时绕圈）。

改后同一口径实测：平均速度 0.42、路径 2.21m、停步收相 49/90 帧、移动时均速 1.5 m/s。

### 附带修掉一个双计

`fighter-rig.ts` 把 `hurt.knock` 并进了 `cs.velocity`，而 `voxel-rig` 内部又按
`gaitCfg.knockGaitScale` 把击退并入**步态驱动** → 陪练挨打时步频翻倍、腿原地倒腾。
现在 `cs.velocity` 只写自主速度（位置仍含击退位移），与主角同一套语义。

## 4. 踩坑

1. **`v9s20` 的贴边用例前提被改了**：旧行为下陪练自己会绕圈溜到边界，新行为停在
   keepDistance 上根本不到墙。改成「玩家比 keepDistance 更近」把假人真的逼到墙边，
   并加前置断言 `position.x > maxX − 0.05`。
2. **确定性快照必须更新**：`spar` / `keep-distance` 的轨迹全变了。变化只来自这两类单位的
   位置序列，玩家 / 全局字段零漂移（dump 对比过）。
3. **诊断脚本帧率只有 ~18fps**：软件渲染下 `requestAnimationFrame` 跑不满，早期用
   「每帧角度差」判断抖动会被采样间隔掩盖；改成统计「移动帧占比 / 移动时均速」这类
   与帧率无关的量。
4. **相机跟随玩家，拍不到陪练**：`snapCamera` 只是把目标点瞬移过去，下一帧又跟回玩家。
   要单独拍陪练，就每帧 `snapCamera(陪练位置)` 并在后期按红色像素包围盒裁切放大。
