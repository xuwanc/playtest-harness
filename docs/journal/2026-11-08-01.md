### v9s.25 · 剑身仰角、动作数据化、索敌与弓

> 反馈：「1. 大剑前两击看着剑尖几乎都指着头顶上方的位置，没有横劈的样子，只有第三击
> 向下劈看着对了点；2. 锁目标的问题，用技能时不应该由移动轮盘指向来搜索，右手按键有
> 拖拽方向时应该由右手方向来搜索；3. 调试面板弓的后坐力全部取消，射击时会有一段前移；
> 4. 后面会做几十种技能，所以希望技能模块化、数据驱动；5. 不同体型 / 四足 / 蜘蛛，
> 是否该在代码和骨骼层加一层 control rig？」

#### 1. 剑尖朝上：不是幅度问题，是挂点语义错了

实测扫一遍三连击的刃身世界方向，问题一目了然：

| 段 | 旧仰角（离水平） | 刃尖高度 | 读感 |
|---|---|---|---|
| 段 1（右→左） | **44° ~ 58°** | 1.31 ~ 1.49 m（头顶在 1.3 m） | 举着剑转身 |
| 段 2（左→右） | **47° ~ 60°** | 1.43 ~ 1.52 m | 同上 |
| 段 3（举顶下劈） | 73° → −25° | 1.86 → −0.14 m | 对了 |

根因是两套角度混在一起：数据里写的是「挂点相对前臂转多少度」（大剑默认 58°），
而手臂绕 X 抬到 −80° 时，58° 挂点只让剑身剩下 12° 的倾斜 —— 剑几乎竖直。
作者也没法凭直觉算出「这一段该给多少度」，因为答案取决于手臂链的实时角度。

改成**世界语义**：数据只写 `bladePitch`（0 = 水平、正 = 剑尖朝上），rig 反解挂点：

```text
仰角 = π/2 − (躯干 + 肩 + 肘 + 挂点)
⇒ 挂点 = π/2 − 仰角 − (躯干 + 肩 + 肘)
```

腕角刻意**不**算进补偿链 —— 那是 v9s.24 的滞后层，抵消掉就等于把它删了；
现在是「剑停在目标仰角附近，再叠加腕部甩动」。躯干俯仰取「姿态层刚写完、
惯性 / 受击还没叠」的快照，所以受击后仰、跑动前倾时剑仍会跟着身体走。

结果：段 1 / 2 的仰角全程落在 **15° → 0°**，水平朝向扫过 103°（刃尖 0.94 → 0.74 m，
胸口高度）；段 3 仍是 73° 举顶 → −18° 下劈。

#### 2. 索敌参考朝向：右手拖拽优先

`targetingUpdate` 原来只认「有移动输入就用移动方向，否则用面朝向」。于是玩家用右手
拖向左 / 右放技能时，索敌还按左摇杆找人，选出来的目标和手指指的方向不一致。
现在与 `resolveFacingYaw` 同序：

```text
右手拖拽方向 > 移动轮盘方向 > 上一帧面朝向
```

只在 `aimActive` 为真时生效，键盘 / 纯点击行为逐字节不变。

#### 3. 弓：后坐力整层删除

- 删掉 `kick` 脉冲层（v9s.21 为弓后坐力加的，唯一使用者也是它）：`World.kick`、
  移动层的积分 / 衰减、`recoilSpeed / recoilDecay` 配置与两个调试滑块一起移除；
- `bow.release.lunge` 0.12 → **0**：放箭动作本身那一下前冲是遗留手感，删掉。

现在原地连射，角色水平位移 < 0.02 m；攻击期间 `impulse` 恒为 0。

#### 4. 动作数据化：PoseClip

技能行为在 v9s.19 已经拆成 `core.skills` 模块表，缺的是**动作数据**。这一版把
三段挥击从 TS 常量搬进 `config/game.json`：

```json
"combo": { "greatsword": ["gs.right-left", "gs.left-right", "gs.overhead"] },
"clips": {
  "gs.right-left": {
    "kind": "right-left",
    "keys": [
      { "t": 0,    "ease": "in", "pose": { "bodyYaw": 0.85, "bladePitch": 0.30, ... } },
      { "t": 0.55,              "pose": { "bodyYaw": 0.05, "bladePitch": 0.12, ... } },
      { "t": 1,                 "pose": { "bodyYaw": -0.95, "bladePitch": -0.05, ... } }
    ]
  }
}
```

- **通道是语义的**（`bodyYaw / bodyPitch / bodyRoll / pelvisX / pelvisZ / armPitch /
  armYaw / armRoll / elbow / armLPitch... / bladePitch`），不是骨骼旋转。体素 rig 是
  一个 solver，将来四足 / 蜘蛛是另一个 solver，读同一份数据；
- `t` 归一化 0..1，**不是秒**：快刀和重劈可以共用同一段动作，改 timing 即可；
- `core/pose-clip.ts` 提供 `samplePoseClip`（纯函数，缺省通道补 0、越界夹两端）与
  `validatePoseClip`（时间递增 / 通道合法 / 有限数），测试把配置里每条剪辑都过一遍；
- 段数不再写死 3：`combo` 数组多长就循环多长；
- 双剑第二段换左手，只写 `{ "clip": "gs.left-right", "lead": "L" }`，不复制整条剪辑。

新增一个技能的动作 = 写一条剪辑 + 在 `combo` 里挂上去（行为侧如需新机制再加一个
`SkillModule`）。**编辑工具按你的意见先不做**：现在缺的是稳定格式与足够多的样本，
等技能铺开、格式不再变，再做「给 AI 用的数据生产工具」才有意义。

#### 5. 关于 control rig 层的结论

数据层已经先把「语义通道」这件事做了 —— 这就是 control rig 的契约部分，只是还没有
第二套骨架来验证。详细判断见本轮回复：**值得做，但只做薄的一层**（接触点 / IK 目标
+ 每套骨架一个 solver），不要做完整的多轨控制绑定；性能不是问题（几十个角色 ×
每帧几百次向量运算），成本在绑定与调参，所以等第二种体型真正落地时再抽。

### v9s.26 · 横扫到对侧 135°、双持整圈旋身、剑盾盾猛顶

> 反馈：「武器的左右幅度还不够，左右砍可以扫到对侧 135° 的大小，双持幅度也加大，
> 第三击可以做武器展开原地转一圈，剑盾可以第三击用盾猛顶。」

三条都是**表现层**诉求，而且都不该靠继续拧腰椎解决：体素方块人上身拧过 ±0.9 rad
后头会甩到背后、副手也够不到柄。真人做大幅度横扫是「脚掌碾地 + 整个人带转」，
所以这轮把幅度拆成两层，并把「转一圈」做成剪辑级语义。**依旧不做编辑器**，
和 v9s.25 一样只加数据格式 + 数据。

#### 1. 三个新语义（数据格式）

| 语义 | 位置 | 作用 |
|---|---|---|
| `rootYaw` | 通道（`POSE_CHANNELS`） | 整个人绕世界 Y 轴带转，写进 `root.rotation.y`；与 `bodyYaw`（腰椎扭转）叠加，是横扫幅度主力 |
| `bladePitchOff` | 通道 | 副手武器挂点仰角，语义同 `bladePitch`；双持两把剑能各自摆平，剑盾盾面能正对前方 |
| `spin` | 剪辑级元数据 | 按 `attackProgress` 单调推进到 `turns·2π ≡ 0` 的整圈旋转，收招自动回正 |

- **`rootYaw` 不是继续加大 `bodyYaw`**：`bodyYaw` 是上身相对骨盆的拧（造型细节，
  ±0.9 内），`rootYaw` 是整个人绕重心的转（幅度主力）。两者相加才是剑尖真正扫过的
  世界角度。写在 rig 自身的 `root` 上，与 three-scene 设在外层 `playerRoot` 的
  `bodyYaw` 叠加不冲突；足部 IK 用世界锚点再转回局部，脚会跟着一起转，不打滑。
- **`spin` 不是 `rootYaw` 通道**：通道按挥击曲线 `swing = −1→+1→0` 采样，收势会回摆，
  转到一半又倒回去；而「转一圈」要按攻击进度单调推进，结束时 `2π ≡ 0` 正好回正、
  不留残余。所以它是剪辑级元数据，不是通道。
- **`bladePitchOff` 只在该剪辑显式覆盖时接管**（`clipHasChannel`）：缺省 `null` 沿用
  武器默认挂点，否则双持待机时左手会被莫名翻成水平。

#### 2. 幅度校准（逐帧扫刃尖世界朝向，unwrap 后取跨度）

| 武器 | `weaponScale` | 段 1 | 段 2 | 段 3 |
|---|---|---|---|---|
| 大剑 | 1.00 | **233°** | **232°** | 59°（举顶下劈，不横扫） |
| 双持 | 0.90 | **199°** | **208°** | **283°**（刃身连续扫）+ 整圈 360° |
| 剑盾 | 0.78 | **186°** | **183°** | 35°（向前盾顶） |

第一版先收到 `rootYaw = ±0.32`（大剑 170°、双持 139°、剑盾 124°），反馈「还不够、
要扫到对侧后方」。第二轮把幅度拆开一起加：`rootYaw` 提到 ±0.55（大剑）/
±0.5（双持 / 剑盾），腰椎 `bodyYaw` 提到 ±1.1~1.15，手臂横摆 `armYaw` 提到
−0.85~−0.9。实测刃尖从右前 71° 扫到左后 161°，**确实越过了对侧后方**。

横扫段刃身仰角：大剑 / 剑盾 `|pitch| < 17°`（仍是平扫）；双持主手 < 8°，
副手正在往后方收势，允许上扬到 36°。

双持不再复用大剑剪辑 —— 新增 `ds.right-left` / `ds.left-right`，因为「副手往哪收」
和大剑的双手持不同（见下一节）。剑盾段 1 / 2 继续复用 `gs.*`（左臂持盾不接管）。

> **截图会骗人**：斜俯视相机下，一把水平指向远处的剑会被投影成「竖直朝上」。
> 所以验收横扫不能只看截图，要读 v9s.26 新增的只读诊断接口 `__harness.bladeWorld()`：
> 大剑横扫最远帧刃根 `y=0.80` / 刃尖 `y=0.81`、双持 `0.71 / 0.72` —— 两端几乎等高，
> 就是水平横扫；仰角全程 `pitch 3°`。

#### 3. 双持：一手挥出，另一手往同侧后方收

> 「左手攻击时，右手往右后方收，左手同理。」

`armL*` 通道统一表示**副手**（主挥手之外的那只手），与 `lead` 无关：

| 段 | 主挥 | 副手通道实际指向 | 值（起手 → 挥出满） |
|---|---|---|---|
| 段 1 `ds.right-left` | 右手 | 左手 | `yaw −0.41→−0.50`（向左）、`pitch +0.45→+0.59`（后摆）、`elbow −1.04→−1.17`（屈肘） |
| 段 2 `ds.left-right` | 左手 | 右手 | `yaw +0.41→+0.50`（向右）、`pitch +0.45→+0.59`、`elbow −1.04→−1.17` |

副手不再跟着主手一起挥，而是收在同侧后方做平衡 —— 主手的挥出幅度因此在视觉上
更突出。大剑仍是双手持，副手由 `applySecondaryGrip` 拉到柄上，不吃这组通道。

踩到一个欧拉角耦合的坑：副手 `armYaw` 一开始写到 0.75 rad（43°），手臂绕 Y 转得
太多，`applyBladeTarget` 只按 X 轴反解挂点，结果副手剑仰角被甩到 44°（朝天）。
把 yaw 收到 0.45、后摆交给 `pitch`、屈肘交给 `elbow` 后降到 36° 以内。

#### 4. 双持第三击：展开原地转一圈

`ds.spin` 双臂 `roll` 外张到 ±1.15、两把剑的 `bladePitch / bladePitchOff` 都保持接近
水平，然后整个人原地转一整圈。踩到三个坑：

- **转不满**：连击的 `cancelWindow` 会在 recovery 过半就接下一段，段内
  `attackProgress` 实测最多只到 ~0.71，线性推进只转到 **289°**。给 `PoseSpin` 加
  `span: 0.6`，让转体在换段前完成，之后一直停在 `2π`（正对前方）。
- **换段倒转半圈**：`segBlend` 会把姿态从 `2π` 插值回 `0`，中途经过 `π`，观感是
  收招时倒转 180°。`blendSwingPose()` 里 `spinYaw` 直接取目标段、不参与插值 ——
  `2π ≡ 0`，旋转上没有任何跳变。
- **段 2 右手剑朝天**：`weaponBlade()` 取的是右手剑，段 2 主挥换到左手后右手剑
  没被反解。现在由 `ds.left-right` 的副手通道（右手往右后方收）+ `bladePitchOff`
  一起管，实测该段右手剑降到 36° 以内。

另外给 `swingCurve` 补了一小段「命中后保持挥出满 0.08 再回落」（旧版 0.5 立刻回落）：
否则 233° 的横扫会在 3 帧内从「左后方」弹回「左前方」，观感像没扫到位。

#### 5. 剑盾第三击：盾猛顶

`ss.shield-bash`：左臂 `armLPitch −0.7 → −1.55`、`elbowL −0.9 → −0.05`（伸直）、
`bodyPitch −0.28 → 0.5`、`pelvisZ −0.08 → 0.18`（重心前压），`bladePitchOff` 反解让
盾面始终正对前方。诊断里这一段的水平扫角只有 **35°**（横扫段是 186°），说明它确实
是在往前顶而不是又挥了一刀。

顺带修一条数据层放行规则：剑盾平时左臂持盾、不接管（交还步态摆臂），但剪辑
**显式**写了 `armL*` 通道时必须放行，否则盾猛顶根本动不了。复用大剑横扫剪辑的
段 1/2 没写这些通道，旧行为逐帧不变。

#### 6. 判定与表现解耦（这轮刻意没动的东西）

`core/hits.ts` 的近战判定只看 `combat.attackFacing` 与 `hits.arcDeg`
（**半角 65° = 全角 130°**），完全不读 `rootYaw / spinYaw / bladePitchOff` ——
这些量只活在表现层的 `SwingPose` 里，Core 的 `World` / `CombatState` 根本没有
这些字段。所以「视觉扫到 135°」和「命中范围」是两件事：这轮只改观感，没有扩大
打击范围、没有动平衡，也没有触碰确定性快照。真要扩判定范围，是单独调
`hits.arcDeg` 的另一个决策，不跟着动画数据走。
