# 2026-11-09 · 蜘蛛主角接入（v9s.50 / v0.9.71）

## 起因

上一轮把蜘蛛做成「可跑原型 + 造型定稿」，用户确认「按 A 来」。这一轮的目标不是再论证，
而是**把原型变成玩家能操作的主角**，好试手感：

> 「主角可以切换成蜘蛛我试下手感」

## 做法：复用已有的体型切换通道，而不是另开一条

`setBodyType(id)` 早就在（v9s.30）：重建 rig → 摘旧 group → dispose → 挂新的 →
同步 `characterHeight / radius` → 重置刀光采样。这条路径本来就是为「换骨架」设计的，
只是之前只换尺寸。

所以新增的只有两件事：

1. `BodyTypeConfig.rig: 'human' | 'spider'`（缺省 human），`buildRig` 按它分流；
2. `src/presentation/spider-rig.ts` —— 主角骨架的第三个实现（人形 / 陪练复用 / 蜘蛛）。

位置与朝向仍然由外层 `playerRoot` 承担。这意味着 **Core 的移动 / 碰撞 / 战斗一行没改**，
蜘蛛的「腿怎么摆」完全在表现层解决。

## 类型上的取舍：PlayerRig 的其余方法是可选的

`VoxelRig` 有 20 多个方法（武器刃身、挥击段、双足步态、脊柱分段…）。蜘蛛没有手、
没有刀、没有两条腿，这些读数对它**不存在**。

没有为它写 20 个返回 0 的假实现 —— 那会让"蜘蛛有这些自由度"变成一句谎话。
改成：

```ts
type PlayerRig = Pick<VoxelRig, 'group' | 'update' | 'dispose'>
  & Partial<Omit<VoxelRig, 'group' | 'update' | 'dispose'>>
  & { debug?: () => { maxReach; clamped; phase } };
```

主渲染路径（`hero.update(...)`）因此**零分叉**：两套骨架的 update 签名一致。
诊断路径按「有则读、无则显示 -」处理，只有 HUD 会直接读的 5 个字段给了中性值。

## 调试过程：三个数看着不对，逐个拆

第一次跑起来 `maxReach = 2.9`（腿长的 2.9 倍，即目标点在 2.5 m 外）。2.5 m 不是
"够不到"，是**坐标算错了的典型量级**。先打印坐标而不是调参数：

```
body z=-3.13  foot0 z=-2.36  → 脚落在身后 0.77 m
```

脚确实在身后。于是问题变成「支撑相为什么落后这么多」，最终拆出三条：

### 1. 步频 9.3 Hz，一帧 0.16 个周期

4.2 m/s ÷ 0.45 m 步幅。摆动相只有 2.6 帧，20 fps 下 1 帧。脚在两帧间瞬移半米，
IK 目标点跳变，`reach` 冲到 2.9。

修法：**步频封顶 7.5 Hz，超出的线速度转成「脚滑」**（支撑脚按帧跟着身体滑一点）。
代价是冲刺时 20% 脚滑，换来不抽腿、不瞬移、不拉直。

### 2. 移速该按体型走，而不是全局

4.2 m/s 对 0.5 m 高的蜘蛛是 **8.4 身高/秒**（人形只有 3.5）。这不是「腿摆不过来」的
调参问题，是量纲问题。`BodyTypeConfig` 加 `moveSpeed`，蜘蛛取 2.6。

### 3. 前伸量公式写错，每周期漂一点

原来 `stride × (1 − duty/2)`，而支撑相实际后退 `stride × duty`。差值每轮累积，
跑 9 m 后脚落后 1.2 m。改成 `stride × duty` 后 `d0` 稳定在 0.52~0.64。

> 这三条都是"数值反推 → 打印坐标 → 算出量纲"的顺序查出来的。
> 靠调参数试错会绕很久：2.9 这个数根本不在可调范围内。

## 相机：一个绕不过去的取舍

`view.camera.pitchDeg = 50°` 是给 1.2 m 人形调的。蜘蛛 0.46 m 高，50° 几乎是顶视，
8 条腿全被身体挡住。降到 32° 后能看出腿的折线，但**再低就看不清地形**（RPG 俯视相机
本来就是为「看清前方」设计的）。

配套改了两件事：

- `bodyZoom = 0.24`（17 m → 4.1 m），蜘蛛占屏从 5% 提到 12%；
- 腿 / 关节配色提亮（`#3e3557 → #5d4f82`、`#5f5285 → #8b7ab8`），
  深紫腿配深蓝地面在俯视下糊成一片，靠对比比靠细节有效。

**结论：32° 下"高抬膝"的剪影读不出来，这是视角决定的，不是模型问题。**
真机试手感时用户可以滚轮拉近；如果这条路走不通，下一步是把蜘蛛做小（0.8×）当地面杂兵，
反而更匹配现有相机。
