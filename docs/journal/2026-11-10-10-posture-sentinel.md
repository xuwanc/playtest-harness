# v9s.64 · 把鱼人按成爬姿：体态是一层，不是一套新动画

用户提了两件事：① 把鱼人「屁股抬高、头胸压低、脊椎接近水平、再弓点腰，像老头一样」，
并且想知道动画能适配到哪里；② 让我自己挑一个角色造型，长期留在游戏里。

## 一、为什么不做新动画

**想要的是一个静态基准**：站着就这样，走、砍、挨打都保持。这正好是「叠在所有动态层之上的一层」，
而不是 12 段关键帧各改一遍。旧代码里已经有先例 —— 老人的 `hunch`（v9s.52），
它插在 `splitSpine` 之前，所以会被摊成腰 / 胸两段，看起来是「弓着」而不是「整根斜」。

新加的 `posture` 就是把 `hunch` 拆成七个可组合旋钮：俯仰 / 弓腰 / 抬头 / 前伸 / 缩颈 / 抬胯 / 后坐。
两件事必须按顺序做对：

- **在 `splitSpine` 之前**写 `pitch`：否则不摊开，胸和腰不会形成弧线；
- **在 `splitSpine` 之后**写 `waist`：只折腰段，才有「塌背」的那道坎（并且要回写 `intendedTorso`，
  否则帧尾的泄漏守卫会当成「有人把 `upper` 当总角写」）。

## 二、三条边界，都是量出来的

写之前我以为是「压到多少算多少」，量完发现全是硬墙：

| 想做的事 | 实测结论 |
|---|---|
| 抬胯（`pelvisLift 0.05`） | 脚离地 2.6cm。两骨 IK 上限 = `legLength`，默认站姿**已经把腿用满** |
| 屈膝换行程（`pelvisDrop 0.09`） | 脚陷地 2.2cm；0.15 时陷 6.7cm（IK 校正角吃不下） |
| 一路压到 103°（`pitch 1.8`） | 头最低点还有 0.36m —— **根本啃不到地**，先坏的是可读性 |

所以「屁股抬高」最后是靠**躯干压平**做到的：髋不动，头和胸低下去，臀线自然成了最高点。
鱼人取 `pitch 0.72 + waist 0.24`（≈55°），`pelvisDrop 0`、`pelvisBack 0.02`。

第三条尤其反直觉：一直防着「头穿地」，结果 2.5D 俯视里先坏的是**遮挡** ——
头一低就把躯干全挡住，最高点从「头」变成「背」，画面读作一坨。判断只能靠截图。

## 三、挥砍会来抢前倾额度

第一版直接给 65°，站着好看；一按 `j` 就扑倒在地 —— 挥砍自带约 30° 前压，叠起来 95°。
修法是「姿态预算」：体态只吃 `maxTotal(1.05) − 动态层已用`，攻击期间再打五折；
头抬头量用**实际吃进去**的角度反算（不是名义值），否则预算夹掉多少、脸就朝天多少。

同时补了剑身补偿：`applyBladeTarget` 吃的是「躯干俯仰」，体态写在它之后，
不把实际吃进去的角度加回去，剑会跟着身子一起扎进地面。

## 四、哨兵机（我挑的角色）

一台锈掉的巡逻哨兵。三条自我约束：

1. **大块抓型**：头 = 一块方颅，躯干 = 一块胸甲板 + 一个背包；
2. **小块点缀**：灯条 / 天线 / 三根警示条 / 侧栅 / 腰侧液压杆，全挂在轮廓线上；
3. **一眼不同**：只画**一只**横灯（人和鱼人都是两只眼）。

两处弯路：① 眼睛做成「方框 + 方窝 + 小灯」三层套盒，200px 下互相吃掉，读作一块铁皮 →
改成「一条黑带 + 一条亮灯」；② 排气管竖在背包上沿，正面看是一对**鹿角** → 改成横着伸。

## 教训

1. **「改姿势」先问它是基准还是动作**：基准加一层，动作才改关键帧。加一层的位置比参数重要。
2. **抬关节之前先量关节余量**：IK 的可达上限是配置值，而默认姿态可能已经贴着它了。
3. **数值安全 ≠ 画面可读**：俯视游戏里，遮挡比穿地更早发生。
4. **组合出来的角度要留预算**：静态基准 × 动态动作会相乘，任何一个都不该「吃满」。
