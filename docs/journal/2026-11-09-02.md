# 2026-11-09 · v9s.41：连击跨步换腿

## 需求

> 「攻击跨步之时，再接跨步攻击没有换腿跨步」

## 1. 不是动画不对，是相位每段都回零

攻击时下盘由 `attackGaitDrive()` 合成：Core 锁了自主移速，腿吃的是「等效驱动」。
旧写法是**往返脉冲**：

```
phase = 基准 + π × bump(p)      // bump: 0 → 1 → 0（两段 smoothstep）
```

于是每段攻击都从同一个基准摆出去、再摆回来，段末与段首姿态**完全相同**。
连着打三刀，下盘的逐帧姿态是**同一段曲线的重播** —— 用户读作「没换腿」。

第二个症状是段间取消。`cancelWindow` 在 recovery 中途接下一段时 `p` 归零，
而基准没变 → 相位从 0.77π 被硬拽回 0，**实测单帧腿角跳 0.82 rad（47°）**，
看起来像脚被拽回去重新起步。

## 2. 改法：一段 = 迈一步，接着上一段走

```
phase = 段起点相位 + π × smoothstep(p)     // 只往前，不回头
```

- 段起点 = 上一段**最后一帧实际输出的相位**（`attackPhaseBase`），识别新段的依据是
  Core 的 `attackId` 变化（连击取消窗口提前接续也算新段）；
- 步序 `attackStepIndex` 每段 +1，**只增不减**。不能用 `comboIndex`：它是 1/2/3/1，
  第 3 段与下一轮第 1 段同奇偶，又回到同一条腿；
- 只有「玩家正在移动」或「本次运行第一次攻击」才对齐 Core 的真实 `gaitPhase` ——
  站着不动时 Core 的相位是冻住的，拿它当基准等于永远同一条腿。

**顺手修的第二个跳变**：`applyStep` 的骨盆偏移（前跨 0.12m / 侧跨 / 下沉）也是按
`swingCurve(p)` 算的，段间取消时 `forth` 从 0.62 掉到 0 → 骨盆**一帧退回 8.7cm**、
下沉 4cm、侧跨方向直接翻号。现在三个偏移量做指数趋近（τ≈85ms），换段变成
0.2 秒的体重转移，单帧 ≤ 3cm。

## 3. 实测（同一套采样：玩家站桩、j 键连点）

| 指标 | 改前 | 改后 |
|---|---|---|
| 段边界腿角单帧跳变 | **0.82 rad** | **0.003 rad** |
| 段边界骨盆单帧位移 | 8.7 cm | 2.9 cm |
| 相邻段起始相位差 | 0 rad（完全相同） | 2.42 rad（≈0.77π） |
| 段内腿角摆幅 | 有（但每段一样） | 每段 > 1.0 rad，且逐段换向 |

三段连击的起始相位：`0.00 → 2.42 → 4.83 → 0.97(≡7.25) → 3.38 → …`
每次都多走 2.42 rad —— 一直在往前，不再回零。

## 4. 踩到的坑

**判据别用「每段腿角峰值符号」。** 我第一版 smoke 断言就是这么写的，结果 1/2 段同号、
假失败：腿角差的幅度包络在 active 段才涨起来（`stride` 随前冲速度变大），
峰值位置会随打击帧漂移，段落被取消的位置不同 → 峰值符号不能代表「哪条腿跨出去」。
真正稳定的量是**段起始相位**：相邻段之差 ∈ `[0.5π, 1.2π]`。

**淡出期相位差不再恒为 0。** v9p 当初把相位改成「往返归零」，部分原因就是
「淡出时相位差一整圈、收势腿抽一下」。现在每段单向推进，combo 结束时累计差可达 π
（3 段 = 3π ≡ π），淡出靠最短弧插值抹平。实测量：静止收招 0.28 rad/帧（且幅度同时衰减），
边走边收招 1.15 rad/帧 —— 但最后这个数字**改前改后完全一样**（来自 `moveTakeover`
与真实步态的交叉淡出，不是本轮引入的）。这一条已写进 `risk-review.md`。
