### v9s.6 · 威胁整形与主动接敌

> 三条接敌语义收敛：① 威胁注视时，**离主威胁越远的加权越低，角色背后的威胁降低**；② **未进威胁状态、但威胁接近时主动进入接敌**；③ **远离威胁一定距离退出威胁状态**。

#### 1. 加权中心整形：越远越轻、背后更轻

原加权是 `proximity × modeWeight (+ 挥砍 boost)`，纯「谁近谁重」，两个问题：

- 侧翼 / 后方一个零散敌人只凭距离就能把加权中心拉平，身体朝一个「谁都不是」的中间方向；
- 背后的敌人和正面的敌人同权，身体会被侧后方牵走。

现在在主威胁选出之后再加两层整形（**只影响加权中心，不改变主威胁是谁**）：

```
eff = w / (1 + spreadFalloff × (|yaw - mainYaw| / π)²)     // 离主威胁方向越远越轻
if (非主威胁 && |yaw - bodyYaw| > behindAngleDeg) eff *= behindFalloff
```

- `spreadFalloff`（默认 `1.5`）：夹角差 π/2 时保留 ≈ 73%，π 时 ≈ 40%；
- `behindFalloff`（默认 `0.35`）、`behindAngleDeg`（默认 `100`）：相对**身体朝向**超过 100° 视为背后；
- **主威胁豁免背后惩罚** —— 被背后偷袭（单威胁）时 `centroidYaw` 仍等于主威胁方向，身体照样整身转过去。

#### 2. 未瞄准也会主动接敌

进入从「瞄准 / 被攻击」两源扩展为三源，新增：

- `reactToApproach`（默认 `true`）：敌对模式单位进入 `approachDist`（默认 **2.5m**）→ 主动进入接敌；
- `hostileModeWeight`（默认 `0.6`）：`modeWeight ≥ 此值` 才算敌对 —— follow `0.8` / keep-distance `0.7` / attack `1.5` 会触发，idle `0.2` / wander `0.45` 不会（站在假人旁边不会被拽得转身）；
- 进入距离是**明确的米制参数**（不是威胁度阈值），贴身 2.5m 才转身戒备。

#### 3. 远离一定距离退出

保持条件简化为 `prevActive && inRecovery`：只要还有任意敌人落在 `recoveryDist`（默认 **3.5m**）内就继续接敌，**全部拉出 3.5m 立即交还身体控制**。`threatRange`（8m）仍是威胁感知 / 瞄准进入的候选范围，`approachDist`（2.5m）管主动接敌的进入、`recoveryDist`（3.5m）管退出，2.5→3.5m 是明确的滞回带。

> **参数修订（v0.9.27 → v0.9.28）**：主动接敌进入 `8m + 威胁度阈值` → `3m` → **2.5m**；退出 `12m` → `5m` → **3.5m**。`approachThreshold` 已被 `approachDist` 取代；`recoveryDist` 改用显式距离判定（不再经近度权重），边界更可预期。

#### 验收

### v9s.7 · 接敌距离收紧 + 受击后 2s 不放下戒备

> 两条收尾：① 主动接敌进入 **2.5m** / 退出 **3.5m**（原 3m / 5m）；② 退出追加条件 —— **最近 2s 内没有被攻击**，刚被打完不立刻卸下姿态。

#### 1. 距离收紧

| 参数 | 旧 | 新 | 作用 |
|---|---|---|---|
| `approachDist` | 3m | **2.5m** | 敌对模式（follow / keep-distance / attack）进入此距离 → 主动接敌 |
| `recoveryDist` | 5m | **3.5m** | 任一敌人仍在此距离内 → 继续保持接敌 |

滞回带从 2m 收窄到 1m：更贴手，也更符合「贴近才戒备、真拉开就走」的直觉。`threatRange`（8m）仍只作威胁感知 / 瞄准进入的候选范围。

#### 2. 受击后 2 秒内不退出

退出不再只看距离，还要看「最近有没有挨打」：

```
hurtGuard = world.time - playerHurt.lastAt < hurtHoldSec     // 默认 2s
hold      = prevActive && (inRecovery || hurtGuard)
```

- **只影响保持、不影响进入** —— 不会因为「刚被打过」就凭空进入接敌；`lastAt` 只出现在 `hold` 里。
- 守卫期间敌人已拉远、`threats` 为空时，沿用上一帧 `mainYaw / centroidYaw`，身体不抖也不误写空表。
- `HurtState.lastAt` 由 `applyHit` 的玩家分支写 `world.time`；未受击用哨兵 `-1e9`（不用 `-Infinity`，保证 JSON 快照往返不丢值）。
- `resetWorld` 把 `lastAt` 复位为哨兵，重新开始不会带着「刚被打过」的保持。

#### 验收

- 新增 `tests/v9s7-gaze-hurt-hold.test.ts` **4 例**：进入后敌人拉到 3.5m 外但刚受击 → 保持、1.9s 仍保持、2.1s 退出 / 同距离未受击 → 立即退出（不改原有滞回语义）/ 未激活时挨打也不会凭空进入 / 完整 `step` 下敌人跑远后 `centroidYaw` 不变、守卫结束自然退出。
- 更新 `v9s3` / `v9s5` / `v9s6` 中依赖旧距离的断言（6m 进入 → 3m 保持 → 4m 退出；follow 3.2m 不进 / 2m 进等）。
- `npx tsc --noEmit`、`npx vitest run`（**45 文件 / 522 例**）、`npm run verify:portable` 全通过；golden snapshot 因 `HurtState.lastAt` 与行为变化按流程 `-u`。
- 线上（Xvfb + Chromium）验收：follow 3m 不进入、2m 进入；2.5m 起手进入后 3m 保持、4m 退出；受击后拉远到 4m 仍保持、满 2s 退出。

### v9s.8 · 摇杆 / 死区 / 转头 / 攻击后滑步

> 四条真机手感：摇杆推满行程减半、技能按钮瞄准死区收紧、切目标转头降速、攻击结束后移动不再滑步。

#### 1. 摇杆满推行程 56 → 28px

`view.joystick.maxRadiusPx` 从 56 减半到 28：同样 28px 的手指位移就到满速（原来是 56px），小屏上不用把拇指推很远。`deadZone`（0.08）不变，仍是归一化后的死区。

#### 2. 技能按钮瞄准死区 26 → 16px

辅助瞄准要「拖出 26px 才算确认」，实际手感像按钮周围有一圈死区。改为：

| 常量 | 旧 | 新 | 作用 |
|---|---|---|---|
| `AIM_SLOP_PX` | 26 | **16** | 拖出 16px 即确认拖拽瞄准 |
| `AIM_EXIT_SLOP_PX` | 16 | **10** | 缩回 10px 内才撤销（迟滞 6px，防阈值附近闪） |
| `GESTURE_SLOP_PX` | 20 | **14** | 按钮手势 drag 判定，仍高于点按抖动 8px |

16px 仍大于 v9i 真机上观测到的 13px 自然抖动，不会回到「点按被当成拖拽」的老问题。

#### 3. 切目标转头降速

`orientation.headTurnRate` 20 → **12**：普通注视（锁定目标 / 拖拽方向）时头部趋近目标的速度降低 40%，切目标不再瞬间甩过去。威胁注视仍走 `gaze.headTurnRate=30`（v9s.4 的要求：头先于身体锁住主威胁），两者互不影响。

#### 4. 攻击结束后移动脚滑

**根因**：`attackGaitDrive` 的等效步幅是 `stride × b²`，`b`（attackBlend）淡出时它趋近 **0**；`solveGait` 拿不到 stride 就退回「摆幅随速度估算」的旧路径，而 Core 的 `gaitPhase` 仍按物理 `c.stride` 推进 —— 两者的步幅不一致，支撑相脚倒退的距离与实际髋部位移对不上，就是滑步。

**修复**：

```
strideTarget = real.speed > 0.05 ? real.stride : 0
stride       = strideTarget + (attackStride - strideTarget) × b²
```

- 玩家**在移动**（攻击结束立刻走）→ `b→0` 时精确回到 `c.stride`，与相位推进严格配套，支撑脚零滑步；
- 玩家**静止**（攻击中 / 收势）→ `b→0` 时仍回 0，保持旧回退路径，避免起手第一帧拿真实步幅把腿一下撑开（单帧跳变）。

#### 验收

- 新增 `v9p-feel` 回归 1 例：移动时 `b=0.35` 的步幅介于真实与放大之间、`b→0` 精确等于真实步幅；静止时仍为 0。
- 更新 `input-aim` 迟滞用例（缩回 8px 撤销）。
- `npx tsc --noEmit`、`npx vitest run`（**45 文件 / 523 例**）、`npm run verify:portable` 全通过；golden snapshot 因配置默认值变化按流程 `-u`。
- 线上（Xvfb + Chromium）验收：`viewConfig.joystick.maxRadiusPx=28`；技能按钮拖 18px 即 `aimActive`、缩回 8px 撤销；头部 0.1s 内转角明显小于旧值；攻击结束立刻移动时下盘步幅与位移一致。

### v9s.9 · 脚下指示半环（选中态 + 威胁染色）

> 去掉「看标签认假人」的旧表达：信息改放到脚下，选中的敌人一眼可辨，颜色直接读出威胁高低。

#### 1. 半环形态

新增 `src/presentation/ground-ring.ts`：贴地环带，默认 **180°** 半环，弧心朝相机侧（屏幕下方）。
两端 alpha 用 `smoothstep` 渐隐到 0（`edgeFade = 0.2`，即两端各 20% 弧长），径向 4 圈剖面
`[0, 0.24, 0.76, 1]` 对应 alpha `[0, 1, 1, 0]`，内 / 外缘同样软边，避免硬切。

几何是自建 `BufferGeometry`：`color` 属性用 **RGBA（itemSize = 4）**，three 会启用顶点 alpha，
所以「角向渐变 + 径向软边」一次烘进顶点，材质只留 `MeshBasicMaterial({ transparent, depthWrite: false, vertexColors })`。

#### 2. 玩家与假人同构

| | 半径 | 弧长 | 透明度 | 颜色 |
|---|---|---|---|---|
| 玩家 | `playerRadius 0.72` | 180° | `0.40` | `playerColor #8fe7ff`（恒定中性） |
| 假人（未选中） | `dummyRadius 0.58` | 180° | `0.40` | 中立冷蓝 / 敌对黄→红 |
| 假人（锁定中） | ×`selectedScale 1.12` | **270°（3/4 环）** | **`selectedOpacity 0.30`** | 同上 |

选中的环带 1.5% 的呼吸（`sin(world.time × 2.2 + id)`），避免完全静态。
弧长变化时才重建几何（约 1KB），透明度 / 颜色 / 缩放 / 朝向都是每帧写材质与 transform。

#### 3. 去掉头顶标签

`dummy-rig.ts` 删除 `SpriteMaterial` + 5 张预生成 `CanvasTexture`（v9s.5 为「切换不卡」做的缓存一并移除）
与模式纹理切换；`DummyViewConfig.labelBg`、`config.view.dummies.labelBg` 同步删除。
点假人仍会切模式，反馈保留为一次 0.45s 的自身高亮（`flash`，原本就与标签独立）。

#### 4. 颜色 = 威胁读数

Core 新增两个纯函数（`gaze.ts`，随 `core/index.ts` 导出，可移植、无 DOM）：

```ts
isHostileDummy(world, d)   // modeWeight ≥ hostileModeWeight（follow / keep-distance / attack）
dummyThreatLevel(world, d) // prox × modeWeight + active 帧 attackBoost，以近距攻击为满值
```

口径与威胁注视 / 智能相机完全一致，所以「环变红」与「身体转过去戒备」是同一个威胁判断，不会各说各话。
映射：中立 → `neutralColor`；敌对 → `lowThreatColor #ffc85a` 按 level 线性插值到 `highThreatColor #ff3b30`
（近、attack、挥砍 active 帧最红；远处 / 游走单位偏黄甚至回到中立色）。

#### 验收

- 新增 `tests/v9s9-ground-ring.test.ts` **9 例**：中立不敌对 / 距离越近读数越高 / active 满值 / 超范围与模块关闭为 0；
  几何两端 alpha 归零、中段满值、径向软边；半环端点落在 ±X、3/4 环端点转到 ±135°；`update` 的弧长重建、透明度、缩放、染色。
- `npx tsc --noEmit`、`npx vitest run`（**46 文件 / 532 例**）、`npm run verify:portable` 全通过。
- 线上（Xvfb + Chromium）验收：玩家脚下半环朝屏幕下方；三个假人分别呈冷蓝 / 黄 / 橙红；锁定目标变 3/4 环且更淡、更大；移动中的假人环贴脚无滞后；无 pageerror。

### v9s.10 · 环尺寸随体型 / 选中表达 / 玩家环接敌状态

> 三个问题一起收：环偏大、选中不明显、玩家环除了「我在哪」还没承担信息。

#### 1. 尺寸跟角色走，不再写死米数

```ts
groundRingRadius(bodyWidth, factor) = bodyWidth × 0.5 × factor
```

| 项 | 旧（米） | 新（按 `bodyWidth 0.46` 推导） |
|---|---|---|
| 玩家环半径 | 0.72 | `0.46 × 0.5 × 2.3` = **0.53** |
| 假人环半径 | 0.58 | `0.46 × 0.5 × 2.05` = **0.47** |
| 环带宽度 | 0.075 | `0.46 × 0.16` = **0.074** |

直径从「约 3 倍身宽」收到 **约 2.3 倍**（脚掌外一圈），改体型 / 换角色时自动跟着缩放。

#### 2. 选中：加厚 + 提亮 + 外发光

旧版「选中透明度降低」字面是变淡，和「选中要明显」互相抵消。现在改成：

| | 未选中 | 选中 |
|---|---|---|
| 弧长 | 180° | **270°** |
| 环带厚度 | 1× | **1.6×** |
| 透明度 | 0.30 | **0.62** |
| 外发光 | 无 | **同色 halo**（半径 1.16×、厚度 2.6×、0.14） |
| 缩放 | 1 | 1.06 ×（含 2% 呼吸） |

未选中环同时从 0.40 降到 0.30，四个假人常驻时不抢眼；选中一口气拉出 2 倍亮度差 + 厚度差 + 一圈光晕。

#### 3. 玩家环 = 接敌状态

复用 Core 已有的 `gaze.active / gaze.threat` 与 `playerHurt.lastAt`，表现层只读：

```
未接敌：180° 半环，青白 #8fe7ff，opacity 0.44
接敌　：弧长 180° → 270°（按 threat 渐进）
　　　　颜色 青白 → 黄 #ffc85a → 红 #ff3b30
　　　　opacity 0.44 → 0.64+，呼吸 4 → 8Hz
受击守卫期（hurtHoldSec 内）：额外闪烁，表达「还没放下戒备」
```

解算抽成纯函数 `playerRingVisual(active, threat, guardRatio, time, cfg)` 与 `threatRingColor(...)`，
不碰 three 对象，可直接单测。

> **为什么没做「环上指向主威胁的扇区」**：2.5D 俯视下，指向远处（屏幕上方）的地面标记会整段被角色本体挡住，实测几乎看不见；
> 方向交给「头 / 身体转向主威胁」表达更有效。真正需要屏幕方向提示时，应做**屏幕边缘箭头**（见下节扩展方向）。
