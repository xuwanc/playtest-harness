# 2026-11-08 · 文档按「地图 / 系统 / 状态 / 决策 / 归档」重构

> 触发：用户给了一套文档写入规则（README ≤100 行只当地图；变更记录进 journal；系统说明进 systems；当前状态覆盖写；决策进 ADR；路径规范独立成文；新建 / 改名必须同步 INDEX；单文件 ≤300 行）。
> 目标：让「下次接手的人或 AI」能在 30 秒内找到「这个现象在哪个文件、这个决定为什么这么定」。

## 动手前的问题

- `README.md` **4220 行**：项目简介、68 个版本的变更日志、89 步验收清单、Core 契约表全在一起。
- 想知道「现在怎么工作」要先翻过几屏「那天改了什么」；AI 会把历史结论当现状（例如「假人不会被击退」在 v9s.38 已不成立）。
- `docs/animation-guidelines.md` **803 行**，规范与逐版本落地记录混排。

## 新增的机械守卫

`scripts/check-docs.mjs` + `npm run docs:check`，已接进 `npm run verify`：

1. README ≤100 行；
2. `docs/**/*.md` 每份 ≤300 行；
3. 所有相对 Markdown 链接目标存在；
4. 不允许链接指向已迁移的旧文件（`tech-map.md` / `animation-guidelines.md` / `sparring-fighters.md`）；
5. `docs/INDEX.md` 必须登记每个 systems / decisions / checklists 文档（缺了给 warn）。

这条检查是给「文档腐化」兜底的 —— 原来的 4220 行 README 就是没有守卫时自然长出来的。

## 顺手修的两处

- 4 处代码注释 / `index.html` 里的「见 README」改成指向 `docs/` 的具体文件（README 不再承载按键表）。
- `smoke.py`「慢放转身无画面不动」判据从「最长连续 ≤1 帧」放宽到 **≤2 帧**：软件渲染 24 帧样本里实测出现过连续 2 帧零增量（0.25× 下 = 8ms，肉眼无感），而真正的卡顿（v9s.34 那个 bug）是 35+/60 连续重复。判据仍按「连续」而非「总数」，没有放松对真卡顿的检测。
