# 2026-11-09 · 蜘蛛 v3：简化 / 步幅 / 惯性，顺手造了造型工坊

v9s.51 / v0.9.72。三条手感反馈 + 一个工具需求，一轮做完。

## 来龙去脉

蜘蛛主角上线后（v9s.50 / v0.9.71）用户试了手感，回了三句话：

> 1. 简化些模型，步幅有点小，身体加点惯性
> 2. 要不做一个方便你生成方盒子角色的小工具？

第 2 条其实解决了第 1 条的一半 —— 造型的问题**在游戏截图里看不出来**，
因为第三人称相机固定 2.5D 俯角。先造工具，再用工具改造型。

## 工坊先跑起来，然后它立刻抓到两个老 bug

`tools/voxel-forge/`：JSON spec → 3D 预览（自由 yaw/pitch/距离）→ 导出 TS 片段。
380 行纯浏览器 ES module，不参与构建、不进 dist。

第一次把蜘蛛身体放进去、从**侧面**看，两个 v9s.50 就存在但被视角掩盖的问题当场暴露：

| 问题 | 游戏截图里 | 工坊侧视图 |
|---|---|---|
| 8 只眼的 z 全在甲壳前立面之外（0.15~0.226 vs 半深 0.114） | 看着像贴在头上 | 8 个红点飘在头前面 4~11 cm |
| 头胸甲与腹部同高 | 像一根长条盒子 | 两节等高，中间没有「腰」 |

修法：眼收到 `z 0.098~0.110` 贴住前立面；腹部整体抬高 0.055 + 后移 0.03，
腹柄落在两节之间的缝里。副作用是**腿根露出来了**（腹部底 0.328 > 髋 0.318），
之前后腿的股节是被腹部包住的。

## 简化：128 个 mesh → 35

合并的判据不是「看起来像一坨」，而是**会不会相对运动**：

- 股节的三段永远一起动 → 合并；
- 髋 / 股 / 胫 / 跗四级会相对转 → 一级一个 mesh。

难度在于合并后只能整块同色，8 层腹部的渐变会糊掉。解法是把颜色写进**顶点色**：
一个 Lambert 材质吃全部顶点色，不同颜色的盒子也能合进同一个 mesh。

踩了一个坑：`Color.setStyle()` 在 r152+ 已经按 `ColorManagement` 把 sRGB 转到工作空间，
我又补了一次 `convertSRGBToLinear()`，整只蜘蛛暗了三分之一。删掉那次转换就好了。

顺带删掉背线 —— 只有把相机拉到 1.5 m 才看得见，却要多一个 mesh、多一组几何。

## 步幅：0.45 → 0.66，是算出来的

第 4 对腿静止落点距髋 0.504 m、腿长 0.929 m、髋高 0.318 m：

```
水平余量 = √(0.929² − 0.318²) − 0.504 = 0.369 m
前伸量   = stride × duty = 0.55 × stride
→ stride ≤ 0.67
```

取 0.66，把余量吃到 98%。配套：

- 腿长 +8%、落点 +10%（**同时**改，否则腿会全弯在身体底下，俯视时被背甲整块盖住 ——
  中间试过只加长腿，8 条腿在截图里直接「消失」了）；
- `strideRatio` 0.34 → 0.62；
- `CAP_HZ` 7.5 → 6.4。

结果：2.6 m/s 从 5.8 Hz 降到 4.2 Hz，冲刺脚滑从 24% 降到 12%。

## 惯性：二阶弹簧，不是 lerp

```ts
const a = omega * omega * (target - x) - 2 * omega * v;
v += a * dt;
x += v * dt;
```

差别只在 `v`。目标突变时它会**冲过头再回来** —— 急停时身体先往前栽一下再收回，
那一下是全部重量感的来源；`lerp` 只有指数逼近，看起来像橡皮筋。

四个量：`pitch`（9）、`roll`（8）、`leanZ`（7）、腹部甩动（5）。
加速度要先低通（`1 − exp(−dt × 18)`）：Core 的 `velocity` 在碰撞 / 翻滚 / 传送那几帧会跳变，
不滤的话弹簧被一帧的 400 m/s² 直接打飞。

顺序也重要：**先算惯性、把 body 变换写进矩阵、再解腿**。反过来 IK 会用上一帧的髋位置，
急停时能看到脚慢半拍补位。

## 线上核验时抓到的第四个坑：相位不能按 `velocity × dt`

发布后在线上量到 `reach 1.58 / clamp 4`（脚离髋 1.47 m，腿只有 0.93 m）。
单测 60 fps 下恒为 0，说明不是解算错。

根因：`dt` 在 `update` 里被截断到 1/20（低帧率下弹簧才稳），而 Core 按**真实**帧间隔积分。
无头 Chromium 掉到 8~20 fps 时，真实帧间隔 0.12 s，rig 只按 0.05 s 推进相位 ——
每帧少推 60%，脚越落越远，没有上界。

改成读**本帧实际位移**（`moved / dt`），相位与「身体走了多远」严格同源，
超步频上限的部分照旧转成脚滑。顺带给传送加了保护（单帧 > 0.8 m 视为传送，
本帧不推进相位）——否则工位跳转会把相位在一帧里跳几十个周期。
20 fps 下峰值从 1.58 降到 1.1，60 fps 下为 0。
