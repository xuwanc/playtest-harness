# 站姿换成斜跨，起手收招接回待机，剑盾重新打一遍

2026-11-10 · v9s.55 / v0.9.76

## 需求

> 1.现在可以优化一波动画，idle 可以支持斜跨站立，停步直接接斜挎，看那只脚先踩出去
> 2.之前做的动画起始和结束 Pose 都没有很好，和待机都接不上
> 3.剑盾攻击整体看上去没舒展开

三件事，各自都有独立的成因，最后一件其实不是「幅度不够」而是「打法错了」。

## 一、斜跨：前脚必须是最后踩出去的那只

旧版停步是「把刚踩出去的脚收回来并拢」。这句描述本身就是 bug —— 玩家看到的是
「最后一步被撤了」。新做法是在**进入停步那一帧**把前脚锁死：

```ts
idleFrontLeft = leadFootIsLeft(c.gaitPhase, plantLock);
```

判据与停步惯性共用 `footOffset(phase) > 0`。这一条一致性是硬要求：两处判据不同时，
会出现「惯性把左脚踩出去、斜跨却把右脚留在前面」，脚在原地打个对调。

三条「不写」是这次的核心约束：

| 不写 | 会怎样 |
|---|---|
| `pelvisX/Y` | 腿是 FK 挂在下盘上的，搬骨盆**连脚一起搬**：穿地或整体滑步 |
| 膝角 | 屈膝是 `sink` + 足部 IK 反解算出来的，再写一遍脚就离地 |
| 手臂通道 | 垂手 / 持械角归 `weaponStance`，站姿不该抢 |

所以 `sink` / `shift` 从解算里单独返回，由骨架层在 `captureIKBase` **之后**叠加 ——
和 `kneeSink`、停步惯性、跨步层完全同一套机制。

**第一版看不出斜跨**：只加了前后脚角度，正面看仍是「正对前方的两脚前后站」。
补上 `hipYaw`（只转下半身、胸口仍朝目标）之后才读得出来 —— 这是格斗站姿，
不是把整个人侧过去。参数从 0.16/0.14 rad 一路加到 0.16 `hipYaw` + 0.05 `pelvisRoll`
+ 0.06 `torsoLean` + 3cm 侧移，才有「重心压在一条腿上」的重量。

代价：斜跨会污染 11 个「关掉后必须精确归零」的对照用例（受击 / 落地 / 攻击下盘）。
它们统一在 `tests/mech-gait.ts` 里用 `GAIT_NO_IDLE` 关掉，否则测的就不是原来的契约。

## 二、起手 / 收招：三条独立的错，缺一条都接不上

### 2.1 采样点会倒退

旧链路 `swing ∈ [−1,1] → u = (swing+1)/2`。收势时 `swing` 从 +1 掉到 0，`u` 就从
**1（挥出满）退回 0.5（挥到中途）**，再从这个半挥姿态淡出 —— 而且 `settle` 把它定格 0.16s。
难怪「收招停在半挥」。

改成按阶段取 `u`：蓄势 `0`、active 前 70% `0→1`、之后保持 `1`。

### 2.2 淡入淡出与动作无关

旧版写死「淡入 0.1s / 淡出 0.16s」。剑盾 windup 只有 0.11s（整个起手都在混合里，
走不到蓄势帧），大剑 windup 0.16s 却只给 0.1s（1.5 rad 压进 6 帧 = 啪一下抬手）。
现在起手 = `max(poseIn, windup × 0.75)`、收招 = `max(poseOut, (recovery + settle/2) × 0.85)`：

| 武器 | 起手 | 收招 |
|---|---|---|
| 剑盾 | 0.100s | 0.298s |
| 双持 | 0.100s | 0.221s |
| 大剑 | 0.120s | 0.374s |

起手只占 windup 的 75%，剩下 1/4 停在蓄势帧上，「抬手 → 定住 → 挥出」才有节奏。

### 2.3 剑身根本没进混合（最隐蔽）

手臂 / 躯干走 `blendCombatPose(w)`，但剑身仰角、外撇、滚转、以及 `rootYaw` 是直接写
绝对值的。权重掉到 0.05 时它们还是满值，`w` 归零那一帧一步跳回待机：

| 武器 | 修前 | 修后 |
|---|---|---|
| 剑盾 | **68.3°** | 3.0° |
| 大剑 | 30.6° | 3.5° |
| 双持 | 62.6° | 4.5° |

这条是被探针抓出来的，截图看不出来 —— 因为 68° 只持续一帧，而截图在软件渲染下
3 秒一张。用 `tools/probe-entry.py` 逐帧读 `bladesWorld()` 的方向才看见。

判据也因此换了：不能看「整段最大单帧转角」（挥出段本身就有 60~70°/帧），
要看「交还那一帧相对邻帧的突跳」。

## 三、剑盾：不是幅度不够，是拿大剑的打法缩小了用

`weaponScale` 原来给剑盾 0.78，把双手武器的手臂角度直接缩到 0.78 —— 结果扫角只有
131°/121°，读起来是「举着剑转了个身」。

单手剑的弧线**不能靠身体带转**：bodyYaw ±0.78、rootYaw ±0.52 时剑会扫到身后 1.6m，
画面上根本看不见。第一版就是这么废掉的。正确的分工是：

- 身体只让 0.55 rad（约 31°），整体带转 0.30~0.35；
- 弧线由**肩打开 + 手臂横过身体**出：`armYaw` 同侧 → 反向，`elbow` 从 −0.95 伸到 −0.08；
- 盾臂必须由数据接管（`armLPitch` / `elbowL` 写进剪辑），否则盾交还步态摆臂，
  挥剑时在身侧乱甩。

结果：扫角 **200.5° / 182.6°**，刃身仰角 ±19°（clip-lab 的 t ∈ 0.15~0.95 判据）。
`weaponScale` 回到 1.0，`combo['sword-shield']` 指向自己的 `ss.right-left` / `ss.left-right`。
