# 2026-11-10 · 断肢 / 倒杆物理 / 仙人掌三修（v9s.60）

两条需求：① 击杀时按最后一击决定怎么断，倒下用一点物理、到位后关掉；② 仙人掌太丑、
砍不到、能穿过去，工位合并散开。第 ② 条里「砍不到」查出来是**两个独立 bug**。

## 一、断肢：判定在 Core，切断在表现层

`decideSever(type, u, dx, dz, bodyYaw, weapon)` 是纯函数，输入只有「这一击是怎么打的」：

| 受击类型 | 高位 | 中位 | 低位 |
|---|---|---|---|
| `light` | — | `reach ≥ 0.52` 断持械臂 | **不断** |
| `heavy` | `≥ 0.80` 断头 | `≥ 0.56` 断臂 | 腰斩 |
| `knock`（含击地） | `≥ 0.78` 断头 | `≥ 0.36` 腰斩 | 断腿 |

`reach = u + (weapon === 'greatsword' ? 0.06 : 0)`；左右由
`side = dx·cos(bodyYaw) − dz·sin(bodyYaw)` 的符号决定，`side ≥ 0` 断右肢。

**为什么不是随机**：它进 determinism 快照。加一个 `random()`，同一次击杀在不同机器上
断不同处，golden hash 每次都变 —— 这类「表演性质」的判定最容易被写成随机，必须挡住。

**为什么轻击不断头**：一刀掉头不合理，而且每刀都肢解会很快失去信息量。
轻击只削手臂高度（`u ≥ 0.52`）—— 匕首削手合理，匕首断腿不合理。

**为什么能一次喂两个系统**：`killDummy` 里写 `h.sever = { part, u, dx, dz, power }`，
表现层同时读它决定「断哪一段」和「往哪边倒」。分成两套就会看到「头掉了但身体往后倒」。

实现是 **clone + 隐藏**，不是摘节点：`clone(true)` 后 `matrix.copy(node.matrixWorld)` →
`decompose` → `scene.add` 到世界坐标做自由落体；原节点只 `visible = false`。
摘走节点的话，重生时得重建整套骨架（还得分左右、还得记住原父节点）。

## 二、倒下：从插值曲线换成倒杆

旧版是一条「0→1 缓动 × 固定前倾角」的曲线，所有尸体一个姿势、同一个方向。

```
θ'' = gravity·sin θ − damping·θ'
```

- 绕**水平轴** `(dirZ, 0, −dirX)` 转 —— 垂直于来击方向，从侧面砍就往侧面倒；
  用身体局部 X 轴的话，不管从哪砍都是往前扑。
- 初角速度 `kickBase + kickGain × power`，`power` 就是断肢那里算的同一个值。
- 触地（`θ = fallDeg`）时 `θ' = −θ' × bounce`；`|θ'| < restVel` 且躺平 →
  `settled = true`，**物理彻底关掉**，只保留四元数。用户要的就是「到位后关掉」。
- 另有一条 `slideX/slideZ` 滑行，`slideDamp` 衰减 —— 被大剑打飞的尸体会滑一段。

参数在 `config/game.json` 的 `view.dummies.death.physics`，关掉 `enabled` 就回到旧曲线。

## 三、仙人掌造型：分段 + 收腰 + 明暗

旧版是「一根方柱 + 两条直角横杆」，两个问题一眼看出：柱子没有粗细变化（不像仙人掌）、
横杆是 90° 直角（像晾衣架）。

新版主干 6 段，宽度 `w = R × (0.84 + 0.26·sin(π·t))` 收腰；**奇数段用 `darkMat`
（本色 × 0.82）**，靠明暗差读出「一节一节」；每段带轻微错位旋转，避免看起来是一根光柱。
侧臂是「水平段 → 上扬段 → 圆头」三段折线，不是直角。断块同理：`kind === 'cactus'` 时
按 5 段渲染 + 顶端一张浅色断口薄片。

## 四、「砍不到」是两个 bug 叠在一起

1. **`computeHits` 里有 `break`**：一刀只处理第一个命中的物件。两株并排的仙人掌，
   永远只有一株会断。去掉 `break`，改成按 `dist − r` 取最近轴。
2. **闸门差一帧**：表现层在 `render` 采样 `currentMeleeShape`，`step` 下一帧才消费。
   挥砍正好在这一帧结束时关闭形状，整批候选被 `if (!shape.active) return` 丢掉。
   加 `world.meleeGatePrev` 只放行**一个 tick**（下一帧立刻清掉）。

第 2 条尤其阴：肉眼看是「有时砍不到」，实际是「某些帧序下砍不到」，跟位置、角度都无关。

另外旧版只按**主干竖轴**求最近距离，侧臂伸出去 0.7m 却没有判定轴 —— 砍在侧臂上必然落空。
`hitSegments(st)` 现在给每条侧臂生成「水平段 + 上扬段」两条线段，一刀扫过取最近的那条。

## 五、「穿过去」：可破坏物没有碰撞盒

`dest-<id>` 的 `kind: 'obstacle'` AABB 进 `world.boxes`，高度跟着站立段走：

```ts
box.maxY = gone ? box.minY : st.y + st.standU * st.height;
```

**必须是原地改 `maxY`，不能 `filter` 重建数组** —— `boxes` 被移动、相机、贴地特效共享
引用，替换数组会让它们继续读上一帧的旧对象（表现为「刚砍断还能撞一下」）。

实测：玩家从 `z = 36.65` 一路按前进走 140 帧，停在 `z = 34.27`（仙人掌 33.65，半径和 0.6）。

## 六、工位合并

`zz-cactus-test` 删掉，9 件并进 `x-destructibles`：旗杆 ×3 / 罐子 ×2 / 仙人掌 ×2（`±2.15`
散开）/ 按钮 ×2（`targetId` 指向两株仙人掌）。

第一次把 `span` 从 `[2,2]` 改成 `[3,3]`，auto 布局把别的工位推到了假人测试位置，
smoke 的「踱步是大步」「攻击能命中」「真机挥刀能打断」三项直接挂。改回 `[2,2]`、
`radius` 放到 3.0，坐标重排后 **53/53 恢复**。地块 `span` 是全局槽位，动它等于动别人的位置。
