# 2026-11-09 · v9s.44 朝向切换时，下盘不再自己拧

## 用户说了什么

> 「朝向切换时，下盘会整体晃下，好像和 movedir 的切换有关」

## 先量，再动手

写了个探针：速度方向固定（一直往 −Z 跑），在 0.5s 内把 `bodyYaw` 扫 180°（等价于
「锁定目标切换 / 攻击锁朝向 / 拖拽瞄准」这类朝向切换）。逐帧记录 `hipYaw`：

```
帧   身体朝向    下盘偏转
 0     1°        +0
 6    25°        −3
 9    47°        −20      ← 已经反向了
12    72°        −23      ← 最深
15    99°        +10      ← 又翻回正
18   125°        +24      ← 峰值
30   180°         0
```

单帧最大 13.5°（810°/s），整条 S 的摆幅 57°，反向过冲 −32°。而正常跨步单帧只有
0.53 rad（30°）。这就是「下盘整体晃一下」。

## 根因：下盘偏转目标有两个「族」

`backHipYawTarget` 在 θ（身体局部移动方向）超过 100° 之后，从「侧移带转」切到
「θ − 180°」（v9s.14 为了让倒退走的脚踩得住地面）。两族在同一角度上差得极远：

| θ | 侧移族 | 后退族 |
|---|---|---|
| 90° | +50° | −90° |
| 112° | +44° | −68° |
| 132° | +31° | −48° |

身体转动时 θ 连续扫过这段，目标只能「跳族」：θ = 99° 时 +49°，θ = 112° 已经 −24°，
实测单帧跳 52.7°。输出那层指数平滑（12/s）是连续的，但追不上 52.7°/帧的目标。

## 修法：身体自己在转的时候，胯不自己拧

用一个「转身闸门」把两件事一起关掉：

```ts
const hipRate  = gaitCfg.hipYawTrackRateDeg * DEG;        // 默认 200°/s
const spinGate = hipRate > 0 ? turnSpinGate(turnRate) : 0; // 30°/s 起、100°/s 满

backHipYawTarget(lf, lr, strafeYaw, backKeep, spinGate);  // ① 转身时停在侧移族
slewHipTarget(lastHipYawTarget, raw, hipRate, dt, spinGate); // ② 目标限速（纯转身时冻住）
```

`turnRate` 取**未平滑**的 `wrapAngle(bodyYaw - prevBodyYaw) / dt`。`hipYawTrackRateDeg = 0`
时两层一起关，精确回到旧行为（面板滑杆可实时 A/B）。

| 0.5s 转 180° | 旧 | 新 |
|---|---|---|
| 单帧最大变化 | 13.5° | 0.1° |
| 整体摆幅 | 57° | 0.5° |
| 反向过冲 | −32° | −0.5° |

## 踩到的坑（都是量出来的）

1. **一刀切限速会打坏 v9s.43**。世界速度本身换向时（摇杆前推 → 后拉、身体朝敌人不动），
   θ 一瞬间翻 180°，下盘必须全速跟：腿的摆动轴就是下盘前后轴。无条件套 200°/s 时，
   v9s43 的「换向不抽腿」实测从 0.55 掉到 0.63 rad（越过「正常跨步」这条线），
   smoke 也跟着红。→ 限速必须按**身体角速度**门控。
2. **只冻目标、不冻输出**。闸门一松，目标会因为 `free = 1` 一步跳到位（rate ≈ 3400°/s）；
   留下 `hipYaw` 那层 12/s 的平滑，正好把它摊成 ~0.2s 的追赶。连平滑一起冻住会看到
   「转完卡一下再瞬间到位」。
3. **闸门开关处要有连续点**。θ = 180°（纯后退）时两族都是 0°，所以最常用的那条路径
   开关无跳变；真正的跳变只在 100°~180° 的斜后方，由节流兜住。
4. **smoke 的「每步跳变」判据会被采样相位带偏**。软件渲染 ~13fps，一个 rAF 覆盖
   4~5 个固定步，`|Δd| / steps` 的峰值随「采样点落在步态曲线的哪儿」浮动（同一次
   构建连跑三次能读到 0.49 / 0.59 / 1.02）。这不是换向的问题，是判据本身不稳。
   改成**同一次采样内的相对判据**：先用两端 `dirF` 都满值的样本量出「正常跨步」基线
   （0.49~0.59），判 `worst ≤ max(0.62, 基线 × 1.3)`。mirror 会到 2 rad+，仍然拦得住。
5. **既有用例的前提要跟着改**。v9s43 里「换向后 dirF 一定到 −1」这条，在有假人的
   世界里其实是在测「注视把身体拖着转」的轨迹；现在下盘回落慢一点，它就漂了。
   改成把 `bodyYaw` 钉住（纯原地倒走），判据变成「窗口内到达过 −1」，语义才回到
   「符号被逐帧推进，不是冻住」。
