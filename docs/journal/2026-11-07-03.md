### v9s.11 · 环上的信息层：起手预警 / 进度弧 / 范围预览

> 上一轮把环做「好看」，这一轮让它开始「说话」。原则：**一个环只承载一层语义**，
> 多层信息用同心环叠，每层独立 mesh + 独立纯函数，而不是往同一个材质上堆颜色和闪烁。

#### 1. 敌人起手预警（假人）

| | 表现 |
|---|---|
| 触发 | `attackPhase === 'windup'`（`active` / `recovery` 立即熄灭，避免和受击闪红混淆） |
| 预警弧 | 半径 ×1.14（落在主环外侧，不重叠）、厚度 ×1.5、红色 `#ff5a4a` |
| 填充 | 按 `attackPhaseTimer / attackWindup` 从左往右填满 → **满格就是命中帧** |
| 主环 | 同步压向警示红（`lerp(warnColor, 0.5 × urgency)`），透明度随紧迫度提高 |

#### 2. 玩家进度弧（蓄力 / 引导 / 冷却）

主环外侧 1.34× 一圈细弧，数据源按操作紧迫度排优先级：

```
蓄力（剑 / 弓）  → ratio = combat.charge            色 #ffd166 黄
引导（法杖）      → ratio = 1 - fireTimer/interval   色 #b48cff 紫
冲刺 / 闪现冷却   → ratio = 1 - cooldown/cooldownMax 色 #7fb8d8 青
```

同一帧只表达一个意图。冷却只在剩冷却时出现，不会变成常驻噪音。

#### 3. 范围预览（AoE / 冲锋落点）

- **电环**：从一条细 `RingGeometry` 升级为「内部柔光填充（径向衰减 26%）+ 外圈边界呼吸」；
  边界亮度随剩余寿命衰减，剩余时间可直接读。
- **冲锋落点**：派生招 `windup` 阶段在 `起点 + 朝向 × travel` 画青白落点圈，
  半径取招式 `hit.radius`。刻意用玩家色系 —— 红色会被读成「敌人的危险范围」。

#### 4. 选中切换：从「开关」改成「缓动」

旧版选中是**一帧内换几何**：弧长 180°→270°、厚度 1.6×、光晕 0→0.14 全是硬切。
现在主环形态与光晕共用一条指数缓动：

```ts
selMix  += (target - selMix) * (1 - exp(-dt / τ))     // 淡入 τ=0.14s，淡出 τ=0.36s
arc      = 180° + 90° × selMix
thickness= 1 + 0.6 × selMix
opacity  = 0.30 + 0.32 × selMix
halo     = 0.14 × haloMix,  scale = 1.06 × (0.94 + 0.06 × haloMix)
```

光晕径向剖面从「环带（内外 0、中间 1）」换成**高斯 7 圈**，边缘没有硬边；
淡出比淡入慢 2.5 倍、半径同步收缩，读起来是「光慢慢收回去」而不是一盏灯被关掉。

> 几何缓存：弧长 / 厚度连续变化后，档位量化到 1.8° 与 0.05 厚度并按档缓存（上限 64 个，
> 超出释放未使用的最旧档），选中过渡只换指针，不产生运行时顶点上传。

### v9s.12 · 环的四处手感修正

> 上一轮把信息装进环里，这一轮修的是「它活在场景里的方式」——高度、亮灭节奏、出现方式、以及引导的移动负担。

#### 1. 环贴地，不跟人上天

```ts
ringGroundHeight(grounded, y, lastGroundY) = grounded ? y : lastGroundY
```

只在**落地帧**刷新脚下高度：跳起来时环留在最后落脚的地面上（不再被抬到脚底一起飞），
但走上台阶 / 箱子时环仍会跟着地面抬起来 —— 这是「贴地」而不是「锁死 y=0」。

#### 2. 选中：快亮、慢降、未选中更安静

| | 旧 | 新 |
|---|---|---|
| 淡入 τ | 0.14s | **0.05s**（≈0.15s 到 95%，点谁谁立刻亮） |
| 淡出 τ | 0.36s | 0.36s（不变，失去选择慢慢降） |
| 未选中 opacity | 0.30 | **0.22** |
| 选中 : 未选中 亮度比 | 2.1× | **2.8×** |

非对称缓动是刻意的：**响应要快、消失要慢**。选中是玩家的操作意图，必须立即确认；
取消选中是状态回收，慢一点反而显得光在「退场」而不是被掐断。

#### 3. 电圈从角色中心展开

```ts
areaOpen(age, expandSec) → { scale: 0.06 → 1 (easeOutCubic), alpha: 0 → 1 }
```

电环放置点就是角色中心，表现层按已存在时长把半径从 6% 推到 100%（0.22s），透明度同步淡入。
**只缩放 mesh，不改 Core 的命中半径** —— 视觉展开不能影响判定，否则会出现「圈还没到就打中」。

#### 4. 引导时移速降到 0.6×

法杖引导原本 `moveScale = 0.82`（几乎感觉不到），改为 **0.6**：
可以走位引导，但要为「持续输出」付出明显的机动代价。实测平地 3.99 m/s → 2.39 m/s。

#### 验收

- 新增 `tests/v9s12-ring-feel.test.ts` **13 例**：展开包络的起点 / 终点 / 单调性 / 零时长防除零、
  贴地高度在落地 / 空中两种取值、淡入快于淡出、未选中更淡且对比 ≥2×、引导移速区间。
- `tsc` / `vitest`（**49 文件 / 577 例**）/ `verify:portable` 全通过；golden 快照因 `moveScale` 变更同步更新。
- 线上实测徽标 `v0.9.33`：跳跃时环留在地面、选中即时亮起、未选中更淡、电圈由中心展开、引导移速 0.6×、无 pageerror。

### v9s.13 · 侧后方改走后退步态

> 反馈：角色向侧后方移动时不要走前进模式，腿斜拉的不好看，用后退适配。

#### 为什么会「斜拉」

`solveGait` 一直按「速度在身体局部的两轴分量」混合：

```
wF = |localForward| / (|f| + |r|)     wS = |localRight| / (|f| + |r|)
footZ = dirF · wF · halfStride · off  （前后摆）
footX = dirR · wS · halfStride · sideWeight · off  （左右摆）
```

正前方 / 纯侧移都只看一个轴，所以没问题；但侧后方（夹角 ≈135°）时两轴各占一半，
**脚走对角线，而膝盖只能绕 X 弯** —— 膝盖平面跟不上脚的轨迹，两腿就像被斜着拽开。

#### 改法：把侧向权重并入前后轴

```ts
backKeep = backStrafeKeep(localForward / speed, 100°, 132°)   // 1 → 0 平滑过渡
wS = (ar / sum) × backKeep
wF = (af / sum) + (ar / sum) × (1 − backKeep)                 // 转移，不是丢权重
```

- **夹角 < 100°**：`backKeep = 1`，与旧行为逐帧一致（侧前方 45°、纯侧移 90° 不变）；
- **100° → 132°**：smoothstep 过渡，两端导数为 0，摇杆在侧后方缓慢划动不会突跳；
- **> 132°**：`backKeep = 0`，全幅前后摆 + `dirF = -1` = 纯后退走，膝盖正对身体前向。

下盘的侧移偏转（`strafeHipYaw`）乘同一个系数：侧后方不再朝移动方向带转 ——
否则「已经按后退摆腿」再让下盘转一半，脚会沿一条偏斜的前向轴走，等于把斜拉换成斜退。

#### 实测（线上 harness 数值）

| 移动方向（相对身体） | 下盘偏转 hipYaw 峰值 | 步态 |
|---|---|---|
| 纯侧移 90° | **0.879 rad**（≈50°） | 侧步 + 交叉步，不变 |
| 侧后方 135° | **0.000 rad** | 纯后退摆腿，膝盖正对前方 |

> **已知代价**：侧后方时脚的前后摆幅按全速走，而身体的实际位移是斜的 —— 横向那一部分
> 没有脚补偿，会有约 `sin(45°) × 速度` 的侧向滑移。想更保守可把 `backStrafeStartDeg`
> 调大（保留更多侧向补偿、但腿又会开始斜），两者在纯 FK 下不可兼得；根治需要「膝盖朝向
> 跟随移动方向」（每条腿独立 yaw 或全身转向），留待以后。

#### 验收

- 新增 `tests/v9s13-back-gait.test.ts` **11 例**：门限单调性与 1° 步进连续性、参数异常退化、
  135° 时 backward≈1 / strafe≈0 / roll < pitch×0.12、45° 与 90° 不受影响、
  真实骨架（`createVoxelRig`）侧后方 hipYaw≈0 且 legRoll≈0、纯侧移 hipYaw > 0.25。
- `tsc` / `vitest`（**50 文件 / 588 例**）/ `verify:portable` 全通过。
- 三处既有「纯侧移」用例改用 `makeQuietWorld()` 隔离威胁注视（注视会把身体转向假人，
  移动相对身体变成侧后方 → 按新规则走后退步，那是新语义而非回归）。
- 线上徽标 `v0.9.34`，无 pageerror。

### v9s.14 · 下盘修正方向翻转：把轴真正对到移动方向

> 反馈：v9s.13 不是要下盘回正，而是要把 hip 修正方向翻过来，匹配「反移动」的表现 —— 现在还在滑。

#### 为什么回正会滑

腿只能绕 X 做前后摆，所以**脚相对身体的摆动轴 = 下盘前后轴**。支撑相要钉地，就必须让这个轴
与真实移动方向平行。

v9s.13 把侧向权重收掉后，下盘偏转也跟着归零 —— 轴停在身体正前方。而侧后方移动是斜的：

```
移动方向 135°（右后）
下盘轴     0°（身体正前）
轴偏差    45°  →  横向分量完全没有脚补偿 = 滑
```

#### 改法：翻到移动方向的反侧

后退摆腿时，脚往移动方向蹬出去，膝盖却朝反侧，所以下盘角度天然与「侧移偏转」反号：

```
h_back = θ − sign(θ)·180°        135° 右后 → −45°（下盘朝左前）
```

因为下盘前后轴是无向的（±180° 等价），−45° 与 135° 是**同一根轴**，脚的前后摆动正好落
在真实位移上。

```ts
export function backHipYawTarget(fwd, right, strafeYaw, backKeep) {
  if (|θ| ≤ 90°) return strafeYaw;              // 侧移段保持原样（0.35 限幅 + 侧摆补偿）
  return strafeYaw·k² + backYaw·(1 − k²);       // k = backKeep
}
```

- `k²` 而不是 `k`：`backStrafeKeep` 是 smoothstep，中段（110° 附近）侧摆已退一半、下盘却只转了一点，
  那是最难看的「半翻」——既没侧摆补偿、轴也没对上。平方让翻转跑在收缩前面。
- 侧移段走 `strafeHipYaw` 的 0.35 限幅（腿不必正对移动方向，剩下的角度由 footX 侧摆补），
  所以纯侧移 90°、侧前方 45° 与旧版逐帧一致。

#### 实测（真实骨架，玩家 rig）

| 移动方向（相对身体） | 下盘 hipYaw | 轴残差 | 步态 |
|---|---|---|---|
| 90°（纯侧移） | +50.4° | 39.6°（靠侧摆补偿，本来就不需要对齐） | 侧步 + 交叉步，不变 |
| 110° | −8.2° | 61.8° | 过渡带，侧摆已收 |
| 120° | −52.7° | **7.3°** | 纯前后摆 |
| 125° | −54.1° | **0.9°** | 纯前后摆 |
| 135° | −45.0° | **0.0°** | 纯前后摆 |
| 180°（正后方） | 0° | 0° | 纯后退 |

对比 v9s.13：135° 时残差恒为 45°（横向滑 45% 速度），现在为 0。

#### 验收

- 新增 `tests/v9s14-back-hip-flip.test.ts` **10 例**：135°/−135° 对称翻转、正后方归零、
  |θ| ≤ 90° 原样返回、`backKeep=1` 逐帧等价旧观感、90°→180° 扫描的残差单调收敛、零速度防 NaN，
  以及真实骨架三例（135° hip ≈ −45° 且残差 < 8°、45° 仍为侧移偏转、90° 对照）。
- `tsc` / `vitest`（**51 文件 / 595 例**）/ `verify:portable` 全通过。

#### 传送：`warpTo` 是 Core 的纯状态转移

```ts
warpTo(world, x, z)   // 落点支撑面高度由 supportHeight 推导（可传到 0.8m 台上）
```

一次性清掉**跨场地会残留**的玩家侧状态：速度 / 步态相位 / 攻击连击 / 派生招窗口 / 冲刺与闪烁 /
引导飞弹与电环 / 受击 / 锁定目标 / 原地转身。假人与 `world.time` 不动 —— 传送只换位置，不重开一局，
所以可以在一局里连续换工位做 A/B。

#### 三个入口

- 左上「工位」胶囊 → 7 行按钮，点名字直接传送，当前工位高亮并显示说明；
- 桌面 `[` / `]` 循环切换、`\` 召回全部假人（回 home + 恢复初始行为）；
- 自动化验收：`__harness.lab.goto('terrain')` / `current()` / `recall()` / `stations`，
  逐工位截图与取数都不必再手动走位。
