### v9s.19 · 头部回正改身体空间，弓箭循环射击，技能模块化

> 三条反馈：① head 在没有目标回正时速度可以慢点、基于 body 空间回正，不然可能比身体转得慢；
> ② 弓箭很难打到人，加一点点自动追踪，取消冷却、按住自动蓄力射击；
> ③ 准备把技能结构拆成模块化，适配以后数据驱动。

#### ① 头部回正：世界坐标 → 身体局部空间

旧版头部只有一条世界坐标的指数趋近：

```ts
headYaw = approach(headYaw, facing, headTurnRate, dt)
```

没有目标时 `headTarget = facing`，身体也正朝 `facing` 转。问题出在「角度是绝对的」：
头和身体的偏角越大，头要走的路越长，而身体是直接朝目标转的 —— 换目标后收势那一下，
头会被身体落在后面，看起来像「头转得比身体慢半拍」。

现在把「有没有明确注视对象」拆成两套动力学：

| 情况 | 动力学 |
|---|---|
| 有目标（威胁注视 / 拖拽 / 锁定） | 世界坐标高速追随，头先于身体锁住目标（不变） |
| 无目标 | `headYaw = bodyYaw + offset`，**offset 自己衰减**，身体转多少头就跟着转多少 |

```ts
const cur = wrapAngle(c.headYaw - c.bodyYaw);
const want = wrapAngle(headTarget - c.bodyYaw);
const converging = Math.abs(want) < Math.abs(cur) - 1e-9;   // 偏角在收 = 回正
const rate = converging ? gaze.headReturnRate : orientation.headTurnRate;
```

- 回正速率 `headReturnRate 3.5`（跟随是 8），角速度上限 `headReturnSpeedDeg 120°/s`；
- 偏角**在涨**（转向新方向）时仍走原速率 —— 转身时头依旧领先身体，不会因为「回正变慢」变木；
- 俯仰回正也同步降速（`min(headPitchRate, headReturnRate)`），抬头 / 低头收得更柔和。

实测（Xvfb + Chromium 逐帧）：`headYaw 0.5 → 0.0151`（60 帧，理论 `0.5·e^-3.5`），
单帧最大 `0.0283 rad` < 上限 `0.0349 rad`；把 `facing` 指到 +60° 后身体转 `0.946 rad`，
头相对身体的偏角 `0.400 → 0.090`，且每帧都严格满足 `headYaw = bodyYaw + offset`。

#### ② 弓箭：取消每箭冷却 + 按住循环 + 一点点自动追踪

**冷却的根因是状态机合流**：放箭复用了近战的 `windup → active → recovery → settle`，
而旧版只允许 `phase === 'idle'` 时起蓄力 —— 一箭之后必须等 0.58s 动作播完。
v9s.19 把「蓄力」和「放箭动画」解耦：

```
按住 → 蓄力（0.85s）→ 自动放箭（开始播 0.42s 放箭动作）
     → 下一帧就重新蓄力（不等动作播完）→ 循环
```

- `bow.autoFire = true`：蓄满自动放箭；松手仍可提前射出（≥ `minChargeToFire`）；
- `bowQueued` 整个删除（不再需要「后摇期间缓冲按下沿」）；
- 蓄力期间移动仍按 `chargeMoveMultiplier 0.55` 减速；
- **翻滚 / 闪现可以打断蓄力**（放弃这一箭、不发射）—— 自动连射时几乎全程在蓄力，
  沿用旧规则会长时间锁死冲刺；放箭动作（0.42s）也允许被翻滚取消，`phase` 直接归 idle。

**打得中的三件事**（都在 Core，确定性）：

1. **出弓软瞄准**：`homingRange 14m` 内、`homingConeDeg 30°` 锥形内选最近目标（有锁定目标优先），
   把发射角压到目标方向（最多压 30°）—— 只靠飞行修正拉不回来，16 m/s 的箭转弯半径有 10m+；
2. **按距离解竖直初速**：`t = 水平距离 / 初速`，`vy = (aimY − startY + ½gt²) / t`，
   落点自动对到目标胸口（`aimHeightRatio 0.7`）。旧版固定 3.5° 仰角，8m 外必掉到脚下；
3. **飞行限速修正**：前 `homingTime 0.9s` 内以 `turnRateDeg 90°/s` 水平转向、
   `verticalTurnRate 18 m/s²` 修正下坠，只追出弓时锁定的那一个目标（目标倒下就放弃修正）。

另外箭的飞行朝向改为每帧由速度反推（`yaw = atan2(vx,vz)`、`pitch = -atan2(vy,|v|)`），
箭尖终于真的指着弹道方向，而不是一直保持出弓时的水平角。命中半径 `0.14 → 0.2`。

实测：目标在 8m 外偏 19° 且持续横移，第 50 帧命中并插在假人身上（`stuckDummy = 0`，插点 y = 0.89）；
按住 2.2s 的循环里 `attackId` 每 ~0.85s 递增一次，不再有 0.58s 的空档。

#### ③ 技能模块化：`core/skills/` + 数据声明表

旧结构里所有技能逻辑都堆在 `abilities.ts`，配置写死 `config.abilities.arcane` / `.ring`，
加一个技能要同时改 abilities、movement（引导减速）、debug-panel、表现层。

现在拆成三层：

```
core/skills/
  types.ts          SkillContext / SkillModule 契约（kind + update）
  channel-volley.ts 引导 → 波次齐射（原 updateChannel / fireWave / updateProjectiles）
  ground-ring.ts    原地电环（原 placeRing / updateRings）
  index.ts          MODULES 穷举表 + normalizeSkills（解析参数）+ skillsUpdate（dispatch）
core/abilities.ts   只剩共享施法状态 + 实体容器 + reset
```

配置侧新增 `core.skills` 声明表：

```json
"skills": [
  { "id": "arcane", "kind": "channelVolley", "slot": "attack", "weapon": "staff",
    "paramsRef": "arcane", "enabled": true },
  { "id": "ring", "kind": "groundRing", "slot": "skill2", "weapon": "staff",
    "paramsRef": "ring", "enabled": true }
]
```

- `kind` 决定「怎么放」，由 `MODULES` 穷举映射到实现（TS 会强制补齐，JSON 写错 kind 也不会静默生效）；
- `paramsRef` 指向 `core.abilities.<name>`，**保留对象引用** —— 调试面板改数值、测试里直接改
  `w.config.abilities.arcane.waves` 都会立刻作用到技能；
- 新技能可以完全不碰 `abilities`，直接内联 `params`；`slot`（attack / skill2）与 `weapon` 决定输入与武器门控；
- 引导减速不再硬编码法杖：技能开始引导时把 `moveScale` 写进 `abilities.channelMoveScale`，移动模块只读这个值。

验证：`w.skills` 解析出 2 条、`params === config.abilities.arcane`；禁用其中一条后奥术不再出手而电环照常；
弓不放环；再往 `core.skills` 里塞一条内联参数的 `groundRing`（半径 5.5），一次按下同时出现 2.4m / 5.5m 两个环，
**没有改任何 dispatch 代码**；未知 kind 被忽略且不抛错。

### v9s.20 · 边界不再「位置冻住、速度满格」

> 反馈：假人走到边界，手脚都在抖。

#### 根因：边界只夹位置，不夹速度

世界边界原先只有一句 `clamp`：

```ts
p.x = clamp(p.x, b.minX, b.maxX);   // movement / dummies 各一份，末尾执行
```

速度没有任何约束，AI / 输入照样把它推到满速。而表现层的步态是两条互不相干的输入：

| 输入 | 作用 | 贴边时的表现 |
|---|---|---|
| `speed`（速度大小） | 决定摆动幅度 `amp` / `reach` | 满格 → 腿摆到最大跨步 |
| `gaitPhase`（由**实际位移**推进） | 决定「摆到哪个相位」 | 位移为 0 → 相位冻结 |

于是假人顶着边界时是「满幅跨步定格」；玩家 / 其他假人再碰一下，位移每帧 1~2mm 地抖，
相位跟着一帧一帧地挪，`speed` 却始终满格 —— 读起来就是手脚在抽。

keep-distance 假人被逼到边界时最明显：它一直想后退，`desiredDirection` 永远朝界外，
速度锁在 2.6 m/s，位置一动不动。

#### 修法：把「朝界外」这件事从速度和方向上一起去掉

1. **输入 / 期望方向投影到边界切向**（`movement` 与 `dummies` 同构）
   ```ts
   if ((ix > 0 && p.x >= b.maxX - EPS) || (ix < 0 && p.x <= b.minX + EPS)) ix = 0;
   ```
   贴边后不再往界外加速，速度自然收敛到「只剩沿墙分量」，斜着走会顺墙滑。
2. **夹紧的同时清掉朝外的速度 / 击退**
   ```ts
   if (p.x > b.maxX) { p.x = b.maxX; if (v.x > 0) v.x = 0; if (hurt.knockX > 0) hurt.knockX = 0; }
   ```
   被击退到墙上也不会残留一股「一直往外顶」的速度。
3. **假人撞墙由「全清」改成「按轴清」**（和玩家原有的处理对齐）
   原先假人只要 `blocked` 且没被夹死就什么都不做，贴墙斜走时速度全速空踩；
   现在只清被挡的那一轴，沿墙分量保留，不会每帧「清零 → 重新加速」形成方波。

#### 顺带修掉一条 NaN 传染链

调试时用坏参数调 `view.snapCamera(undefined, …)` 做对照，结果整场假人位置变 `NaN`。
链路是：相机矩阵 `NaN` → `getGroundBasis()` `NaN` → 输入 `moveX/moveZ` `NaN` → 玩家 `velocity` `NaN`
→ `position` `NaN` → `separation` 里 `nx = dx / d` 得到 `NaN` → **所有假人一起 `NaN`**。

`movement` 现在对输入做最后一道闸：非有限值直接按 0 处理。相机再怎么坏也不该污染 World。

#### 验收

- 新增 `tests/v9s20-boundary-gait.test.ts` **9 例**：贴边按住朝外速度收敛到 0 / 斜推只保留沿墙分量 /

  假人 keep-distance 被逼到边界速度 < 0.05 / 贴边斜走 `vx = 0` / 击退不越界 / 玩家离开后恢复追击。
- 真机逐帧（Xvfb + Chromium，假人贴 `x = 15.5`）：修复前 `vx = 2.6`、`gaitPhase` 冻在 `1.659`、
  腿部保持前后跨步；修复后 `vx = 0`，收相到 idle，四帧近景双腿并拢、姿态完全一致。

### v9s.21 · 技能与移动的融合：三层速度模型

> 反馈：放技能速度立马掉下来，放完接移动又像重新起步；攻击跨步希望能到目标位置、
> 但不要把冲击力叠在原本移速上导致到点速度过高；弓箭移动射击想要一点后坐力。

#### 根因：一条速度被三种语义轮流「赋值」

```ts
// movement.ts（旧）
if (inAction) {
  v.x = ix * speed;          // 赋值：attackMoveScale = 0 时一帧从 4.2 变 0
  v.z = iz * speed;
} else {
  v.x += (ix * speed - v.x) * k;   // 只有这里才是趋近
}
```

- **进技能掉崖**：赋值不是趋近，按下攻击那一帧速度直接归零，没有任何过渡。
- **放完重新起步**：技能结束时 `v` 仍是 0，只能靠 `acceleration = 16` 从零爬回 4.2，
  时间常数 62ms、到 95% 要 190ms；步态相位又由实际位移推进，位移停了腿就收拢，
  再迈开就是「起步」的视觉信号。
- **跨步是方波**：`speed = lunge / active` 全程匀速，末帧 `impulse` 被清 0 —— 从 7.3 一帧切到 0。
  而且 `impulse` 是**加法**层，一旦放开 `attackMoveScale`，总速度就是 4.2 + 7.3。

#### 改法：移动层 / 技能位移层 / 脉冲层

```
vTotal = v(locomotion) + impulse(skill) + kick(impulse)
```

每层有自己的生命周期，移动层永远只做「目标速度 + 指数趋近」，不做赋值：

```ts
const rate = inAction ? cfg.skillDecel : (ilen > EPS ? cfg.acceleration : cfg.friction);
const k = 1 - Math.exp(-rate * dt);
v.x += (ix * speed - v.x) * k;
```

**1）跨步改成 ease-out 包络**

`s(t) = D·(1 − (1 − t/T)^(p+1))`，速度取「本帧位移增量 / dt」而不是采样曲线高度 ——
这样离散积分的总位移严格等于 `D`，不会因为帧率或采样端点漂移几个百分点。

| 量 | 旧（匀速） | 新（p = 1.2） |
|---|---|---|
| 起手速度 | 7.3 | 6.4（第 2 帧到峰值） |
| 到点速度 | 7.3 → 一帧硬切 0 | 0.43 → 0.73 平滑回升 |
| 总位移 | 0.45 | 0.45（面积不变） |

**2）跨步期间移动层让位**

`lungeMoveScale = 0.08`：真正把身体推出去的那 0.13s 里，自主移动几乎归零，
总速度由跨步层主导而不是两层相加。攻击的其他阶段保留 `attackMoveScale = 0.3`，
所以「边跑边打」成立，但不会在到点那一下叠出 11+ m/s。

**3）新增脉冲层 `kick`**

弓箭放箭时写 `kick -= facing × recoilSpeed`，每帧 `kick *= exp(-recoilDecay·dt)`。
它不经过 `v` 的目标速度，所以「往前走 + 后坐」= 4.2 − 1.0 = 3.2，仍在前进；
如果直接改 `v`，后坐力会把移动输入顶掉，读起来像卡了一下。

**4）步幅改按实际位移速度推导**

旧版 `stepSpeed = |v|`，而攻击 / 翻滚期间的位移来自 `impulse`，`v` 很小 →
`stride` 被压到最小值、`frameDist` 却很大，相位一帧推进一两弧度，腿看着在疯转。
现改成 `frameDist / dt`，跨步时步幅同步放大。
