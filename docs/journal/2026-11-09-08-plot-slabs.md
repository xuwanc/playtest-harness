# 2026-11-09-08 · 底板按地块拆开：5 m 模数 + 整数格拼合（v9s.48）

## 触发

> 「现在测试场景需要再次改造，整块底板已经不够用了，是否可以按测试项目，拆分底板和测试物件，
> 并在进入场景的时候自动把测试场景拼合好，每个测试地块规格一致？还是按实际需求单位格
> 比如 10*10，20*10 之类？」→ 选定「模数 5m + 整数跨格」→「好的，做好规范开整」。

## 1. 现场：其实已经出界了

| 项 | 值 | 出处 |
|---|---|---|
| 底板 | 32 × 32 单块 | `scene.ground.size` |
| 可行走边界 | ±15.5 | `core.worldBounds`（手写） |
| 地块 | 9 块（7 块 pinned + 2 块 auto） | `config/plots/*.json` |

`sparring-demo` 落点 `(0,14)`、半径 2 → 北缘到 z=16，**超出边界 0.5 m、正好压在地面边缘**。
再想加「可破坏物 / 新武器 / 新 AI」的独立场地，只能挤缝里。

根因不是「32 太小」，而是**底板是单体、地块位置是手写绝对坐标**：加一块地 = 改一块共享地板 +
手工找一个空位。`plot-assembly` 当初只做了「标识盘」，没做「承重的地」。

## 2. 决策与落地

统一的是**模数和缝**，不统一的是跨几格：

| span | 尺寸 | 用途 |
|---|---|---|
| `[1,1]` | 5×5 | 单道具 |
| `[2,1]` | 10×5 | 量具 |
| `[2,2]` | 10×10 | **默认**：圆盘工位 / 陪练场 / 可破坏物 |
| `[2,4]` | 10×20 | 冲刺跑道（`dash` 沿 z 要 19 m） |

算法（`assemblePlots`）：

1. 去重 + 按 `id` 字典序排序（与加载顺序、提交先后无关）；
2. `pin:'origin'` 的地块（只有 `hub`）先占格 `(0,0)`；
3. 其余**行优先 first-fit**：从 `(0,0)` 逐格试，`span` 覆盖的格子全空就占位；
4. 整体平移，让 **pin 板中心 = 世界原点**（出生点 `core.spawn=(0,0,0)` 就在 hub 板上）；
5. 每块地生成一张 `SlabSpec`；包围盒内的**空格补填充板**（`plotId:''`，行内合并成条带）。

不重叠是构造性的（占用表是 `Map<"c,r">`），没有浮点圆相交。

最终 6 列 × 8 行 = 30×40 m：

```
        c0        c1        c2        c3        c4        c5
 r6-r7  x-destr  │ 填充×4
 r4-r5  sparring │ terrain │ windup
 r2-r3  meter    │  dash   │ rings
 r0-r1  hub      │  dash   │ gait
```

## 3. 顺手把「测试物件」也搬进地块

不只底板。`steps` / `doorways` / `obstacles` / `dummies` / `grass` 全部改成 `dx/dz` 相对坐标，
由拼合器解算：

| 从 `game.json` 迁出 | 迁到 | 备注 |
|---|---|---|
| 8 台阶 + 2 门洞 | `terrain.json` | 相对偏移原样保留，形状不变 |
| `crate-hub` | `hub.json` | |
| `pillar-sw` | `meter.json` | 旧坐标在板外 4.8 m，挪到 `(-4.0, 3.6)` |
| 6 个假人 | `rings`(3) / `windup`(1) / `gait`(1) / `meter`(1) | 每个写 `mode`，不再依赖 `initialModes` 顺序 |
| 3 个持械陪练 | `hub.json` | 原来 z=5.9 超板，挪进 ±4.2；每个写 `weapon` |
| 主草场 12×10 m | `sparring-demo.json` 的 `grass` | `game.json` 的全局区域置 0（关闭） |

`applyPlotAssembly(core, scene, assembly)` 是唯一注入入口，`src/config.ts`（Vite glob）与
`tests/helpers.ts`（Node fs）共用 —— 这是第一版漏掉的：两处各写一遍必然会漂。

`worldBounds`、`gridMeta`、阴影相机范围全部从包围盒推导，`±15.5` / `±16` / `sc.left=-20` 都删了。

## 4. 表现层

- **板缝**：每块地板沿边画一条 0.09 宽的主色线 + 四角 0.42 小方块（`lab-scene.ts` 的 `slabFrame`），
  放在 y=0.006（低于地面盘 0.012）。填充板不画。
- **网格**：`GridHelper` 只能画正方形，30×40 会溢出；改成自建 `LineSegments`，
  按 `gridMeta` 铺 1 m 细线、5 m 亮线。
- **阴影**：`sun.position` / `target` / 正交相机都按地图中心平移，`mapSize` 1024 → 2048。

| 项 | 结果 |
|---|---|
| `tsc --noEmit` | 0 error |

## 6. 踩到的坑

1. **填充板是必需品，不是美化**：`bounds` 是矩形，而地板可以是非矩形。9 块地拼完 r6-r7 的
   c2..c5 是空的，`worldBounds` 却允许角色走过去 —— 没有填充板就会踩空。
   这条写进风险文档了，不能当成可选项删掉。
2. **`relocated` 诊断语义崩了**：旧模型里「顺延过槽位」有意义（圆重叠），新模型里每个
   auto 地块都不是第一格，全是噪声。直接删字段，位置信息改由 `cell:{c,r}` 表达。
3. **测试夹具漏同步**：`applyPlotAssembly` 抽出来之前，`config.ts` 注入 5 个字段、
   `helpers.ts` 注入 3 个，测试里 `CONFIG.scene.slabs` 是 undefined。抽成共享函数后一次解决。
4. **草场奇偶断言失效**：旧断言「plot 草块与主草场同奇偶」依赖主草场存在；主草场关掉后
   基准变成 0，地块草块从 -9 起就是奇数。改成「同一行内 patch 间距 = footprint」。
5. **smoke 旧断言三连红**：「7 块 pinned 零回归」现在只有 1 块 pin；「auto 落点 = 中心」
   不成立（`rings` 的 spawn 有 +3 偏移）；「点测试按钮传送到 auto[0]」——`auto` 数组里
   第一块是 `rings` 不是带按钮的 `sparring-demo`。三条都按新契约重写。

## 7. 没做的

- **`hub` 居中**：现在钉在原点、地图向东北长。居中要加 `at:{c,r}` 或环形扫描，
  会引入「谁先占谁得」之外的新规则，等有实际需求再说。
- **物件出界校验**：拼合器只解算坐标不校验，靠单测兜。若要运行时兜底，
  可以在 `diagnostics` 加 `overflow: string[]`。
- **`dist/` 入库**：仍是老问题（每次 build 大 diff、合并必冲突），本轮没动。
