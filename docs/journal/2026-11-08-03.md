### v9s.31 · 关键帧事件、命中窗口、段间混合自适应

> 承接 v9s.30 文档第九节的改进清单，先做投产出最高的前两项：
> 「关键帧事件」与「姿态锚点 + 连击窗口数据化」。

#### 1. 为什么需要 AnimNotify

旧版有两个「靠比例猜」的地方：

- **判定**只认 `attack-active` 那一帧。active 段 0.13s，第一帧扫完扇形，敌人在第 2 帧
  才走进刀风就完全吃不到伤害 —— 快速移动 / 被击退的目标会「穿刀」。
- **表现**（刀光风声、脚步、尘土）只能拿 `attackProgress` 做阈值比较。掉帧补算时一帧跨
  两个阈值，要么漏一个，要么同一帧连发两次。

数据放在武器的 profile 上，跟着时间轴走，而不是另建一条计时器：

```json
"notifies": [
  { "at": "windup", "u": 0.7, "name": "blade-air", "value": 0.5 },
  { "at": "active", "u": 0.0, "name": "blade-air", "value": 1.0 },
  { "at": "recovery", "u": 0.35, "name": "foot-step", "value": 0.6 }
]
```

#### 2. 扫描：一个连续标量 + 一个游标

三个阶段首尾相接成 0..3 的标量（windup 0..1 → active 1..2 → recovery 2..3），
`CombatState.notifyCursor` 记住上一帧走到哪，每帧只扫 `(cursor, after]`：

- 单帧跨阶段 / 掉帧补算 → 只是一个更大的区间，顺序由时间排序保证；
- 卡肉冻结 → `advancePhase` 提前 return，游标不动，恢复后不会补发；
- 攻击结束进入 settle → `after = 3`，把 recovery 末尾 `u: 1` 的通知补齐。

`cursor = -1` 表示「本段还没开始」，因此 `u: 0` 的通知在起手第一帧就能发出。
这条边界很容易写错成左闭右开，结果是每一段的第一条通知都丢一帧。

实测：同一段剑盾攻击，60Hz 与 30Hz 步长下事件序列（名字 + 数值）逐条一致。

#### 3. 命中窗口：从「一帧」到「一段」，靠 hitIds 去重

```json
"hitWindow": { "start": 0, "end": 0.85 }
```

active 段内每帧都扫扇形，`CombatState.hitIds` 记录本次攻击已结算过的目标，
每次起手清空。于是：

- 中途进入刀风的目标能被打到（用例：第 3 个 active 帧才挪进范围，旧行为 0 命中，新窗口 1 命中）；
- 贴着不动也不会掉成十几击（整个窗口扫 5 帧以上，`hitCount` 仍然只 +1）；
- 一次攻击可以打多个目标，各结算一次；下一段清表后同一目标能再次受击。

`end: 0.8~0.9` 是给「收招前已经抽刀回来」留的余量，避免刀都收回去了还在判定。

#### 4. 段间混合：固定 0.1s 换成「姿态差 → 预算」

固定值的两个毛病：双剑整段 0.35s，0.1s 混合占近三成，连击发黏；大剑姿态差大，
0.1s 内跨 200°，读起来是硬切。

```
distance = Σ 加权角度差（躯干 / 手臂 / 剑身 / 刃面 / 骨盆位移）
k        = clamp(distance / segBlendRef, 0, 1)
span     = segBlendMin + (本段总时长 × 22% − segBlendMin) · k
```

- 姿态差小的快刀贴近下限（0.03s，约 2 帧）；
- 姿态差大的换段接近本段预算，但**不会吃掉挥击本身**；
- 上限用「本段时长 × 22%」而不是固定值 —— 这是「快攻不黏」的关键；
- `SwingClipRef.blend` 仍可按段写死，用于必须精确对齐帧的特殊段。

权重按「观众最先注意到哪个通道」排：躯干扭转 / 手臂俯仰 / 剑身仰角最高，刃面滚转最低；
骨盆位移按 2 rad/m 折算。`spinYaw` 不参与（它是时间轴语义，不插值）。

#### 5. 连击窗口分武器

`comboWindow` 从全局 0.65s 改为可按武器覆写：双剑 0.5s（快节奏）、剑盾 0.62s、大剑 0.78s
（收势长、允许更晚接）。缺省仍继承全局值，旧配置不用改。

#### 6. 表现层消费

`blade-air` → 镜头微震（大剑 ×1.5，读得出「这把刀很沉」）；`foot-step` → 极轻的落地震。
`diagnostics().camera.shake` 暴露震动能量，线上冒烟可以断言「关掉 hitstop 震动后打一拳，
shake 仍然 > 0」，从而证明消费的是 notify 而不是命中卡肉。

### v9s.32 · 体型入口、空挥不震屏、分武器持械姿态

> 三条试玩反馈：UI 找不到体型入口、打空气也震屏、五把武器待机长得一样。

#### 1. 体型入口：从「隐藏快捷键」变成可见控件

`B` 键一直能用，但手机没有键盘，等于没有入口。顶部胶囊行新增一枚「体型 标准」：

- 点击 / `B` 共用 `cycleBody()`，每次都从 `view.bodyTypes().id` 反查下一项，
  不维护第二份下标 —— 控制台或验收钩子改过体型也不会错位；
- 胶囊文案直接显示当前体型名，`aria-label` 带快捷键说明；
- 与旁边四个「▸」折叠胶囊用不同描边区分：它是「动作」，不是面板开关。

#### 2. 空挥不震屏：镜头震动只属于「打实了」

上一版把 `blade-air` 通知映射成镜头震动，副作用是**空挥也在震** —— 打空气和打实人
反馈一样，命中感反而被稀释。现在分成两条通道：

| 事件 | 触发条件 | 表现 |
|---|---|---|
| `hitstop` | Core 判定真的命中 | 镜头震动 + 骨架定格 |
| `blade-air` | 挥出瞬间，不论是否命中 | 刀光短促增亮（`trail.pulse`） |
| `foot-step` | 换步 | 只发事件，暂不震屏 |

`WeaponTrail.pulse()` 按指数衰减（`pulseDecay`，默认 14/s），多次叠加有上限 1.5，
`reset()` 清零；`trailDebug().pulse` 可直接读数。实测：把假人挪到 200m 外连打，
`camera.shake` 最大 0、`trail.pulse` > 0；把假人放回身前，`shake` 立刻 > 0。

#### 3. 分武器持械姿态：待机 / 移动不再共用一套徒手站姿

```json
"stance": {
  "greatsword": {
    "armSwing": 0.45,
    "armR": { "pitch": -0.30, "roll": 0.05, "elbow": -0.55 },
    "armL": { "pitch": -0.20, "roll": -0.10, "elbow": -0.65 },
    "torsoPitch": 0.04,
    "bladePitchDeg": -30
  }
}
```

四个语义：

1. **持械臂基准**：肩 pitch / yaw / roll + 肘，直接叠在步态摆臂上；
2. **摆臂倍率**：双手重武器 0.45，短剑 1.0 —— 大剑走路不会像提着两根筷子甩；
3. **躯干朝向**：剑盾侧身（`torsoYaw +0.12`）、弓侧持（−0.08），双刀正面对敌；
4. **刀身仰角**：大剑待机剑尖压低 30°，剑 / 双刀小幅下压，法杖 / 弓不参与反解。

关键设计是**只改非攻击基准**：`applyCombatPose` 仍整体覆盖手臂 / 躯干，交叉淡出以
持械姿态为起点，因此攻击数据一个字没改，起手 / 收招反而更自然。换武器时
`stanceWeight` 从 0 在 `blend`（0.22~0.26s）内升到 1，不会瞬移。

躯干偏移在 `blendCombatPose` **之后**按 `(1 − combatPoseW)` 叠加，攻击权重越高越让位；
刀身仰角只在 `swingBladePitch === null`（非攻击帧）生效。两者都不需要第二条时间轴。

#### 4. 两个测试口径的更新

- `chest-yaw`：待机上半身现在含持械扭转，比较 `upper.rotation.y` 时要补
  `stanceDebug().torsoYaw`（`chestYaw` 仍只表示「胸随下盘」）；
- `v9s23-swing-body`：大剑待机双臂前收会让肩点前送约 2mm，验收从「精确 = 0」
  改为 `< 1cm`（要抓的是攻击残留的 3.5cm，不是持械基准）。
