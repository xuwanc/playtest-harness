### v9n · 停步收相、侧移迈步，以及方向问题的最后一次修复

#### 方向问题：换到「松手瞬间」这条路径

v9m 真机摘要回来了，关键读数是：

```
异常 0（dir 0 / aim 0 / freeze 0 / stick 0 / stickJump 0 / 坏指针 0 / 坐标漂移 0）
摇杆坐标源 屏幕 screenX/Y（2419 帧）
UA ... OpenHarmony 7.0 ...
```

屏幕坐标全程生效、两套坐标之间**一次漂移都没有**、逐帧自洽性检查全绿 —— 说明方向跳变**不在输入层的坐标计算里**。前两版（v9l 跳变阈值、v9m 屏幕坐标）都修错了地方，这一版不再碰坐标体系，只封「松手瞬间」尚未覆盖的四条路径：

1. **id 错配兜底**：部分 WebView 给 `pointerup` 的 `pointerId` 与 `pointerdown` 不一致，旧逻辑只按 id 匹配清摇杆 → 松手后 `stickId` 残留、方向一直挂在旧向量上，直到下一次按下才被重建（真机「松手一瞬间方向变了、再按又回到 45°」）。现在**所有非 UI 指都抬起时无条件释放摇杆**。
2. **幽灵 move**：松手后 150ms 内同 id 的补发 `pointermove` 一律丢弃（新按下会解除窗口）。
3. **假起点**：`(0,0)` 的 `pointerdown` 不再建摇杆原点（v9j 对瞄准做过的防御扩展到摇杆 down）。
4. **逐帧方向守门**：方向突变必须由真实手指位移支撑 —— 转过 θ 却没走出对应的弧长就保持上一帧方向。遥测是 30Hz 抽样，**松手那一两帧的尖峰可能整个漏采**（这正是摘要「异常 0」却仍看到跳变的原因），守门放在事件层逐帧跑。

> 按约定：这版之后若仍复现，就清除 v9l/v9m/v9n 在输入层的全部修理，方向问题不再追。遥测诊断与调试盘是纯观测层，保留。

#### 手感 ①：停步不再卡在最后一个 pose

Core 的 `gaitPhase` 只在有位移时推进（`frameDist / stride`）。松手后速度指数衰减、位移趋零 → **相位冻结**；而 `solveGait` 只要 `speed >= EPS` 就仍按这个冻结相位输出姿态，于是角色卡在最后一个跨步 pose 一小段时间，然后突然弹回待机。

新增纯函数 `solveStopGait` / `nextFeetTogetherPhase`：在减速尾段接管相位与幅度，用 smoothstep 把相位推进到**下一个双脚并拢点**（`π/2 + kπ`，两腿相差 π，此时左右脚同时回到髋正下方），同时把 `speed` 与 `stride` 同系数淡到 0 —— 两脚各走完最后半步、抬膝与重心同步消退，收拢到待机。玩家与假人同构。

#### 手感 ②：纯侧移不再「双腿平行拖行」

「与假人保持距离横移」是纯侧移：`wS≈1 / wF≈0`，两腿 `pitchX≈0`、只有左右摆，看起来像两脚平行滑动甚至互相穿过。

新增纯函数 `strafeHipYaw`：用**连续侧向占比的平方**做增益，把下盘朝移动方向多带转一点（`legYawScale 0.35 → 侧移时 0.56`，约 50°），速度在腿局部坐标系里就有了前向分量，步态自然变成斜向迈步。增益在前进/后退（`lat≈0`）时为 0，没有 `atan2` / `wrapAngle`，任何朝向都不会跳变；假人用独立参数（`strafeHipScale / strafeHipMaxDeg`），玩家沿用 `orientation` 配置。

### v9s.2 · 锁定目标转身跨 ±π 接缝「反向转几圈」修复

> 真机 / 实操反馈：锁定目标（或拖拽瞄准）后绕到背后转身，**锁定时转几圈、停步后又反向转几圈**。根因在 `turn-in-place` 状态机的激活帧插值。

#### 根因

```ts
// turn-in-place.ts（修复前）
c.bodyYaw = wrapAngle(t.fromYaw + (t.targetYaw - t.fromYaw) * ease(t.progress));
```

`t.targetYaw` 本身已 `wrapAngle`（落在 (-π, π]），但 `(t.targetYaw - t.fromYaw)` 用的是**未归一的原始差**。
当 `fromYaw` 与 `targetYaw` 分列 ±π 接缝两侧时，这个差会比「最短弧」多/少一个 2π：

- 例：`fromYaw = 2.9rad`（≈166°），目视目标 `look = -0.78rad`（短弧 +149°）。
- `dir=+1`、`abs≈2.6`，`targetYaw = wrapAngle(2.9 + 2.6 - 0.14) = -0.92rad`。
- 原始差 `-0.92 - 2.9 = -3.82` → 插值沿 **-3.82rad（≈-219°）长弧**推进，方向与 `dir` 相反、幅度超 π。

观感即「反向整圈转」。而 `approach` / `headYaw` 钳制都走 `wrapAngle` 最短弧，不受此影响，故只有 `turnInPlace` 激活帧发病。

#### 修法

插值前先把差值取最短弧：

```ts
const turnDelta = wrapAngle(t.targetYaw - t.fromYaw); // 永远 ∈ (-π, π]，即 dir 决定的短弧
c.bodyYaw = wrapAngle(t.fromYaw + turnDelta * ease(t.progress));
```

`wrapAngle(t.targetYaw - t.fromYaw)` 恒等于 `t.dir * (abs - settle)`（短弧），与 `dir` 同号、幅度 ≤ π。一次转身必留 `settleDeg` 余角，故 `|累计转角|` 恒 ≤ π，再不可能走长弧 / 反向整圈。

### v9s.3 · 面向朝向智能评估威胁 / 重要目标（两级注视）

> 用户两项诉求：① **机制调整**——面向朝向智能评估威胁或重要目标，分两级（普通注视 / 威胁注视）；② **回归修复**——「锁定目标后转几圈、停步后反向转几圈」（已由 v9s.2 修复，本批仅收尾发布）。

#### 用户拍板的两项设计决策

1. 威胁注视的「身体朝向」目标 = **主威胁 + 最近 2~3 个高权威胁**的加权中心（`centroidYaw`）。
2. 进入 / 解除口径 = **主动瞄准（`aimActive`）且范围内存在威胁**才进入；全部威胁超出 `recoveryDist` 后带滞回交还身体控制。

#### 两级行为

**普通注视（不改身体朝向，仅转头）**
- 头看「拖拽瞄准方向 > 锁定目标方向」（`orientation.ts` 头部逻辑）；未锁定时头跟随 `facing`（移动 / 瞄准方向）。
- 头部相对身体的偏角超过 `headLookLimitDeg`（默认 55°）时，平滑转回看**移动方向** `moveYaw`，而非硬卡在极限。
- 注意：**头部不做「最近假人」兜底**——那是 `turn-in-place`（身体）的机制；头部只跟明确的拖拽 / 锁定意图，未锁定时自然看向移动方向。

**威胁注视（身体趋向包围中心）**
- 仅当 `aimActive && 范围内有加权威胁 && 归一化强度 ≥ enterThreshold` 进入；进入后即使边瞄准边走位，身体也始终压向 `centroidYaw`。
- 多目标时：头看**主威胁** `mainYaw`，身体朝向**主威胁 + 最近 `maxThreats-1` 个高权威胁**的加权中心 `centroidYaw`。
- 加权口径与相机（`camera.ts`）完全一致：`proximity × modeWeight（+ 挥砍 active 帧 attackBoost）`，归一化强度 `= sum / (sum + saturation)`，保证「包围圈构图」与「威胁注视」同源。
- 全部威胁超出 `recoveryDist` 后（滞回：在 `threatRange` 与 `recoveryDist` 之间仍保持，避免门口反复横跳）交还身体控制。

#### 架构落点（Core，确定性、可快照）

| 文件 | 改动 |
|---|---|
| `src/core/gaze.ts`（新增） | `gazeUpdate(world, dt, intents)` 状态机 + `gazeCentroidYaw(world)`；写入 `world.gaze.{active, mainId, mainYaw, centroidYaw, threatCount, threat}` |
| `src/core/orientation.ts` | 身体目标：`gaze.active ? centroidYaw : facing`；头部：`gaze.active ? mainYaw :（拖拽 > 锁定目标 > facing）`，超 `headLookLimitDeg` 转回 `moveYaw` |
| `src/core/turn-in-place.ts` | `resolveLookYaw` 开头：`gaze.active` 时直接返回 `centroidYaw`（身体 / 转身朝包围中心，与 orientation 一致）；`turnShouldDrive` 同理预判 |
| `src/core/step.ts` | movement 之后、orientation 之前调用 `gazeUpdate`（模块开关守卫） |

#### 进入 / 解除的滞回逻辑（修复一处控制流崩溃）

`gaze.ts` 的激活判定：`desired = aimActive && inThreat && threat ≥ enterThreshold`；`hold = aimActive && prevActive && inRecovery`（威胁已移出 `threatRange` 但仍在 `recoveryDist` 内）。`active = desired || hold`。

> **控制流修复**：纯滞回保持（`hold` 触发、但威胁已超出 `threatRange` 故 `threats` 为空）时，原先仍走到 `g.mainId = threats[0].id` 触发 `TypeError`。现加守卫：若 `threats.length === 0` 则提前返回，**保留上一帧** `mainYaw / centroidYaw`，身体保持指向旧威胁方向、不重算（无有效威胁点）。

### v9s.4 · 接敌准备与普通注视收尾

> 用户三条反馈：① 威胁注视时「头比身体转得慢」；② 威胁注视更像**接敌准备**——移动时朝向也保持威胁方向，除技能之类可打断；③ 普通注视应**仅转头**，停下却被附近目标拽得整身转过去（怀疑是 `turnInPlace`）。

#### 1. 威胁注视：头不受「超角改看移动方向」限制

旧逻辑对头顶部统一做一道 `headLookLimitDeg`（55°）路由：`|headTarget − bodyYaw|` 超过 55° 就把头改去看 `moveYaw`。威胁注视时身体朝 `centroidYaw`、头要朝 `mainYaw`，两者夹角很容易超过 55° —— 头于是被踢到移动方向，看起来「没看目标、还比身体慢」。

- 现在这道路由**只作用于普通注视**；威胁注视时头目标恒为 `mainYaw`，只受相对身体的 `maxHeadTurnDeg`（55°）物理限幅。
- 新增 `gaze.headTurnRate`（默认 **30**，> `bodyTurnRate` **7**）：威胁注视时头部用更高速率追主威胁 → **头先于身体到位**。
- 技能 / 攻击 / 引导打断期间，头随战斗朝向（`attackFacing`），不会在挥砍时死盯威胁。

#### 2. 威胁注视 = 接敌准备（移动保持朝向，技能可打断）

- 威胁注视激活且未被主动动作打断时，`facing` 以 `bodyTurnRate` 平滑压向 `centroidYaw`，并且**跳过摇杆移动输入对 `facing` 的改写** —— 边走位边保持面朝威胁，侧移 / 后退由 `moveYaw` 独立表现。
- `busy = combat.phase !== 'idle' || combat.charging || channeling || dash.phase !== 'idle'`：任一主动动作都让 `gazeHold` 失效，身体 / 头交还战斗朝向（技能打断接敌准备）。
- `bodyYaw`、`facing` 同以 `centroidYaw` 为目标，两者不再互相拉扯。

#### 3. 普通注视仅转头：移除「最近假人」自动兜底

`resolveLookYaw` 原先三级：`威胁注视中心 > 技2 拖拽 > 锁定目标 > 范围内最近假人`。最后一级会让静止时的路过假人触发整身原地转身 —— 正是「停下就回转向附近目标」。

- 删除最近假人兜底。原地转身只服务两类**明确意图**：威胁注视中心、玩家主动拖拽 / 锁定的目标。
- 无瞄准、无锁定时 `resolveLookYaw` 返回 `null`，`turnInPlace` 保持 idle；普通注视只动头，不拽身体。

#### 架构落点

| 文件 | 改动 |
|---|---|
| `src/core/orientation.ts` | 提前计算 `gazeActive / busy / gazeHold`；`facing` 新增 `gazeHold` 分支（压向中心、不读移动输入）；头部 `gazeHold ? mainYaw : facing`，`headLookLimitDeg` 路由改为仅 `!gazeActive` 时生效；威胁注视用 `gaze.headTurnRate` |
| `src/core/turn-in-place.ts` | `resolveLookYaw` 删除「最近假人」兜底；`lookRange` 参数保留占位（`_lookRange`） |
| `src/core/types.ts` | `GazeConfig.headTurnRate` |
| `config/game.json` | `core.gaze.headTurnRate: 30` |

### v9s.5 · 被攻击自动注视与切换假人零上传

> 真机反馈两条：① 威胁注视触发有问题，**被敌人攻击都不转身**；② **切换假人状态有时候会卡一下**（遥测：235s / 228 次受击 / 29 个 100ms 尖峰）。

#### 1. 被攻击自动进入威胁注视

v9s.3 的进入口径是「主动瞄准（`aimActive`）+ 范围内有威胁」。真机摘要显示玩家全程 `攻击 0 · 手势 0 · 摇杆 9%`，只是站着被围攻 —— 没有瞄准就永远不进入注视，自然「被打了也不转身」。

- 进入条件改为 `aimActive || 有敌人正在攻击自己`：范围内任意假人 `attackPhase = windup（起手）/ active（挥砍中）` 即触发。
- 保持条件放宽为「`prevActive && inRecovery && (瞄准中 || 仍被攻击 || 威胁仍在 threatRange 内)`」—— 一刀打完的 recovery 间隙、敌人小退几步都不会立刻交还，避免反复横跳。
- 新增 `gaze.reactToAttack`（默认 `true`）做 A/B 开关；关掉即回到「必须瞄准」的旧口径。

#### 2. 切换假人状态不再卡顿

头顶标签原本用一张 `CanvasTexture`，切换模式时在**当帧** `clearRect + fillText` 重绘并 `needsUpdate = true` 同步上传。移动端（尤其鸿蒙）Canvas → GPU 纹理上传会造成 1~2 帧卡顿，表现为「点一下假人切状态，画面卡一下」。

- 改为在 `createDummyRig` 时**预生成全部 5 种模式的标签纹理**。
- 切换时只做 `labelMat.map = labelTexByMode[mode]`，纯指针替换、零运行时上传；材质类型不变，也不会触发 shader 重编译。
- `dispose` 遍历释放全部预生成纹理。

- 因 `reactToAttack` 默认开启，隔离两处既有用例：`dummies.test.ts`「假人不写玩家状态」加 `modules.gaze=false`；`orientation.test.ts` 掉头用例加 `modules.gaze=false`（均为测试隔离，不改变契约）。
