## 一、血跟骨骼：Core 给比例，表现层给高度

旧版血量点固定 `身高 × 0.52`，打脚踝和打头喷在同一个高度。

**为什么不能直接在 Core 里算世界 Y**：命中判定是 2D 扇形（`currentMeleeShape` 只有 x/z），
Core 根本不知道刀砍在哪个高度；而骨架的实时高度只有表现层有（驼背、屈膝、后仰都在变）。

所以拆成两层：

| 层 | 输入 | 输出 |
|---|---|---|
| Core | `hits.hitHeight[受击类型]` + 招式偏移 | 归一化部位 `u ∈ [0.05, 0.98]` |
| 表现层 | `u × 身高` 取点 → `boneAtWorld` | 最近骨骼段上的世界坐标 |

骨骼吸附用的是**已有的** `boneAtWorld`（原先给「箭插在身上」用），零新增接口。
血珠起点再沿击打方向外推 10cm —— 骨骼段在身体中轴，不外推的话前几帧血还在躯干内部。

招式偏移：三连第三段 −0.14（收招是下劈）、大剑 −0.05（本来就砍腰腹）、击地固定 0.26。

实测（`tools/death-polish-shot.py`）：

| 招式 | `u` | 世界 Y |
|---|---|---|
| 剑盾轻击 | 0.600 | 0.72 |
| 大剑击飞 | 0.350 | 0.42 |
| 大剑击地 | 0.260 | 0.31 |

截图对比：剑盾那刀血在胸口，大剑那刀在腰腹以下、血珠往右下飞 —— 不再是同一个点。

## 二、尸体挡路：权重反过来

旧版死者直接 `continue` 掉分离，玩家能穿过去，死亡读起来像「模型被删了」。

关键不是「加进分离」，而是**谁让开**：

```
活人：separatePair(玩家, 假人, wa=0, wb=1)   → 假人让开
尸体：separatePair(玩家, 尸体, wa=1, wb=0)   → 玩家让开
```

两个容易漏的点：

1. **碰撞圆心跟着倒向前移**：躺下的身体中心在脚后 0.55m，只用站立半径 0.42 会让人从胸口穿过去。
2. **玩家也要解算一次**：尸体贴墙倒时，把玩家推开可能推进墙里。分离后对玩家跑
   `resolveHorizontal` + 边界夹紧，只在真有尸体时跑。

行为是「贴边滑开」而不是「硬顶住」—— 圆形碰撞本来就会沿切线滑过去。
测试断言因此写成「3 秒持续推进，与尸体圆心距离始终 ≥ 半径和 − 0.08」，
而不是「走不过去」。要「推不动」得再加一档速度衰减，本轮没做。

## 三、头顶血条：DOM 不做 3D 精灵

血条是纯 UI：固定像素宽、不受透视缩放、不受光照。场上只有 3 个陪练，
每帧 3 次 `project` + 3 次 `translate3d`，开销可以忽略。

- 只给 `health.maxHp > 0` 的单位画 —— 打不死的测试桩不挂血条，否则「哪个能打」读不出来。
- 死亡隐藏、重生满血重现；相机背后（`project.z > 1`）隐藏。
- 宽度变化超过 0.5% 才写 style，避免每帧触发样式重算。

## 四、踩坑

**截图脚本只给第一帧输入**。`stepOnce(i === 0 && patch ? patch : {})` 是给「点击类」
（attackPressed）用的；测「按住前进撞尸体」时它只推了一帧，玩家原地不动，
看起来像「被尸体挡住」，其实根本没走。拆成 `patch`（首帧）+ `held`（每帧）后才测对。

**方向语义**：`Intents.moveZ` 是世界方向，不是角色局部方向。玩家 facing=π 时
「朝尸体走」要传 `moveZ: -1`；传 +1 会走反，读数是「穿过尸体」的假象。
