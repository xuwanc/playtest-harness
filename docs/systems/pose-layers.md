# 姿态分层：谁叠在谁上面，以及「在哪个坐标系里叠」

> 触发问题（2026-11-10 用户）：胸块下面那块是腰还是胯？为什么胸的朝向补偿几乎看不出、腿根却跟着转会？
> 「补偿是不是应该用模型空间旋转」「要不要 个性 pose +（攻击 pose − 攻击基础 pose）+ lean」。
>
> 一句话答案：**层已经是对的，坐标系是错的。** 补偿写成局部欧拉角，父节点一转就歪。

## 1. 骨架里那几块分别是谁

```
root（bodyYaw）
└ pelvis            髋部原点，y = legLength。v9s.70 起挂一块 hipMesh（只鱼人有）
  ├ hipMesh         髋块：跨在「骨盆 → 腰」夹角上的补块，rotation.x = 腰段角 × hipShare
  ├ lower           下盘：两腿的 hip 挂在这里（rotation.y = hipYaw）
  │ └ hipL/R → knee → ankle → 脚掌
  └ upper           上半身：腰段（rotation = 腰）
    ├ torsoLower    ← 「胸方块下面那一块」= 腰段（占躯干 42% 高）
    └ spine1        下胸段枢轴，y = 0.72 × bodyHeight（v9s.72，段数 ≥3 才有）
      ├ torsoMid1   ← 中间那块
      └ chest       上胸段枢轴（= 躯干顶）
        ├ torsoUpper ← 最上面那块
        ├ headPivot → headYaw → 头
        └ shoulderL/R → 肘 → 手 → 武器
```

所以：**胸下面那块是腰（`torsoLower`），不是胯**。胯（`pelvis`）是腰段底边所在的那条线，
v9s.70 之前**完全不可见**（空节点）；腿根 `hipL/R` 挂在 `lower` 上、位置正好在 `pelvis` 原点。

由此带来一个必然现象：`lower` 与 `upper` 是**兄弟节点**，两者都在髋高旋转。
腿根转 `hipYaw` 时腰段不会自动跟着转 —— 躯干的偏航必须由自己这一支补出来。
补得不对，链上就会断开（下一节）。

## 2. 偏航必须沿链单调：髋 → 腰 → 胸

`chestYaw = chestYawFromHip(hipYaw, 0.6, 40°)`：下盘偏 40° 时给胸 24°。

v9s.66 把这一份写进 `upper` 再按 58/42 摊，胸段只吃 42%（24° → 10°），看起来「胸根本没动」。
v9s.66 的修法是**分账**（`spine.yawChest`，胸拿 70%）。分账解决了「胸不动」，
但漏了一件事：**腰段是从 0 起算的**。

实测（站姿，`postureDebug` + 世界朝向）：

| | hips（`lower`） | 腰段（`upper`） | 胸段（`chest`） |
|---|---|---|---|
| v9s.66 | 8.6° | **7.0°** | 13.9° |
| v9s.70 | 8.6° | **11.5°** | 13.7° |

8.6 → 7.0 → 13.9 是**先减后增**：腿根已经转过去了，腰却「转回来」一点，胸再转出去。
画面读作腰被拧了一下 —— 这就是用户说的「lower 转了、torsoLower 还朝面朝向、torsoUpper 又转了」。

修法把腰段**锚在髋上**：

```
腰段 = hipYaw + (躯干总角 − hipYaw) × chainBlend      // chainBlend 缺省 0.58
胸段局部 = 躯干总角 − 腰段                            // 胸的世界朝向不变
```

两条不变量：**总角不变**、**胸的世界朝向不变**（`chest` 是 `upper` 的子节点，两者之和就是它的世界角）。
变的只有腰段停在髋与胸之间的哪个位置。`chainBlend = 0.58` 时，
`hipYaw = 0` 退化成 `总角 × 0.58` —— 与 v9s.66 逐位相同，只有「下盘带转」时才真正生效。

验收：`tests/v9s33-spine.test.ts`、`tests/v9s66-pose-space.test.ts` 都断言
「腰段夹在 `[髋, 胸]` 区间内」—— 这就是「连续」的可测形式。

## 2.1 段数：从「两级台阶」到一条曲线（v9s.72）

v9s.70 把偏航修成单调之后，还剩一层结构性问题：**躯干只有两个关节**。
每一级都是「整块方块绕自己的底边转」，两级之间必然掀开一个楔形缝，
v9s.70 只能靠补块去盖。行业做法不是补块，而是让旋转**沿骨链逐级衰减** ——
Unreal 的 `Layered Blend per Bone` 里那个 `Blend Depth` 干的正是这件事。

`view.animation.spine` 新增两个旋钮：

| 旋钮 | 含义 | 缺省 |
|---|---|---|
| `segments` | 段数（2 = 旧的腰/胸；3 = 腰/下胸/上胸；上限 4） | 3 |
| `pivots` | 各关节高度（相对躯干高，自下而上，长度 = 段数 − 1） | `[0.42, 0.72]` |

第一个 pivot 与老的 `chestPivot` 同位，所以**腰部折点不动**，只是上半身多了一道折。
分配数学在 `presentation/spine-chain.ts`（纯函数，可单测）：

```
俯仰/侧倾：w_i ∝ lerp(waist, chest, i/(N−1))，归一化      // N=2 时 = 旧公式
偏航：累计 C_i = hip + (总角 − hip) × c((i+1)/N)，c(x) = x^p，p 使 c(1/2) = chainBlend
```

两条不变量：**权重和为 1**（总角一分不改）、**累计曲线末项恒为 1**（胸的世界朝向 = 总角）。
`N = 2` 时两个公式都退化成 v9s.70 的原式，逐位相同 —— 老调校不用重调。

实测（鱼人站姿，世界俯仰）：v9s.70「0 → 16.6 → 37」两级台阶，v9s.72「29.0 → 42.7 → 54.2」，
每级约 12.7°，缝按 `sin` 缩小到 1/3。偏航同样单调：`8.6 → 10.4 → 11.6 → 12.6`。

### 2.2 这一版踩的坑：链的起点是 0，不是髋

`upper` 的父节点是 `pelvis`（yaw 恒为 0），**不是 `lower`**。髋与躯干是兄弟。

第一版把累计角的起点写成 `hip`：`local_i = C_i − C_{i−1}`，`C_{−1} = hip`。
于是所有局部角之和等于 `总角 − hip` —— 整条链平白少掉一个 hip（实测 0.2 rad），
表现是「头跟着身体转走了、帧尾守卫报 leak 0.017、胸偏航符号偶尔翻转」。
正确写法是 `C_{−1} = 0`：末级累计必须落回 `总角`，而**首级的世界角**才锚在髋上。

可测形式（`tests/v9s72-spine-chain.test.ts`）：每一级的世界角都夹在 `[髋, 总角]` 之间。

## 3. 俯仰的新问题：楔形缺口（v9s.70）

偏航修好之后，同一件事在**俯仰**上还有一半没解决，而且这次是几何问题：

- 体态把腰段压到 37°、胸段再折到 54°，两块方块绕**各自的底边**转，
  转角外侧（背面）会掀开楔形缝，内侧（腹面）互相插进去；
- 骨盆是空节点，腰段与它之间那一级台阶最陡（0° 对 37°），
  背面缺口 `sin(37°) × torsoD/2 ≈ 8.8cm` —— 38° 俯视能**直接看穿**到身体另一侧。

两条修法，一个思路：**每一级台阶都要被上一级的方块盖住**。

| 位置 | 做法 | 参数 |
|---|---|---|
| 骨盆 → 腰 | 加一块 `hipMesh`（宽 0.96×、深 1.10× 躯干），转 `腰段角 × hipShare` | `hipShare = 0.45` → 台阶变 0° → 16.6° → 37°，每级缺口 ≤ 4.2cm |
| 每一级 | 方块向上多长一截，藏进**更宽 4mm** 的上一级里（直立时不可见） | `min(0.06, h × 0.3)`，仅鱼人 |

> v9s.72 起把「每级补块」推广到了任意段数：第 i 块宽 `bodyW + i×4mm`、高 `h + pad`，
> 上一级永远比下一级宽，顶面那一截就被盖住。段数提到 3 之后，每级折角降到 1/3，
> 补块从「主要手段」退化成「兜底」。

`hipMesh` 挂在 `pelvis` 而不是 `upper`：它是「髋」这个位置本身的质量，腿和腰都从它长出去；
挂在 `upper` 会跟着腰一起转，缺口只是被搬到骨盆下面。`hipShare = 0`（不转）缺口回来，
`hipShare = 1`（跟腰同角）缺口挪到骨盆底下 —— 0.45 是「劈成两级」的那一档。

假人（`dummy-rig`）没有脊柱分段，`upper` 直接吃满 55°，台阶比主角更陡，
所以同一块 `hipMesh` 也补在假人身上（码头三只杂兵）。

## 4. 局部空间 vs 模型空间（v9s.66 的真正病根）

`arm.root.rotation.x -= back` 这条式子的含义是「绕**父节点当前的 X 轴**转」。
父节点是胸段，胸段一旦被偏航 20°、或者骨盆侧倾 8°，它的 X 轴就不再指向角色的左右 ——
同一个 `-= back` 变成「斜着往上掰手臂」。鱼人那种扁宽躯干上，读作两只爪子朝侧前方支棱。

模型空间（= 骨架根节点 `root` 的局部空间）里做，式子变成一次共轭：

```
q_node' = q_parentInModel⁻¹ · R · q_parentInModel · q_node
```

- 父节点没转时 `q_parentInModel = I`，退化成 `q_node' = R · q_node` —— **既有调校逐字节不变**；
- 父节点转了，旋转轴仍是模型的轴，读作「在角色正面往回压」；
- 只改四元数不改 `rotation.order`，后续 `rotation.x +=` 照样能叠。

代码：`presentation/rig-space.ts`（`rotateInModelSpace` / `pitchInModelSpace` / `yawInModelSpace`，
纯四元数运算，不刷新世界矩阵，可以在写完某根骨的同一帧立刻调用）。
用在：上臂回正（`armDrop`）、脚锁。验收：`tests/v9s66-pose-space.test.ts`。

## 5. 脚锁：IK 只负责位置，不负责朝向

两骨 IK 反解的是髋 / 膝角。脚掌挂在膝的末端，髋膝一拧，脚掌跟着被拧 ——
脚还钉在原地，但**脚掌在地面上缓慢转向**，读作打滑。

v9s.66 在 `knee` 与脚掌之间插了 `ankleL/R`（`voxel-rig` / `dummy-rig` 同构），
`applyFootIK` 反解完髋膝后把踝的**模型空间朝向**拧回 IK 之前：

```
目标 = quatParentInModel(ankle)      // 只取父链，不含踝自己的局部旋转
局部 = 新父链⁻¹ · 目标
```

两点必须注意：

1. **只取父链**。把踝自己的局部量算进基准，上一帧的补偿会被当成新基准，逐帧累加，
   脚腕会一直往里拧（实测 5 帧拧到 100°）。
2. **踝的局部旋转归 IK 独占**。其它层不要再写 `ankle.rotation`，否则脚锁会把它当噪声抹掉。

副作用：`footTip` 从「挂在 knee 下 y=-legLen/2」改为「挂在踝原点」。
`squash & stretch` 原本改写 `tip.position.y` 来跟随骨长，现在改成移动 **ankle** ——
两者都动就会双倍偏移（实测误差正好 0.195m = 腿长一半，`smoke` 里表现为脚悬空）。

## 6. 分层的目标形态：additive（增量）而不是「一堆 = 」

现状是**加权求和**：每层拿一个 0~1 权重、`upper.rotation.x += w * angle`。
它便宜、可控，但有三个天花板：层与层互相看得见（改 A 就要重调 B）、
无法表达「这一层的意图是相对某个参考姿势的差值」、欧拉角相加在大角度下不保序。

### 6.1 别家怎么做（可查证的四处）

| 来源 | 做法 | 对我们意味着什么 |
|---|---|---|
| [ozz-animation](https://github.com/guillaumeblanc/ozz-animation/tree/refs/heads/develop/samples/additive)（Guillaume Blanc，开源运行时） | 离线构建 `delta = reference⁻¹ · pose`（逐骨、逐关键帧），运行时 `base · nlerp(identity, delta, w)`；参考姿势默认取动画第一帧 | 用户提的「攻击 pose − 攻击基础 pose」就是这条公式；**权重通过「从单位四元数插值」实现**，不是缩放角度 |
| Unreal「Layered Blend per Bone」 | Branch Filter 指定骨骼，`Blend Depth` **沿链逐级衰减权重**（depth=2 → 子骨 1.0、指定骨 0.5），官方文档原话是「where it will have all of the child bones have 100%…allows you to get a smooth blend（让脊柱渐变而不是断在一个关节）」 | 我们这一轮做的「把弯折摊到骨盆/腰/胸三级」正是 Blend Depth 的方块版；真要做细，应支持 **>2 段**的锥形分配 |
| Unity Layer（Override / Additive）+ Avatar Mask | 一层一个 mask 与混合类型；mask 就是逐骨权重 | 我们目前是「代码里按名字写死的分配」，要变成数据就得有 mask |
| Epic 官方论坛（UE4 角色动画直播问答） | 髋（pelvis）是根骨，**没法和其他动画做 50/50**；要做只能给腿加 `Blend Depth = -1` 把它排除掉 | 这解释了为什么「髋块吃 45% 而不是 50%」是合理近似：根骨只能靠「下游骨骼开洞」来间接分账 |

两处直接印证了我们踩过的坑：

- **约定必须一致**：delta 用哪一侧乘（`reference⁻¹ · pose` 还是 `pose · reference⁻¹`），
  构建与叠加就必须用同一条 —— 混用会「绕错轴」。这正是 v9s.66 的上臂回正 bug。
- **增量层要克制**：社区经验是「最多 2~3 层增量、值要 clamp、参考姿势必须与基础动画一致」，
  否则会骨爆炸 / 在错误的基础姿势上叠加。

### 6.2 目标形态

```
最终姿势 = 基础姿势（个性 pose）
          ⊗ 增量层₁ = 攻击姿势 ⊗ 攻击参考姿势⁻¹     （权重 w₁ = attackBlend）
          ⊗ 增量层₂ = lean（倾斜）                  （权重 w₂）
          → 最后才是程序层：足 IK、脚锁、look-at
```

| 要素 | 做法 | 本仓库对应 |
|---|---|---|
| 基础姿势 | 每个受控节点一个四元数 | `CharacterPosture` 目前是欧拉角参数，够用 |
| 增量 = A ⊗ B⁻¹ | 两个姿势快照逐节点做差，再转到模型空间 | `quatInModel` + `rotateInModelSpace` 已经够 |
| 权重 | `slerp(identity, delta, w)` | `lockModelRotation` 就是这个形状 |
| 叠加顺序 | 基础 → 增量（按注册顺序）→ 程序层 | `voxel-rig.update()` 的 2.x / 2.96 / 3.x / 4 段 |
| 禁止项 | 增量层不许写 `position`（骨盆位移会互相打架） | 骨盆位移仍留在独占通道 |

落地顺序（不建议一次全换）：

1. **已经完成**：模型空间工具 + 上臂回正 + 脚锁 + 偏航沿链单调（都是「补偿被写错坐标系」的地方）；
2. **下一步**：攻击层改成 `delta = 攻击姿势 ⊗ 攻击基础姿势⁻¹`，权重走现有 `attackBlend`；
   好处是「换武器 / 换体型」时不用重调每一帧的绝对角度；
3. **再下一步**：`lean`（惯性侧倾）提到最外层做增量，和攻击层解耦；
4. **最后**：`posture` 从参数表变成「一份基础姿势快照」，`splitSpine` 退化成它的一个特例。

## 7. 已知边界

1. 模型空间工具**只处理旋转**。位移（骨盆前后上下、头前伸）仍走各自通道，混进增量层会互相覆盖。
2. 脚锁假设踝的局部旋转没人用。将来若要做「脚尖点地 / 踮脚」，得给它一条显式的优先级通道。
3. `splitSpine` 的泄漏守卫按**整条链的欧拉角之和**校验；凡是绕模型轴转的层
   （现在只有上臂）都不能写进躯干节点，否则读数不再等于总角。
4. `chainBlend` 是「中点停在哪」，用幂曲线 `x^p` 反解 —— 段数变化时曲线形状会跟着变，
   段数从 3 改成 4 需要重新看一眼腰段位置（曲线中点不变，但第 1、2 级的分配会变）。
5. 偏航的 `chainBlend` 目前**只作用于躯干总角**（下盘带转 + 攻击旋身 + 站姿斜跨一起算），
   没有按「来源」分开 —— 想做「旋身从腰起、下盘带转从髋起」得先引入逐层 mask，见 §6.2 第 3 步。
6. 补块的重叠是**常数**（`0.06 / 0.3×h`），不随实际折角变化；
   若将来把 pitch 开到 70° 以上，需要按 `sin(折角)` 动态加长。
