> 管什么：智能相机（威胁权重 → 推近 / 拉远 / 平移 / 俯仰）、前方扇区软锁定、两级注视（威胁 / 重要目标）、
> **测试截图机位**（`shot-cam.ts` / `tools/shot.py`）。
> 相关：朝向四角分离见 [`movement-facing.md`](movement-facing.md)。

## 智能目标辅助（v5）

`core/targeting.ts` 是独立模块（`modules.targeting` 可开关）。每帧在**当前面朝向的前方扇区**内挑选优先目标：

- 参考朝向：有移动输入时取输入方向（转身意图即时生效），否则沿用上一帧 `facing`。
- 候选条件：水平距离 ≤ `range`（7m）且与目标方向夹角 ≤ `maxAngleDeg`（90°，半角）。**背后的敌人不会被强行锁定**，避免玩家背对敌群时攻击莫名扭头。
- 评分 `score = dist - frontBias × cos(夹角)`，越小越优先 → 更近且更正面的敌人胜出。
- 结果写在 `world.targeting { targetId, targetYaw, targetDist, hasTarget }`，表现层在目标脚下画一个**金色指示环**（带轻微呼吸），HUD 显示 `target #id @距离`。

由此带来三条行为：

| 行为 | 规则 |
|---|---|
| **朝目标方向攻击** | 起手时 `attackFacing = targetYaw`（优先于摇杆方向），锁定后挥击过程中不变；关闭 `targetAssist` 后退回「按摇杆/面朝向」的基础行为 |
| **动态前冲** | 有目标时 `lunge = clamp(targetDist - idealRange, 0, 基础lunge × maxLungeScale)`：目标远则最多放大 1.6 倍追近，目标已在理想距离（1.35m）内则**不再前冲**，避免怼到敌人身上。每击结束趋向与敌人保持理想间距 |
| **弓蓄力面向目标** | 按住弓蓄力期间 `orientation` 把 `facing` 覆盖为 `targetYaw`（压过摇杆方向），松手 / 换武器即恢复 |

配置在 `core.targeting`：`range / maxAngleDeg / frontBias / idealRange / maxLungeScale / targetAssist`，调试面板「目标辅助」分组可热改。

## 测试截图机位（v9s.77）

### 1. 为什么不能直接用游戏相机

`camera-rig.ts` 是给玩家看的，不是给截图用的。三个硬约束叠在一起，特写一张都拍不出来：

| 约束 | 代码位置 | 后果 |
|---|---|---|
| 注视点写死「脚下 + 0.6m」（腰高） | `camera-rig.ts` 的 `snap()` | `snapCamera(x, y, z)` 传脚下坐标，相机永远看腰。想拍脚就把脚挤出画面 |
| 智能构图把角色往一侧推 | `smart.offsetX`（威胁质心方向） | `yaw ≠ 0` 时世界偏移被转成横向，角色偏到画外 |
| 每帧重算 + 叠震动 / 微推 | `cam.update()` | 截图必带抖；命中瞬间画面位移几厘米 |

v9s.76 拍脚掌折角时，四张特写全是腰以上 —— 不是机位没调对，是相机在跟一个不可控的注视点。

### 2. 三个概念

```ts
view.shotTake({ anchor: 'node', node: 'ballL', eye: [0.45, 0.05, 0], fov: 24 });
```

- **anchor**：跟什么。`hero`（角色根：脚底原点 + 角色朝向）/ `node`（骨架里的命名节点）/ `world`（固定世界点）。
- **eye / look**：相对锚点的**偏移**（米），不是绝对坐标。两个点定一条视线 —— 比给欧拉角可靠，
  不用想轴序、局部轴、yaw 正负。`world: true` 时按世界方向解释（只跟位置，不跟朝向）。
- **fov**：特写用小值（20~30）压缩透视；广角会把 0.18m 的脚拍成一只拖鞋。

`shotRelease()` 交还游戏相机并还原 fov / 补光 / 法线着色。

### 3. 接管时机

每帧在 `cam.update()` **之后**、`renderer.render()` 之前覆盖（`three-scene.ts` 主循环）。
放 update 之后而不是「让 update 走分支」，是因为相机还被 `projectPoint` 等读数用着 ——
覆盖比改分支简单，也不会漏掉 near / far / aspect 的同步。

`release()` 后下一帧 `update()` 自动接管回去，不需要额外通知。

### 4. 自动取景

```ts
view.shotFit('footTipL', [1, 0.3, 0], /* pad */ 1.2, /* fov */ 26);
```

按 `pad` 反算距离，让目标填满画幅（`pad: 1.2` = 四周各留 10%）。

两个必须踩过的坑：

- **用 tan 不用 sin**。`radius / sin(half)` 是「外接球内切」的解，对扁平的矩形系统性偏远。
  正确式子是 `dist ≥ 目标半高 × pad / tan(halfV)`。
- **分方向算**。只取一个「垂直面上的最大半径」不行 —— 那个半径是斜的，投影到屏幕只占一部分。
  实际按屏幕竖直 / 水平两个方向分别量展开量，取更大的距离（宽画幅下水平才是瓶颈）。

实测：不分方向按 sin 算，一只脚只填到画幅 72%；改正后 `pad 1.15` 填到 90%（宽度约束）。

- **空锚点会向上退**。`footTipL` 是纯 `Object3D`、没有几何，包围盒是空的 —— 退到第一个有
  几何的祖先（`ankleL`），并在 `info.measured` 里报出来，避免「我让它拍脚末端、它拍了一整只脚」
  这种无声降级。

### 5. 补光与法线着色

场景是暗色调夜景，鞋色接近纯黑（反照率≈0）：

- **补光**（默认 1.2）**必须斜着打**。放在相机位置 = 平光，所有朝向的面一样亮，拍出来是一团
  没有结构的黑。抬到斜上方 38°、侧偏 25°，顶面才比侧面亮，折角两侧的倾角差才变成明暗差。
- **法线着色**（`--xray`）是几何验收的兜底：按面朝向上色，折角 = 颜色不同，穿地 = 边缘被地面
  切掉。这是技术视图，**不是给玩家看的画面**。近黑材质在任何补光下都读不出折角，只能用这个。

### 6. 已知边界

| 边界 | 说明 |
|---|---|
| 姿态在动时取景会偏 | `fit` 按当帧包围盒算距离，待机斜跨 / 呼吸会让下一帧的盒子变。要稳定就 `--paused` |
| `--paused` 停的是 Core 的 `step` | `render` 照常跑，`rig.update` 每帧仍执行 —— 所以能钉相位，也能截到动画 |
| 蜘蛛 / 鱼人有自己的骨架 | `anchor: 'node'` 只查主角骨架；蜘蛛的多足节点名不同，需要时另加 |
| 法线着色会 clone 材质 | 只在接管期间，`release()` 还原；忘记 release 会让角色一直是彩色的 |
