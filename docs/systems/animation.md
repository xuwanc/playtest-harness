> 最后更新：2026-11-09（v9s.44）。
> 管什么：一段动作怎么切锚点与窗口、动态平衡怎么做、节奏怎么排、踩过的坑、加新动作的检查清单。
> 这是**规范**（当前有效）；按版本追加的落地细节在 `animation-notes-1/2/3.md`。
> 代码：`src/presentation/voxel-rig.ts`（主体）、`program-anim.ts`（纯函数）、`gait.ts`（步态）、`config/game.json` → `view.animation`。

## 一、连击骨架：锚点与窗口

### 1.1 「对齐同一个 pose」只对了一半

「每击首尾对齐起始 pose」方向是对的，但**单一 pose 会把三连击变成同一次攻击打三遍**。
实战里用的是**锚点集合**：

| 锚点 | 用途 | 典型姿态 |
|---|---|---|
| `guard` | 默认待机 / 收招归位 | 剑在右前下方，重心居中 |
| `left-finish` | 段 1 收势、段 2 起手 | 剑在左后，右肩前送 |
| `right-finish` | 段 2 收势、段 3 起手 | 剑在右后，左肩前送 |

相邻段**共享**一个锚点就够了，不需要全段对齐。段 1 收在 `left-finish`，段 2 就从
`left-finish` 起手；段 2 收在 `right-finish`，段 3 从 `right-finish` 起手。

> **对齐的不只是手**。手对上了、骨盆没对上，换段时脚会滑一步。锚点至少要锁
> `bodyYaw`、`pelvisX/Z`、`rootYaw` 三项。

**本项目的现状**：走的是「连续承接」而不是「共享锚点」——段 2 的起手是段 1
收势的延长线，段与段之间**故意**不收敛到同一个点。这带来一个必须知道的副作用：

> 段首的幅度由 `attackBlend` 淡入，本来就接近中位；段末是满幅。两者天然差
> **100~170°**（`npm run clip:lab:combo` 实测：大剑 162°/169°、双持 136°/30°）。
> 这个差只能靠 `segBlend`（默认 0.08s）掩过去。

**两条路线，不要混用：**

- **共享锚点**：换段零跳变，但动作幅度受约束，适合轻武器 / 快速连段。
- **连续承接**：动作舒展，但换段必然有跳变，必须把 `cancelWindow` 放在
  「下一段起手方向」上，且 `segBlend` 不能太短。

### 1.2 连击窗口不在「下一招 pose」

你写的是「攻击进行到下一招的 pose 时放缓，给连击窗口」。**时序反了**。

下一招 pose 还没发生，谈不上在那时开窗口。真实的窗口在**挥击到位之后、收势走完之前**：

```
起手 ──── 前摇 ────► 挥出 ──► 命中 ──► 保持 ──► 收势 ──► guard
                          ▲              │
                          └── 窗口从这附近开 ──┘（cancelWindow）
```

- **窗口内按下一击** → 直接切段，跳过剩余收势。这是「连打跟手」的来源。
- **窗口过期** → 老老实实跑完收势回 `guard`。

**本项目**：`core.combat.cancelWindow = 0.45`（按攻击进度归一）。

v9s.28 修了一个真问题：旧的挥出曲线在 `progress = 0.50` 才走满，而窗口
`0.45` 就开了 —— 玩家连打时**剑才走到 64% 就被切走**，衔接处实测跳 85~117°。
现在挥出提前到 `0.42`，窗口打开时动作已经到位。

> **自检**：`cancelWindow` 必须 ≥ 挥出完成点。否则最"爽"的连打方式恰好是最难看的那条路径。

### 1.3 「放缓」只应该发生在命中之后

不要全程减速。正确的三处变速：

1. **前摇**：慢，可带一点反向预备。2. **挥出**：最快，且**持续加速**到命中（ease-in）。
3. **命中后**：保持满幅 3~8% 的时间（hit stop / follow-through hold），再回落。

本项目的 `swingCurve`（`src/presentation/voxel-rig.ts`）就是这条曲线：

```ts
if (t < 0.22) return -1;                        // 前摇：停在起手
if (t < 0.42) return -1 + ((t - 0.22) / 0.2) * 2; // 挥出：20% 走完 -1 → +1
if (t < 0.5)  return 1;                          // 保持：8%
return Math.max(0, 1 - (t - 0.5) / 0.5);         // 收势：50%
```

### 1.4 下盘：一步 = 半圈，且要接着上一段走（v9s.41）

手可以对锚点，**腿不行**。腿是一条连续的步态曲线，段与段之间如果「每段都从同一个基准
摆出去再摆回来」，读起来就是「同一个动作重播三遍」——用户的原话是
**「攻击跨步之时，再接跨步攻击没有换腿跨步」**。

| 写法 | 每段结束 | 连段观感 |
|---|---|---|
| `phase = 基准 + π × bump(p)`（往返，v9p~v9s.40） | 回到基准，与出发姿态完全一样 | 每刀都同一条腿迈出去；在 recovery 中途取消时相位被硬拽回基准，实测**单帧腿角跳 0.82 rad**（脚像被拽回去） |
| `phase = 基准 + π × smoothstep(p)`（单向，v9s.41） | 停在基准 + π = **另一条腿在前** | 下一段从这里接着走，自然交替；段边界零跳变（实测 < 0.003 rad） |

三条配套规则：

1. **段起点接上一段停下的相位**：`attackPhaseBase` 在新段（Core `attackId` 变化）时
   取上一帧实际输出的相位，不要每段重新锁基准。
2. **步序用单调计数器，不用 `comboIndex`**（1/2/3/1 → 第 3 段与下一轮第 1 段同奇偶）；
   `attackStepIndex` 每段 +1，只增不减。
3. **站着连点也要接上一刀**：玩家不动时 Core 的 `gaitPhase` 冻住，用它当基准等于永远
   同一条腿；只有「正在移动」或「本次运行第一次攻击」才对齐真实步态相位。

同一条规则也用在 `applyStep` 的骨盆偏移上：段间取消时 `swingCurve` 从 0.6 掉到 0，
旧版骨盆一帧退回 **8.7cm**、侧跨直接翻号；现在三个偏移量指数趋近（τ≈85ms），
换段变成 0.2 秒的体重转移（单帧 ≤ 3cm）。

> 判据不要用「每段腿角峰值符号」（幅度包络在 active 段才涨，峰值随打击帧漂移），
> 用**段起始相位**：相邻段之差应落在 `[0.5π, 1.2π]`。验收
> `tests/v9s41-attack-step-legs.test.ts`、`npm run smoke`「连击跨步左右换腿」。

### 1.5 相位怎么看（v9s.42）

`attackGaitDrive` 的相位看不见，调参只能凭腿的观感猜。手感面板第三区把它画成 `sin φ`
并按踩地侧分色（细节与三个坑：[`animation-notes-3.md`](animation-notes-3.md) §17）。

### 1.6 换向：摆腿方向是个「符号」，不能一帧翻过去（v9s.43）

前后摆幅 = `dirF × wF × 步幅/4 × off(φ)`。`dirF` 原本是硬符号
（`localForward >= 0 ? +1 : -1`），速度穿过 0 的那一帧整条腿位被**镜像**，
读起来就是「前进切后退，腿抽一下」：

| 场景 | 旧行为最大单帧跳变 | 融合后 |
|---|---|---|
| 注视锁定、原地倒走（纯前后） | **1.06 rad**（61°） | 0.55 |
| 边转身、边滑动（本机最常见） | **1.26 rad**（72°） | 0.55 |
| 左右横移换向 / 参考：正常跨步 | 1.21 / 0.53 | 0.55 / 0.53 |

修法只有一句话：**把符号变成 −1..1 的驱动量，换向时按 `dirFlipSec` 走过 0**，
摆幅随 `|dirF|` 收放（等价于两套姿态交叉淡入），腿先并一下再朝新方向迈出。

两条约束：① **不能按速度淡出**（摆幅按步幅定、与速度无关，反向那一帧只有 0.43 m/s
却仍是满摆幅，按速度淡会把慢走削成碎步）；② **左右轴同构**（`dirR` 同一条通道）。

细节与三个坑见 [`animation-notes-3.md`](animation-notes-3.md) §18；验收
`tests/v9s43-reverse-blend.test.ts`、`npm run smoke`「换向不抽腿」。

### 1.7 朝向切换：下盘不能自己拧（v9s.44）

「一边跑一边让身体转向」时下盘会整体晃一下：下盘偏转目标有「侧移族」（θ=90° 时 +50°）
与「后退族」（θ=132° 时 −48°，v9s.14 的踩地对轴），身体转动让 θ 扫过 90°→132°，目标只能
跳族（实测单帧 52.7°、整条 S 摆幅 57°）。修法：**身体自己在转的时候，胯不自己拧**
（30°/s 起、100°/s 满的角速度闸门）—— ① 转身期间停在侧移族；② 目标限速
`hipYawTrackRateDeg = 200°/s`，纯转身直接冻住。0.5s 转 180° 的摆幅 57° → 0.5°、
单帧 13.5° → 0.1°。两条边界：**不能一刀切限速**（世界速度换向时下盘要全速跟，否则摆动轴
错开，v9s43 用例 0.55 → 0.63 rad）；**停用后退族只在转身期间**（松开要交还，否则斜向
倒退的对轴失效）。三个坑与验收见
[`animation-notes-3.md`](animation-notes-3.md) §19 / `tests/v9s44-hip-yaw-track.test.ts`。

## 二、动态平衡

### 2.1 副手反向是对的，但有三个补充

你提的「挥左手时右手往右后方收」正确。补充：

**① 反向配重有上限。** 双手同柄武器（大剑）做不了反向——副手被 IK 锁在柄上。
只有单手 / 双持才适用。

**② 反向的意思是「副手往自己那侧后方」，不是「往主手的反方向」。**
右手挥出时，左手往**左后**收（不是往右）。这样两把剑是展开的，不是交叉的。
本项目双持中段实测主副手分离 **49.8°**（段 1）；低于 45° 时两把剑视觉上会重合。

**③ 反向的不只是手。** 完整的配重链是：

| 部位 | 动作 | 通道 |
|---|---|---|
| 骨盆 | 向挥击反方向平移 3~7cm | `pelvisX` |
| 躯干 | 侧倾（roll）与挥击方向相反 | `bodyRoll` |
| 肩膀 | 主手侧前送、副手侧后拉 | `shoulderPush` / `shoulderIn` |
| 头 | **不跟着甩**，保持朝目标 | —（当前不做头部独立控制，靠躯干幅度控制） |

### 2.2 舒展 ≠ 幅度大

「动作要舒展」的判据是**关节行程**，不是剑尖扫过多大的角。

- 挥击结束时肘应该接近伸直（本项目 `elbow` 从 `-0.5` 收到 `-0.12`）；
- 起手时肘应是屈的（`-0.5` 左右），才有「蓄力」的形；
- 全程肘角不变 = 抡胳膊，看着像假肢。

双持第三击「展开旋身」是本轮最典型的例子：`armYaw` 从 1.7 展开到 2.1、
`elbow` 收到 `-0.05`（几乎伸直）、两把剑 pitch 保持 3~12°（水平），
刃身分离 **169°** —— 这才叫舒展。不是把剑举高。

## 三、节奏

### 3.1 慢快慢的量化

你说「慢快慢或快快慢」是对的，但需要落到数字上才可执行：

| 阶段 | 建议占比 | 说明 |
|---|---|---|
| 前摇 windup | 18~38% | 最短不能少于 15%，否则看不出预备 |
| 挥击 active | 15~32% | **必须最短**，这一段是爆发 |
| 收势 recovery | 40~60% | 短于 40% 会「刹不住」，长于 70% 拖沓 |

本轮实测（`npm run clip:lab:combo`）：

| 武器 | 前摇 | 挥击 | 收势 |
|---|---|---|---|
| 大剑 | 23% | 26% | 51% |
| 双持 | 20% | 29% | 51% |
| 剑盾 | 20% | 28% | 52% |

**问题**：三种武器、三段的配比**完全一样**。读起来就是「同一个动作点三下」。
下一步应该做成逐段递减：第 1 击 25/25/50、第 2 击 18/25/57、第 3 击 35/20/45。

### 3.2 帧数下限

挥击段在 60fps 下**不能少于 5 帧**（83ms）。少于此刀光来不及成形，
表现层会看起来像「闪了一下就结束」。

按本项目双持最短的 `active = 0.10s` 算，正好 6 帧——这是下限，不要再短。

### 3.3 三连要有起伏

同一套动作连打三次，节奏必须变化，否则玩家感受不到「连段」：第 1 击建立节奏（中速）、
第 2 击更快（承接动量，前摇可砍到 60%）、第 3 击重（前摇与收势都明显更长，它是终结技）。

## 四、容易踩的坑（都是本项目真踩过的）

### 4.1 别让语义漂移

`bladePitch` 是**剑身相对水平面的世界仰角**，不是「相对前臂的角度」。
v9s.25 之前写成了后者，结果手臂一抬高，剑尖就朝天——前两击看起来像举着剑走路。

> 语义一旦定死，改它就要重调所有数据。宁可新加通道，不要偷偷改含义。

### 4.2 语义通道不等于骨骼旋转

`armYaw` 曾经是个**假通道**：`shoulder.rotation.order = 'ZYX'` 让它变成了
「绕手臂长轴自转」，实测 −1.4 → 0 只让刃身水平朝向变 25°。v9s.28 把顺序改成
`'YXZ'` 才真正变成肩的水平内摆。

> 加通道时先确认它**真的**能驱动目标自由度（用工具扫量程）；不够就改骨架，别硬调数据。

### 4.3 截图会骗人

斜俯视相机下，**水平指向远方的剑在画面上是「向上」的**。
v9s.26 因此误判了一次「剑举起来了」。

判断横扫必须读刃身两端的世界坐标：

```js
__harness.bladesWorld()   // { right: {base, tip}, left: {...} }
// 两端 y 差 < 0.03m 才是水平
```

### 4.4 稳态 ≠ 手感

`clip-lab` 的 `preview` 会定格后渲染 45 帧让腕部收敛，量到的是**稳态角度**；
真实连打时腕部一直在追，角度会有 ±10~20° 的滞后。

> 角度用工具量，手感必须实时连打看。两者不能互相替代。

### 4.5 命中帧要和视觉最快点对齐

判定结算的 `active` 段必须落在剑挥得最快的那一帧附近。v9s.23 之前 `active` 结束时
挥击曲线才走到 0.16——判定已结算、剑还在半路，观感是「挥了个寂寞」。

> 改 `windup/active/recovery` 之后，一定要用 `clip-lab` 重新确认 `active` 时间段内刃身已经扫过。

## 五、加一段新动作的检查清单

```bash
# 1. 扫角度：仰角是否水平、扫角够不够、有没有朝天
npm run clip:lab -- scan --weapon greatsword --seg 1 --steps 40 --shots

# 2. 连击结构：衔接跳变 / 节奏配比 / 主副手平衡
npm run clip:lab -- combo

# 3. 全段门禁：九段一起跑，不达标直接非零退出
npm run clip:lab:check
```

提交前确认：

- [ ] 横扫段刃身 `|pitch| < 15°`（是平扫，不是举着剑转身）
- [ ] 扫角：大剑 ≥150°、双持 ≥150°、剑盾 ≥120°、盾顶 ≤70°
- [ ] 双持主副手分离 ≥45°
- [ ] `cancelWindow` ≥ 挥出完成点
- [ ] 三段的节奏配比**不完全相同**
- [ ] 副手有反向位移（`pelvisX` 与主手方向相反），不是全身刚性平移
- [ ] 换段没有单帧跳变（`combo` 报告的衔接数 ≤130°）

## 六、留给下一轮的已知问题

1. **三连节奏同质**：三种武器九段配比完全一致，需要逐段差异化（见 3.1）。
2. **段首末跳变大**：连续承接路线的固有代价，要压到 70° 以内需把段首姿态往「上一段
   收势方向」重写，或改用共享锚点路线。
3. **举顶仰角受挂点链限制**：`gs.overhead` 写 `bladePitch = 1.62`（93°），实测只有 41° ——
   反解链在手臂过顶 + 有 roll 时饱和。要修得把 `mount.rotation` 改成用父节点世界四元数
   求解（成本较高，暂记）。
4. **头部没有独立控制**：视线始终跟着躯干走，连续转体时会「甩头」。
