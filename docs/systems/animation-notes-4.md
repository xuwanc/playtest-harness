## 十八、v9s.43：换向为什么不能「一帧翻符号」

用户原话：**「前向移动切后向移动时 腿会抽一下」**。

`solveGait` 本身是 C∞ 的（只有 sin/cos 与一条 C¹ 的 `plantOffset`），所以第一反应是
「数学没问题」。问题不在曲线，在**乘在曲线前面的那个符号**：

```
前后摆幅 footZ = dirF × wF × (stride × reachRatio) × off(φ)
dirF = localForward >= 0 ? +1 : −1        // ← 硬符号
```

速度穿过 0 时 `dirF` 一帧取反，等于把整条腿位**镜像**过去。`wF` 这时并不小（纯前后移动
`wF ≈ 1`），而摆幅是按**步幅**定的（`stride/4`，恒 ≈0.36m），与速度无关 —— 于是
反向那一帧（实测 0.43 m/s）脚等效瞬移 0.5m，读数上就是单帧腿角跳 1.2 rad。

三个数字先量出来再改（`tests/v9s43-reverse-blend.test.ts` 里保留了对照）：

| | 注视锁定（原地倒走） | 不锁朝向（边转身边滑） | 左右横移 |
|---|---|---|---|
| 旧 | 1.06 rad | 1.26 rad | 1.21 rad |
| 新 | 0.55 | 0.55 | 0.55 |
| 正常跨步单帧 | 0.53 | 0.53 | 0.53 |

也就是说：**换向那一帧现在不比正常走一步更激烈**，再压下去意义不大（自然动作成了主导项）。

做法（`gait.ts`）：

```ts
// 骨架层每帧推一次符号；state 是 −1..1 的**线性**值
dirF = slewDirSign(dirF, drive.localForward >= 0 ? 1 : -1, dt, gaitCfg.dirFlipSec);
// solveGait 里再映射成两端速度为 0 的系数
const dirF = dirDrive(input.dirF ?? (localForward >= 0 ? 1 : -1));
```

- `slewDirSign` 匀速走 `|Δ|=2/sec` 的步长（`−1 → +1` 正好 `dirFlipSec` 秒）。匀速是刻意的：
  峰値单帧变化最小；smoothstep 会让峰值变成 1.5 倍。
- `dirDrive` 是 `sign(x)·smoothstep(|x|)`：`|x| = 1` 时逐位等于旧的 ±1（稳态零差异），
  0 附近衰减更快 → 腿在换向中点真正并拢，不会「一半镜像」。
- 左右轴 `dirR` 同一条通道。顺带把抬膝的领先量从 `lead > 0 ? 0.2 : 0` 改成
  `0.1 × (1 + side·dirR)` —— 旧写法在 `dirR` 过 0 时会让两条腿的抬膝差一帧跳一格。

### 三个坑

1. **不要按速度淡出**。看着「反正换向时速度很低」就想 `amp *= speed`，会把慢走削成碎步
   （v9o 踩过：低速巡航被误判成停步，腿冻住、身体平移 = 滑行）。摆幅归步幅管，只有
   **符号翻转**才需要淡。
2. **stale 状态要用「最终 drive」而不是 realDrive 推进**。攻击期间 `drive` 是
   `attackGaitDrive` 的等效驱动（符号可能和真实速度不同），用 realDrive 推进会让收招
   淡出段的两套姿态互相打架。顺序必须是：`realDrive → attackGaitDrive → drive → 推符号`。
3. **停步收相期间也要传同一组符号**。`solveStopGait` 用的是冻结的 `stopFwd/stopRight`，
   正常情况下符号与它同向；若换向恰好发生在收相窗口里，`dirF` 还在半途，摆幅会跟着
   收相进度一起衰减 —— 这比「切回硬符号」更安全（切换才是一帧跳变）。

## 十九、v9s.44：朝向切换时，下盘为什么自己拧了一下

用户原话：**「朝向切换时，下盘会整体晃下，好像和 movedir 的切换有关」**。

### 它不是「角度不连续」

先用探针把整条轨迹打出来（速度方向固定，0.5s 内把 `bodyYaw` 扫 180°）：
`hipYaw` 从 0 爬到 **+24°**，再翻到 **−32°**，最后回 0。单帧最大 13.5°（810°/s），
而正常跨步单帧只有 0.53 rad（30°）。

`hipYaw` 的输出那层指数平滑（`hipYawSmoothing = 12`）本来就是连续的，所以问题不在
平滑，而在**目标本身**：`backHipYawTarget` 有两个「族」，身体转动时 θ 连续扫过
90° → 132°，两族在同一 θ 上差 ~100°，目标只能跳族。

| θ（身体局部移动方向） | 侧移族 | 后退族 |
|---|---|---|
| 90° | +50° | −90° |
| 99° | +49° | −81° |
| 112° | +44° | −68° |
| 132° | +31° | −48° |
| 180° | 0° | 0° |

`backStrafeKeep` 的 `flip = k²` 只在 100°~132° 之间过渡，于是那 30° 里目标要横穿
~97°：θ = 99° 时 +49°，θ = 112° 已经 −24°（实测单帧 52.7°）。

### 修法：身体自己在转的时候，胯不自己拧

物理上说得通：胯是被上身带过去的，不可能比身体本身转得还快。实现两层，共用一个
「转身闸门」`turnSpinGate(turnRate)`（30°/s 起、100°/s 满）：

```ts
const hipRate   = gaitCfg.hipYawTrackRateDeg * DEG;      // 默认 200°/s
const spinGate  = hipRate > 0 ? turnSpinGate(turnRate) : 0;

// ① 换族：转身期间停在侧移族
backHipYawTarget(bodyFwdRatio, latRatio, strafeYaw, backKeep, spinGate);

// ② 节流：目标最大转速
slewHipTarget(lastHipYawTarget, rawTarget, hipRate, dt, spinGate);
//   free = 1 - spin：
//   free = 1（没转身）→ rate ≈ FREE_RATE，等价于不限速，与旧行为逐位一致
//   free → 0（纯转身）→ rate → 0，目标冻住
```

`hipYawTrackRateDeg = 0` 时两层一起关（`spinGate` 直接置 0），精确回到旧行为，便于 A/B。

| 0.5s 转 180° | 旧 | 新 |
|---|---|---|
| 单帧最大变化 | 13.5° | 0.1° |
| 整体摆幅 | 57° | 0.5° |
| 反向过冲 | −32° | −0.5° |

> 图：`shots/v9s44/01-hip-yaw-turn.png`；数据：同目录 `v9s44-before.csv` / `v9s44-after.csv`
> （`hipYawTrackRateDeg = 0` vs `200`，同一段输入）。

### 三个坑

1. **一刀切限速会把「换向」也拖慢**。世界速度本身换向时（摇杆前推 → 后拉、身体朝敌人
   不动），θ 会在一瞬间翻 180°，下盘必须全速拧过去：腿的摆动轴 = 下盘前后轴，下盘
   跟不上就等于用错轴迈步。给所有情况都套 200°/s 时，v9s43「换向不抽腿」实测从
   0.55 掉到 0.63 rad（超过「正常跨步」这条线）。所以限速必须按**身体角速度**门控，
   而不是无条件。
2. **只冻目标、不冻输出**。`hipYaw` 自己那层指数平滑必须留着：转身结束时闸门一松，
   目标会一步跳到位（`free = 1` 时 rate ≈ 3400°/s），靠这层平滑把它摊成 ~0.2s 的
   追赶；连平滑一起冻住就会看到「转完卡一下再瞬间到位」。
3. **闸门开关处不能有跳变**。纯后退（θ = 180°）时两族都是 0°，所以最常用的那条
   路径上开关是连续的；真正的跳变只发生在 100°~180° 的斜后方，由节流兜住。
   另外 `turnRate` 必须用**未平滑**的 `wrapAngle(bodyYaw - prevBodyYaw) / dt`，
   用平滑过的值会让闸门比身体反应还慢半拍。

## 二十、v9s.45：慢放还抖，是「时间基准」错了

用户原话：**「慢放还是会抖下，看看有没成熟解决方案，或者前/后相位独立 hip 补偿偏移限制计算」**。

### 先量：常速干净，慢放不干净

同一个转身场景（跑步中把身体转 90°）跑两遍，只改 `debug.timeScale`：

| | 常速 1× | 0.25× 慢放 |
|---|---|---|
| 转身期间 `hipYaw` | 全程 0（闸门全关） | 9.1° → 15.1°（单帧 6°），目标冲到 21° 再回落 |
| W → S 反 180°，单帧最大 | — | **18.6°**（摆幅 25°，最深 −19.7°） |

同一个公式、同一段输入，只因为播放倍率不同就抖 —— 说明变量不是公式，是**时间**。

### 根因：闸门读的是「渲染帧」角速度

`turnRate = wrapAngle(bodyYaw - prevBodyYaw) / dt`，这里的 `dt` 是渲染帧步长。
慢放 0.25× 时身体转过同样角度要多花 4 倍真实时间，算出来的角速度只有常速的 1/4：
30°/s 起、100°/s 满的闸门**从「全关」掉进「半开」**。而 v9s.44 的限速率是

```ts
rate = free · (maxRate + free · FREE_RATE)   // FREE_RATE = 60 rad/s ≈ 3400°/s
```

`free = 0.5` 时还有 ~950°/s —— 半开等于放行，目标照样一帧蹿出去十几度。

### 修法（五条，互相配套）

1. **角速度走游戏时间**：`ΔbodyYaw / Δworld.time`。常速下两者逐位相同，只有慢放 /
   低帧才有区别 —— 慢放从此是纯粹的放大镜。
2. **闸门变一阶状态** `slewGate`：升 0.06s、降 0.22s。瞬时值在转身尾部几帧里会从 1
   掉到 0，状态化之后「半开」只可能连续出现，不可能一帧完成。
3. **限速率与放行程度线性挂钩**：`rate = maxRate · (1 - spin)`，删掉 `FREE_RATE`
   这个逃生口。spin=1 精确冻结，spin=0 就是 `maxRate` 本身。
4. **前 / 后相位各一档上限**（用户提的那条）：侧移族 240°/s、后退族 150°/s，按
   `hipFlipWeight` 平滑混合。后退族那个 −48° 只是「对齐行走轴」的**稳态解**，
   压低上限后快速扫过 θ∈100°..132° 就来不及把它拖出来再拖回去。
5. **速度 < 0.5 m/s 按比例淡出目标**。`latRatio` 是**方向比值**：贴着墙被夹住时
   v 只剩 1e-5，方向能一帧翻 90°（实测把下盘拧到 −22°）。速度趋零时方向没有意义。

| 0.25× 慢放，W→S | 修复前 | 修复后 |
|---|---|---|
| 单帧最大跳变 | 18.6° | 1.4° |
| 整体摆幅 | 25.1° | 4.5° |
| 最深反向 | −19.7° | −1.5° |

### 两个坑

1. **不能用「渲染帧 dt」算任何跟手感有关的时间常数**。下盘的指数平滑、闸门斜坡、
   目标限速全部换成游戏时间步长，慢放才不会把 83ms 的时间常数摊成 330ms。
2. **`speed > EPS` 不够**。`EPS = 1e-6` 只防 NaN，不防「方向噪声」：被挡住时
   v 可以是 1e-5 且方向任意，而 `latRatio` 是比值，照样满幅 ±1。要按**大小**淡出。
