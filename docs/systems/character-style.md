# 角色造型：尺寸、体态、配饰

> **一句话**：`VoxelConfig` 六个数值决定**骨架尺寸**（髋高、臂展、跨步），
> `VoxelConfig.style` 决定**体态与配饰**（驼背、屈膝、发型、胡子）。两者都不进 Core。

改造型前先分清你要动哪一层：

| 想改 | 改哪里 | 会连带影响 |
|---|---|---|
| 高矮胖瘦、四肢粗细 | `bodyTypes.<id>.voxel` 六个数值 | 髋高 / 碰撞半径 / 跨步 / 握持臂展（`height` 必须 = leg+body+head） |
| 驼背、屈膝、发型、胡子 | `bodyTypes.<id>.voxel.style` | 只影响观感，Core 一行不改 |
| 一身专门的配色 | `bodyTypes.<id>.colors` | 覆盖 `view.colors` 的对应项 |

## 1. 体态：驼背与屈膝

两条都写成**基准偏移**，与走路 / 攻击 / 受击的动态层叠加，不是替代：

```jsonc
"style": { "hunch": 0.32, "kneeSink": 0.05 }
```

- **`hunch`（弧度，正 = 前倾）** 加在 `upper.rotation.x` 上，位置在**脊柱拆分之前**，
  于是它被 `splitSpine()` 按腰 58% / 胸 42% 拆成两段弯折 —— 看起来是「弓着」而不是「整根斜」。
  头再做 `hunch × 0.55` 的反向补偿：驼背的人抬眼看人，不是盯着地面。
- **`kneeSink`（米）** 是骨盆整体下沉量。**不要直接写膝角** —— 足部 IK 会把脚钉回地面，
  膝盖自然被「压」出一个前屈角；写死角度会和步态、受击、落地缓冲打架。
  IK 关闭时同样把下沉量补回下盘（`lower.position.y += kneeSink`），脚不穿地。

### 为什么驼背要补一块「脖子」

头前伸 + 抬头补偿后，头底和肩线之间会裂一道缝（方块头没有脖子）。
`hunch > 0` 时在 `headPivot` 下补一个 `0.46H × 0.30H × 0.46H` 的皮肤色方块。
只在驼背体型创建，默认体型盒子数不变。

## 2. 配饰：地中海 + 长白胡子

盒子预算压到 **9 个**（1 顶发帽 + 2 道眉 + 3 节胡子 + 1 个脖子 + 2 块肩甲），
判据是「远看一眼能不能读出来」，不是「细节够不够」：

| 部件 | 盒数 | 抓的特征 |
|---|---|---|
| 发帽 | 1 | **一个盒子穿左 / 右 / 后三个面**：左右各露一圈白边、后面盖住后脑、前面收在头内、顶上半截留空 → 正面是鬓角、背面是后脑、头顶是秃的 |
| 白眉 | 2 | 方块脸性价比最高的一笔：加完立刻「老」 |
| 胡子 | 3 | 上宽下窄的锥形，垂到胸口 |
| 脖子 | 1 | 驼背导致头底与肩线裂缝的补丁（只在 `hunch > 0` 时建） |
| 肩甲 | 2 | 见 §2.2，把「窄肩细臂」的接头补实 |

### 2.1 发帽为什么必须是一个盒子

第一版是 4 片分离的发片（两鬓 ×2 + 后脑 + 顶后半圈）。问题是**片与片之间有缝**，
从斜后方看能同时看到三条接缝，读成「贴了几块白胶布」。

改成一个盒子后，接缝消失，还少 3 个 mesh。两个数值不能省：

```ts
const pad = HS * 0.075;
new THREE.BoxGeometry(HS + pad * 2, HS * 0.66, HS * 0.84 + pad);
position.set(0, HS * 0.47, -HS * 0.08 - pad / 2);
```

- **宽度**要 `+ pad × 2`，否则正面只剩两条 1cm 的线，等于没头发；
- **深度中心要减 `pad / 2`**，让后表面真的溢出头的背面 —— 最初写成 `-HS × 0.07`
  没减这一项，后表面与头背面**几乎共面**，后脑整片被头挡住，背面看是纯肤色
  （与 §2 第一版「胡子埋进胸腔」同源的错误：算的是面的位置，忘了算厚度的一半）。

白发的材质要加自发光：后脑与侧面全是背光面，纯 Lambert 在暗场景里会读成「灰帽子」。
`emissive = hairColor, emissiveIntensity = 0.55`；胡子 0.42。

### 2.2 肩甲：为什么不挂在肩关节上

`style.spaulder: true` 时，每侧加一块 `t × 1.35 × t × 1.35 × bodyW × 0.44` 的方块，
位置 `x = ±(bodyW / 2 + t × 0.4)`，**挂在 `torsoRoot`（胸段）上**。

挂在 `shoulder` 关节上的话，抬臂 / 挥击时肩块会跟着翻起来，反而暴露「它其实是手臂的一部分」。
挂在胸段则始终对齐肩线，抬臂时手臂从肩甲里伸出来，正是护肩该有的样子。

躯干深度跟随宽度：`torsoD = 0.28 × clamp(bodyW / 0.46, 1, 1.4)`。
默认体型的 `bodyWidth` 恰好是 0.46，系数为 1 —— **默认几何与旧版逐字节一致**。
不联动的话，正面加宽、侧面还是一块薄板，反而更显扁。
胡子挂点随之改成 `max(HS × 0.5, torsoD / 2 + 0.025)`，否则躯干加厚会把胡子埋进去。


## 3. 胡子物理：三节二阶弹簧

`src/presentation/beard.ts`，纯函数，零依赖：

```
节 0 目标 = 0（垂直下垂）+ drive
节 i 目标 = 节 i−1 的角度 × follow       // follow = 0.82，末端更软
a = ω²(target − x) − 2ωv + (i==0 ? drive : 0)
```

- **为什么是二阶**：胡子是挂在脸上的绳子，滞后来自**惯性**而不是延迟。一阶 lerp 只会
  「慢半拍」，加速时没有「往后甩、再荡回来」。
- **`drive` 的来源**：本帧速度差分 `(speed − lastSpeed) / dt × 0.3`，clamp 到 ±9。
  加速 → 胡子向后甩；匀速 → 驱动归零，弹簧自己回正。
- **大 dt 保护**：按 ≤1/90 拆步、最多 4 步，否则切后台回来会发散。
- 首帧直接落到静止位（`ready` 标志），不做弹入。

## 4. 加一个新造型（三步）

1. `config/game.json` → `view.bodyTypes` 加一项，`height = legLength + bodyHeight + headSize`；
2. `voxel` 给尺寸、`style` 给体态与配饰、`colors` 给配色；
3. `?hero=<id>` 直接开局验收，或游戏内 `B` 键循环切换。

不需要改 `three-scene`：`buildRig()` 已经按 `bt.voxel` 建骨架。

### 5.1 造型出问题时的第一反应

不要靠猜。`view.heroGroup()` 返回主角骨架根节点，遍历一遍就能知道每块盒子在哪、多大、叫什么名：

```js
const g = __harness.view.heroGroup();
g.traverse(o => o.isMesh && console.log(o.name, o.getWorldPosition(new o.position.constructor())));
```

**「某块东西凭空出现 / 消失」九成是坐标算错半个厚度**，而不是渲染 bug ——
本页 §2.1 的发帽共面、第一版胡子的埋胸，都是同一类。
