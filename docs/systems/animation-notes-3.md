# 动画补充记录 3/3（v9s.36 ~ v9s.37）

> 最后更新：2026-11-08。**补充记录，不是规范**；规范见 [`animation.md`](animation.md)。
> 覆盖：命中必须落在接触帧（刃身扫掠门）、卡肉是节奏不是暂停（接触瓦片 + 偿还）。

## 十五、v9s.36：命中时机必须落在「接触帧」上

### 15.1 现象与误判

「武器还没打到人就卡肉」听起来像表现层问题（平滑 / 滞后），实际是**判定时机**问题：

- 卡肉冻结的是 Core 的攻击时间轴（`phaseTimer` / 前冲 / 连击窗口），还在插值离散键里；
- 表现层「晚半帧再卡」= 逻辑停了画面还在走，解冻后要补跳，比不改更糟。

所以先问一句：**命中那一帧，`swingCurve(attackProgress)` 是多少？**
如果 < 0（蓄势），那就是「刀在身后就判了」——战场在 Core，不在渲染。

### 15.2 判据：命中帧的刃身角 vs 目标方位角

不要用「看起来像」验收，用两个数：

1. **命中时的 `attackProgress`**（或 active 内 `u`）；
2. **刃尖相对角 `ang(u)` 与目标方位角之差**。

剑盾第一段修复前后：`progress 0.217 / ang +160° / 刃尖离目标 2.0m` → `progress 0.362 / ang −2° / 0.33m`。

### 15.3 曲线从哪来：不要手写

用 `clipLab.preview({weapon, comboIndex, progress})` 把进度逐 5% 摆一遍，
读 `bladeWorld()` 的刃尖世界坐标，减去角色位置后反算 `atan2(x, z)`，
再减去 `attackFacing` 得到相对角。这条曲线**就是玩家看到的那把刀**，
而不是「按挥击手感估一个」。

改完剪辑（换关键帧 / 调节奏）必须重采一遍，否则判定会和画面重新错开。

### 15.4 三种段的写法

| 段型 | 写法 | 例 |
|---|---|---|
| 横扫（角度单调扫过） | `pts: [[u, ang], ...]`，命中要求目标角落在 `[ang(0), ang(u)]` | 剑盾 1/2 段、大剑 1/2 段、双剑 1/2/3 段 |
| 突刺（角度几乎不变） | `stabU`：`u >= stabU` 才判 | 剑盾第 3 段 |
| 下劈（角度变化大但慢） | 仍用 `pts`，它的角度区间最终会覆盖正前方 | 大剑第 3 段 |

### 15.5 规矩

1. **只推迟，不否决**：`reach` / `arcDeg` 不动，扫掠门只决定「什么时候开始算」。
   否则会变成「判定范围变了」，那是平衡改动，不是手感修复。
2. **每段独立可回滚**：某一段的曲线不对，删掉它的 `byCombo` 项即可回到旧行为。
3. **代价要写出来**：命中会晚 40~70ms（原本是提前判）。这不是新增延迟，
   是把「判定在刀前面」改成「判定跟着刀」，但对「按键→反馈」的体感是变慢的，
   所以 `tolDeg` 要留可调余量。

## 十六、v9s.37：卡肉是「节奏」，不是「暂停」

### 16.1 一个反直觉的事实

硬冻结（速率 0）看起来最「有力」，但它把**整段动作变长**了：45~130ms 的停顿全部加在这一刀上。
单发看不出来，三连就很明显 —— 越打越黏。战神的解法不是「冻结」，而是：

1. 命中瞬间把双方 **pop 到第一帧接触姿势**（不是随便冻一帧）；
2. **每一击都卡**，所以单次必须短（3~8 帧）；
3. 重量交给别的通道：重低频音效、大幅挥击弧线、夸张受击 —— 镜头震动反而**调小**。

### 16.2 三段式：保持 → 释放 → 偿还

| 段 | 速率 | 作用 |
|---|---|---|
| 保持 | 5% | 黏住。**不要设 0** —— 0 读作「游戏卡了」，5% 读作「砍进骨头里」 |
| 释放 | 5%→100% ease-out | 「脱开」的那一下。线性回 1 会显得软 |
| 偿还 | 150% | 把 hold+release 欠下的时间补回去，**总时长守恒** |

偿还必须封顶：`recovery × (payback-1) × 0.6`。不封顶的话，配置一改长就会在收招阶段
以 1.5× 抽搐式加速。

### 16.3 判据：看总帧数，不看单帧

「有没有变得更拖沓」唯一可靠的判据是**从起手到 idle 的总帧数**：

```
完全不卡 38   硬冻结 41   瓦片+偿还 38
```

同时要断言「保持期没有零速率帧」和「保持期进度仍在推进」—— 前者防止退回硬冻结，
后者防止把 holdRate 写成 0。

### 16.4 击地这类「圆形判定」的时刻怎么定

不要按「看起来像落地」猜。用 `npm run sweep -- --heights` 打印刃尖高度曲线，
取**穿过 y=0 的那一点**（大剑第三击是 u≈0.605，取 0.6）。
判定半径要和尘环半径是同一个数 —— 玩家应该能「看着圈躲」。

### 16.5 采样工具的三个坑

1. 刃尖是世界坐标，**必须减掉根节点实际 yaw**（`yawDebug().shown`）。角色在主循环里
   一直被索敌转过去，不减就会得到一条「随采样时刻漂移」的曲线。
2. 每个采样点要预热 ≥16 帧：腕部滞后 / 副手握持是有惯性的，跳进度后直接读是过渡帧。
3. `hitSweep.pts` 的 u 是 **active 内进度**，不是 `attackProgress`；
   换算 `(windup + u×active)/total`，搞错会整段偏移。

### 16.6 一个会骗人的坑：`clipLab` 会锁住主循环

`clipLab.preview()` 会把 `clipHold = true`，此时**主循环不再调 `view.render`**，画面停在上一次
preview 的最后一帧。于是「新加的贴地特效不显示」很容易被误判成特效代码有 bug —— 其实只是
主循环被锁住了。验证一次性特效（尘环 / 震动 / 刀光）必须先 `clipLab.release()`。

另外两条：

- 贴地环如果和角色脚下的「八向指示环」同半径、同色系，会完全看不出来。
  尘环要**更厚（≥18% 半径宽）、加色混合、颜色和 UI 明确区分**（现在用米白 #e8d8b0）。
- 环的半径就用**判定半径**，不要另配一个"看起来差不多"的数 —— 玩家会拿它当距离参考。
