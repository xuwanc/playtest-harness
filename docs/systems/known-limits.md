# 已知限制与扩展点

> 正文写于 v9s.38（2026-11-08）；用例数于 2026-11-10 由 `npm run docs:facts:fix` 现场采集同步。
> 读法：每条都是**当前真实状态**，不是待办清单；要做的排在 [`../state/CURRENT.md`](../state/CURRENT.md)。

## 已知限制 / 下期扩展点

- **v7 全部 12 项需求已发布**（v7a / v7b / v7c 三批），另修复了一次「移动步频抽动」回归；当前无待发布的 v7 项。
- **v9e 冲刺段仍有拖步**：腿长 0.4m，7.35 m/s 冲刺一个周期要走 1.79m，几何上前伸需要 0.45m > 腿长，必然被可达半径钳制；表现为高速时脚轻微蹬地（约 20% 体速），常速与慢走为严格零滑步。要彻底消除只能提高冲刺步频（会变成碎步）或加长腿。
- **捏合需要「有意手势」**：两指相对移动 <18px 不缩放（换来的是按按钮 / 掌根蹭屏不再搅动镜头与摇杆）；想恢复「一碰就缩放」把 `PINCH_ARM_PX` 调 0。
- **技能实体是「体素风」而不是粒子特效**：v9s.16 给箭矢 / 飞弹补了柔光 Sprite + 锥形拖尾（任意角度都看得见、能读出速度方向），但仍是基础几何体拼装，没有粒子、屏幕后处理与光照衰减；要升级只需替换 `three-scene.ts` 里的 mesh 与 `view.projectiles` 参数，Core 的 `ProjectileState / ShockRingState` 已自带半径与剩余寿命。
- **技能无碰撞遮挡**：飞弹只与假人做圆形相交判定，不检测场景白盒 / 电环之间叠加；要扩展只需在 `abilities.ts` 里增加命中源。
- **浏览器渲染的环境差异**：**纯 headless** Chromium 在这个沙箱里拿不到 WebGL 上下文（`THREE.WebGLRenderer: A WebGL context could not be created`），但 `xvfb-run -a` + **headful** Chromium（`--use-angle=gl --ignore-gpu-blocklist`）实测 WebGL 2.0 可用，v8g 已用它完成 4 个场景截图 + HUD 读数验收（见 `preview-v8g-zoom-*.png`），v9a 用它实测「翻滚 → 窗口 0.27s → 按 J → `link shield-charge active`」与法杖引导不受抢（见 `preview-v9a-*.png`）。自动验收靠 **1286 个用例** + 构建 + 可移植契约，观感仍需真机确认：v8 的侧移 / 后退脚步、v8b 的引导飞弹下盘连续性、v8d 的攻击两条下盘路径（等效步态 vs 挥击跨步）、v8c 的跳跃落地缓冲、v8e 的双指捏合方向与进出时摇杆衔接、v8f 的受击分层观感（上半身倾斜 / 屈膝深浅 / 屁股后坐 / 打肩 vs 打腹），以及 **v8g 的 IK 钉地力度是否过硬、大剑重击跨步是否够味、肘朝向、盆骨惯性与移动下沉幅度**。**v9a 尤其需要真机确认**：三种窗口时长是否够用（长跑 / 闪现更容易接上）、冲锋距离 3.4m 与 `stopDistance 1.25m` 是否合手感、盾击举盾前撞幅度与蓝色光环是否合眼缘、共享 CD 0.85s 是否过长；调试面板「派生招 (v9a)」可逐项热调并一键关掉对照旧连击。可用调试面板「程序化步态」「朝向参数」「程序动画 (v8c/v8d)」「相机缩放 (v8e)」「受击分层 (v8f)」「足部 IK (v8g)」「惯性倾斜 / 盆骨 (v8g)」「派生招 (v9a)」分组热调，或在控制台读 `diagnostics().gait / attackWeights / attackBlend / landing / camera.zoom / hurt / ik / link`。
- **智能相机的威胁源只有假人**：当前按 `dummies` 的位置 / 行为模式 / 挥砍状态评估，未接入场景障碍、投射物或未来的伤害系统；要扩展只需在 `cameraUpdate` 里增加威胁源。
- **构图平滑留在表现层**：Core 只输出确定性目标值，平滑状态不进 `World`（与 `lean` 一致），因此跨语言比对以 `World.camera` 为准，而非屏幕上的瞬时镜头。
- **翻滚方向未分化**：前滚动画固定绕身体局部 X 轴一圈，方向取移动输入 / 面朝向；暂未做侧滚、方向自适应翻滚姿态。
- **闪现只做水平落点保护**：逐段采样只检查 XZ 重叠，`y` 不变，因此不会主动闪上台阶或避开高低差。
- **无伤害与血量系统**：`attack-active` / `hit` / `player-hurt` 事件与三种受击动画已就位，可直接接伤害盒。
- **脊柱分段是「帧尾改写」**：`splitSpine()` 之后 `upper.rotation` 只剩腰段（42% 给了 `chest`）。
  新加的表现层如果在这之后读 `upper.rotation` 当总角用，会静默偏小、不报错。读总角请用 `torsoYaw()` 或自己相加。
- **平衡反馈有相位滞后**：`solveBalance → 骨盆侧移 → 下一帧脚位变化` 是一圈闭环，`counterRate = 8`
  是按「不抖」调的而不是按「跟得上」调的；剧烈位移（击退 + 转身同时）时余量滞后 1~2 帧。
  当前实现只适合「静态度量 + 小幅修正」，要做「失衡 / 踉跄」玩法必须先改成从 Core 速度前馈。
- **卡肉分层没做 `hitflash` / 时间缩放**：这轮只有「时长 × 武器系数 + 方向性微推」；
  受击者闪白要动材质 / 后处理，时间缩放会牵动 Core 全部 `dt` 的确定性，单独一批做。
- **命中是「每段一次」**：`hitWindow` 让判定覆盖整段 active，但同一目标在**一次攻击**里只结算一次（`hitIds`）。
  多段伤害（大剑三段判定 / 连斩）需要显式把窗口拆成多段并配多组 hitIds，暂未实现。
- **关键帧事件只有 Core 时间轴版**：`notifies` 挂在武器 profile 上，剪辑级 `events`（同一条剪辑换武器复用时才会不同）
  没有做 —— 目前三段剪辑与武器一一对应，收益为零；等「一把武器多套动作」时再加。
- **持械姿态只管上半身**：`stance` 覆盖肩 / 肘 / 躯干 / 刀身仰角，腿仍是同一套步态；剑盾的侧身站、双刀的正面站还没有各自的脚位 / 步法变体，跳起时也回到统一的空中收腿姿态。下一步可给 `stance` 增加 `hipYaw` 与脚位偏移，但那会与停步收相 / 转身踏步抢同一批通道，需要先定优先级。
- **空挥反馈只有刀光**：`blade-air` 现在只调用 `trail.pulse()`，没有独立音效 / 风声 / 空气扭曲；`foot-step` 事件已保留但尚未接脚步音或尘土，属于表现层缺口而不是 Core 缺口。
- **玩家是不可推动的锚点**：分离只推假人，因此玩家能「挤开」人群而不是被挡住；这是为保持「假人不修改 character」与「击退作用于敌人」的有意取舍。若需要玩家也被挡，把 `separation` 的玩家权重做成配置即可。
- **墙角极端挤压**：分离后再推出白盒，若假人被夹在墙与玩家之间可能出现极小残留重叠；开阔地与常规走位不重叠。
- **目标辅助只锁前方扇区**：背后敌人不会强制扭头；`maxAngleDeg` 可热调（上限 180°）。
- **复位后 AI 立即继续运行**：复位当帧不推进模块、速度归零，之后从静止重新起步。
- **寻路未实现**：契约、网格元数据、模块开关已就位。
- **场景是手工描述**：`buildBoxes()` 是唯一生成入口。
- 调试面板改 `characterHeight` 只影响碰撞，体素外观尺寸固定（来自 `view.voxel`）。
- `attackMoveScale` 默认 0（攻击锁移动），调到 >0 时攻击期间为匀速无惯性移动。
- 尚未做移动端性能压测与 WebGL 兼容性兜底；本期定位是桌面/手机浏览器里的玩法实验台。
