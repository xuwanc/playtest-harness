## 本轮三条需求（v9s.61，用户第五轮反馈）

- **老头 ghost「拖影动画还是上一次持武器的动作」**：旧 `buildSnapshot` 只给 mesh 叶子节点建配对、resync 只回写 mesh 局部 transform，而角色动画几乎全靠中间 `THREE.Group` pivot 旋转驱动、武器切换靠 `setWeapon` 改 `visible`；`builtFor === target`（顶层引用稳定）又让克隆树永不重建 → 残影姿态永久冻结在首次克隆。现在 `nodes` 覆盖全树，每帧同步 `position / quaternion / scale / visible`，碎裂基准取回写后的当前姿态，并用「节点数 + mesh 数」结构签名在 rig 变化时重建。稳态仍是每槽位只克隆一次（零分配）。
- **机器人 RT「全黑」+「被墙挡住仍透视」**：全黑有两重根因 —— accum 把 `vec4(prev)` 连 rgb 一起乘 `uDecay`、compose 又 `c.rgb - cur.rgb` 削掉当前帧颜色（双重衰减）；以及 RT 存线性色、自定义 shader 不走 Three 的 `colorspace_fragment`，直接输出到 sRGB 画布明显发黑。现在 accum **只衰减 alpha**、rgb 恒保留角色本色，compose 用本色 + 历史覆盖度并补一次 `linearToSRGB`。透视根因是全屏 compose 无视深度：新增 `EffectContext.occluders`（`boxGroup` 的非地面盒），三条「相机→角色」射线门控，完全被挡则清空累积并整套停跑（不透视还省 3 个 pass），部分遮挡按可见比例变淡。`debug().occlusion` 暴露读数。模糊保持移除、`resolutionScale` / `updateStride` 保持低开销。
- **装备界面「横屏看得到 / 竖屏看不到 / 相机下移」**：竖屏 CSS 里 `.wardrobe-stage{flex:1 1 52%;min-height:0}` 被 12 格 `aspect-ratio:1/1` 魔方挤成 0 高（实测 canvas `478×1`）；现在舞台 `height: clamp(140px,26vh,240px)` 保底、侧栏可滚动、魔方改 6 列小方格。用户明确纠正「相机下移」是**主场景相机**：`camera-rig.setLift()` 沿屏幕下方平移相机（`lookAt` 后只改位置、视线不变）让场景角色上移，链路 `wardrobe.onOpenChange → app.ts → view.setWardrobeLift → cam.setLift`；转台 `wardrobeFraming()` 回到 1.5× 身高、居中、正常大小，不再拉远缩小。
- 单测：新增 `v9s61-camera-lift`（3 例）；`v9s56` 加 pivot 动画 / 武器 visible / 结构重建 3 例；`v9s57` 加 shader 非黑契约 + 遮挡 4 例；`v9s60-wardrobe-framing` 改为「正常大小 / 居中」断言。全量 134 文件 / 1356 例全绿（数字由 `check-facts --fix` 同步）。

主干已含：可复用残影特效库 `src/presentation/effects/`（ghost / rt / shared / index）、Wardrobe 底部抽屉 + 3D 装备 + 合成台、动画层通道所有权守卫、鱼人 / 蜘蛛 / 哨兵机体型、可破坏物与草块、文档事实守卫 / 推送护栏。

## 下一步

1. **残肢只是表演**：断块不进 `world.boxes`，会穿地穿人；要「踩到断头会滑」得给残块加低矮碰撞。
2. **腰斩高度写死**：`waist` 一律在 `u` 处断开，不看骨架的盆骨位置；驼背体型会偏。
3. **蜘蛛骨架没有断肢**：`SEVER_NODE` 只覆盖人形两条骨架，蜘蛛打死了仍是整只倒下。
4. **仙人掌侧臂没有碰撞**：AABB 只按主干 `radius` 建，贴着侧臂走过去能穿。
5. **AABB 是方盒**：仙人掌是圆柱，斜着看盒子会「方一角」；要贴合得换圆柱 / 胶囊碰撞。
6. **血迹不分材质**：台阶侧面也会贴一块平的（`groundY` 取脚下支撑面）。
7. **尸体是「滑开」不是「顶住」**：圆形碰撞会沿切线滑过去；要推不动的阻力感，得再加一档 `crowdResistance`。
8. **转身期间站姿权重为 0**：转完再升回来，中间 0.15s「并腿」过渡。
9. **脚掌分段只有人形鞋**：蹼足 / 机械脚整只挂踝（`toeLen = 0`），鱼人走路仍是整块拍地。
   蹬离相位脚最低点 −0.065m（不折角的同相位基线 −0.037m）—— 抬踝是「几何补偿」，不是滚动 IK。
   试过闭环（量实测最低点再补差值）：蹬离时小腿接近水平，局部 `+y` 几乎不指向天空，
   会越补越偏（实测踝抬 13.6cm 才顶起 3cm），已回退。正解是按世界竖直方向平移或做滚动 IK。
10. **移动端 `resize` 没去抖**：地址栏动画会连发 `setSize`，每次都重建 render target。
11. **`antialias` 不能热改**：降档只降 dpr / 阴影，要关 MSAA 得重建 renderer（未做）。
12. **`config/game.json` 拆分**：`core.gait` / `core.combat` / `view.*` 仍未拆。
13. **鱼人走的是人类步态**：没有「拖步 + 左右摆」，和方块人一致。
14. **鱼人杂兵没有手**：`dummy-rig` 的手臂末端本来就没有手掌，蹼掌只做在主角上。
15. **鱼人主角没有断肢**：断肢是假人系统的能力，主角只有受击 / 击退。
16. **尾巴是静止的**：挂在 `pelvis` 上跟着屁股走，没有独立摆动。
17. **体态是静态的**：不随速度 / 动作变化，跑起来还是同一个前倾角（想要「跑起来更趴」得给它加一档速度权重）。
18. **头前伸不改碰撞盒**：鱼人贴墙时吻部会插进墙里约 15cm。
19. **盾没有世界角语义**：压平体态后剑被补偿回目标仰角，盾却跟着小臂一起倒（只有剑有 `applyBladeTarget`）。
20. **哨兵机只能当主角**：没有 `DummyVariant.sentinel`，还不能配置成杂兵。
21. **鱼人杂兵的颜色曾经分两套**：v9s.68 之前四肢仍走「每个假人专属色」，一颗绿头接在蓝色身体上（已修，`cc`）。
22. **头仍然挡住大半躯干**：v9s.70 抬头 7.7° 之后露出肩线与背鳍，但 38° 俯视下仍只读作「一个大头」——
    这是「头比身体还横（0.46 对 0.34 高的躯干）」的几何必然；再往上只能缩头，代价是认不出鱼人。
23. **`armDrop` 只管上臂**：举盾时手臂会重新前倾，回正只在待机 / 步态下明显。
24. **补块的重叠是常数**：髋块与腰块的盖缝量写死（`hipShare` / `0.06`），不随实际折角变化；

25. **`chainBlend` 不区分来源**：下盘带转、攻击旋身、站姿斜跨三笔偏航走同一条分配；

27. **髋块只给鱼人**：`hipMesh` 按 `style.murloc` 创建。直立体型压 10~20° 缺口在 2cm 以内，
    加了反而显胖；将来做驼背老人再开。
28. **段数改了要复查腰段**：`chainBlend` 是「曲线中点停在哪」，用 `x^p` 反解；3 → 4 段时

29. **躯干几何按段切块**：3 段 = 3 个 mesh（多一个 draw call / 角色）。暂时无感，
    但真做几十个角色时要考虑合批。

## 已知风险

见 [`../risk-review.md`](../risk-review.md)。本轮变化：

- **v9s.76：抬踝必须排在 IK 之后**。IK 的锚点是踝原点（`tip`），在它之前抬踝，IK 会把
  整条腿反解回去，补偿等于没写。`4.05 heel-toe lift` 因此是**唯一**在 IK 之后写
  `ankle.position` 的层；同层里要用「基准值 + 增量」，不能 `+=`（stretch 关闭时没人重置）。
- **v9s.76：折角权重必须两头取**。只看速度 → 攻击跨步时 `gaitSpeed = 0`，脚完全不折；
  只看攻击 → 站定时 `gaitPhase` 是冻的，某个相位的折角会永久留在待机姿态（脚一直翘着）。
  正确写法 `max(attackBlend, speed / 1.5)`。
- **v9s.76：黑靴子的折角截图看不出来**。8° 在 0.18m 的脚上前掌只抬 1.2cm，暗背景上分不出
  「入地 1cm 还是 3cm」。验收判据得是 `gaitDebug().footMinYL/R`（`Box3` 量世界最低点），
  截图只兜「有没有撕裂」。同理拍脚前要先把盾 / 剑 `visible = false`，0.9m 机位会怼进盾里。
- **v9s.76：钉住步态相位不能用「按键走 + 每帧改 `gaitPhase`」**。rAF 与 `render` 先后不保证、
  Core 每帧还在推相位 —— 钉 0.045π 实拿到 0.43π。正解 `debug.paused = true`：只停 `step`，
  `render` 照常每帧调 `rig.update`，相位与速度都由测试钉死。

- **「看着画面报的问题」几乎都是语义错，不是数值错**：脚掌在腿中间（`ankleY` 被乘了 headSize）、
  尾巴少一节（两段差 1.1cm）、头疯狂转（yaw 绕脖子）—— 这三条在数值上都「没报错」，
  只有把画面拍下来才看得出来。
- **IK 的契约是「钉在基准脚位」，不是「钉在地面」**：FK 给的脚位本身穿地时，IK 会忠实固化它。
  修法只能是给锚点加下限，不能改解算 —— 改解算会破坏「权重 0 时等价于 FK」这条恒等性。
- **v9s.70：「补偿看不见」有一半是几何，不是角度**：偏航分账调对之后躯干仍然断成两截 ——
  两块方块绕各自底边转，背面会掀开楔形缝，而骨盆是空节点。角度对了不等于读起来连续。
- **v9s.70：中间关节的角度必须锚在**上游**上**：`腰 = 总角 × 0.58` 在下盘一转就变成「先减后增」。
  任何「把总角摊到链上」的分配，起点都必须是上游关节的实际角，不是 0。
- **v9s.72：链的起点是 0，不是髋**：`upper` 的父节点是 `pelvis`（yaw 恒 0），髋（`lower`）是它的**兄弟**。
  把累计角的起点写成 hip，整条链会平白少掉一个 hip —— 症状是 leak 0.017、头跟着转 0.009、
  偏航符号偶发翻转。三条都指向同一个常量差。
- **v9s.72：补块是兜底，不是解法**：真正让缝变小的是「每级折角 = 总角 / 段数」；
  加补块只是把还剩的那点缝盖住。先想「能不能多分一级」，再想「要不要补一块」。
- **v9s.70：多 agent 同时开工时，闸门的第一步 `git fetch` 不能跳**：这台机器 `github.com:443`
  间歇挂死，跳过 fetch 直接领号会和别人的号撞（本轮撞在 0.9.97 / v9s.69，重领到 0.9.97 / v9s.70）。
- **旋转中心和俯仰是两件事**：把 pivot 抬到颅中心解决了甩头，但同一批角度会让脸扎地。
  yaw 与 pitch 必须分层，不能共享一个 pivot。
- **「体态」是独立一层，不是改动作**：它必须插在 `splitSpine` 之前（否则不被摊成腰 / 胸两段，
  读作「整根斜」）、足 IK 之前（否则抬沉骨盆时脚跟着飞）。位置错了不会有报错，只会「看起来哪里不对」。
- **抬胯不能抬骨盆**：两骨 IK 可达上限 = `legLength`，默认站姿已用满；`pelvisLift: 0.05` 实测脚离地 2.6cm。
  「屁股高」只能靠躯干压平，让臀线成为最高点。
- **前倾需要总预算**：挥砍自带 ~30° 前压，叠在 65° 体态上 = 扑倒。体态只吃 `maxTotal − 已用`，
  攻击期间再打五折；头抬头量必须用**实际吃进去**的角度反算，否则预算夹掉多少、脸就朝天多少。
- **俯视下先坏的是可读性不是穿地**：三头身髋高 0.385m，头压到 103° 最低点还有 0.36m；
  但头一低就挡住整个躯干，最高点从「头」变成「背」，读作一坨。停在 55° 是这个原因。


- **「换造型」优先换几何，不要加骨架**：鱼人双足、髋膝踝肩肘腕、攻击前压都与人类同构，
  只换了头 / 背鳍 / 手 / 脚 / 尾五处几何，骨架名与骨骼层级一字未动 ——
  于是断肢（按节点名查找）、IK、步态、倒杆物理全部**白拿**。加新骨架只在
  「运动方式真的不同」时才值得（蜘蛛）。
- **单只假人的血量和「测试桩」是两件事**：`dummies.health` 是全局默认（0 = 打不死），
  `DummySpawn.health` 是单只覆盖。把全局改成 90 会让一堆测距离 / 测 AI 的工位失效；
  反过来只给鱼人配血量，鱼人才能被打死、才看得到断头。
- **smoke 的速度判据被过渡帧稀释**：`sp > 0.15` 把起步 / 收步也算成「移动」，
  均速从 1.5~1.9 掉到 0.8，看起来像「碎步」。阈值必须取「大步」的下限（0.6），
  且采样窗口 ≥ 一个横移周期（5.2s），否则窗口会随机落在停顿段、`moveRatio` 直接归零。
- **同一个造型写两份，必然漂移**：侧臂曾经「站立一套尺寸 / 断块一套尺寸」，
  断块那套还正好是 2 倍；`CACTUS_VIS_RATIO` 也是两边各乘一次（根部差 0.06m）。
  造型参数只允许有一份真源（`cactusArmBoxes`），表现层只负责画。
- **「谁跟着断块走」要用区间判据**：`atU > cutU` 看着合理，但第二次砍更低位置时，
  上一次已经飞走的臂仍然满足它 —— 必须写成 `cutU < atU ≤ prevStandU`。
- **站立几何的高度不能写死**：旗杆 mesh 一直用 `st.height`，`standU` 只影响碰撞和断块 ——
  于是「砍完还有一整根柱子」。凡是跟 `standU` 走的几何，顶面都要用 `cutBoxHeights(...)`。
- **移动端卡顿先看 `lost`**：桌面探针（对象数 / 几何数 / longtask 全平）排除了 JS 侧原因，
  剩下的「几秒」只能是 WebGL 上下文丢失 + 恢复重传。`?diag=1` 的 `lost` 在涨就是它。

上一轮（可破坏物去壳）仍有效：

- **测试站位不要压在物件上，也别站到它背面**：smoke 原来传送到「地块中心 −2.0」，
  正好和 `pole-b` 重合 —— v9s.68 靠「人和杆重叠」侥幸砍中；物件有了碰撞盒后一落位就被推开。
  v9s.75 又发现「站到正北 1.0m」也有坑：`facing = 0` 对应 **+Z**，站在 +Z 侧等于背对杆，
  前冲还会再推远 0.445m。正解是站 −Z 侧 1.35~1.45m + `timeScale` 0.35（给 active 段
  多几帧采样窗口，否则 10~15fps 下只剩 1~2 次机会）。
- **`dest-*` 碰撞盒不能进白盒渲染**：盒子宽度 = 物件直径，画出来就是一个红棕色方块
  把造型整个包住，现场读作「可破坏物是个方块」。
- **视觉半径 ≠ 碰撞半径**：仙人掌画 `0.82R`、撞 `1.0R`，每侧差 0.06m。
  改就得两边一起改（判定轴仍用 `R`）。

- **断肢判定不能有随机**：`decideSever` 进 determinism golden；写 `Math.random()`
  会让同一次击杀在不同次运行断不同处，快照直接炸。判据必须是纯函数。
- **`world.boxes` 是共享引用**：移动 / 相机 / 贴地特效都拿着同一个数组读。
  `destructiblesUpdate` 只能**原地改** `box.maxY`，`filter` 重建数组会让它们读到上一帧的旧对象。
- **残块要先 `updateMatrixWorld`**：`matrix.copy(node.matrixWorld)` 拿的是上一帧的矩阵，
  没更新就 `decompose`，残块会从原点飞出去（实测：飞出画面外）。
- **闸门晚一帧是刻意的**：`meleeGatePrev` 只放行一个 tick（表现层 `render` 采样、
  `step` 下一帧消费）。要动 `hitSweep` / 帧序，必须同时看这条。
- **地块 `span` 会挤占槽位**：`x-destructibles` 从 `[2,2]` 改 `[3,3]` 会把别的工位推到
  假人测试位置，smoke 的踱步 / 命中三项直接挂（本轮踩过一次）。

上一轮（死亡体感）仍有效：

- **木桩喷血是个陷阱**：`maxHp = 0` 的单位必须跳过 `pushHitMark`（否则砍测试桩也出血）。
  但**不能**因此提前 `return` —— 那会把卡肉也一起跳过。判断要包在 `if` 里，不是守卫语句。
- **死亡要跳过的系统有七处**：命中结算 / 近战·击地·派生扫描 / AI / 索敌 / 注视 / 分离 / 脚下环。
